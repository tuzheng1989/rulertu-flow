**路由 + references 的理由**：一次会话只运行一个模式，单文件意味着每次触发装载 ~500 行全量指令；模式手册放 references/ 按需加载，SKILL.md 只保留判别与共享规则。

### 1.2 SKILL.md 路由层

**开场硬规则**：每次触发先公开宣告"本轮判定为 X 模式，判据是……；如需切换，说'切换深钻/扩散/创意'"，再读对应模式手册开始。

**显式指定（frontmatter 参数通道）**：

```yaml
argument-hint: "[模式：深钻|扩散|创意] 主题"
arguments: mode
```

**模式判别三层，顺序固定**：

1. **`$mode` 显式参数**：正文以 `$mode` 与 `$ARGUMENTS` 并用——`$mode` 是首词（空白切分；中文无空格整串时为全串），`$ARGUMENTS` 是完整参数串（不引用则自由文本会丢失）。路由对 `$mode` 做**前缀匹配**（防自由文本中段误中模式词）："深钻/下钻/deepdive"前缀 → 深钻；"扩散/发散/diverge/头脑风暴"前缀 → 扩散；"创意/灵感/creative"前缀 → 创意。命中即进入该模式，宣告标注"用户指定"。守卫两种无参形态：`$mode` 为**空串**或保留**字面 `$mode`** 时视为未指定，落到第 2 层。
2. **自由文本点名**：`$ARGUMENTS` 或会话首条消息中出现"深钻模式""创意模式"等点名短语时进入对应模式（会话中途说"切换创意模式"也走这层）。
3. **自动判别**：按上方判据表。

> 替换行为依据 Claude Code v2.1.316 实现核实（官方 plugin-dev 文档未覆盖无参数时的取值；`argument-hint`/`arguments` 均为 SKILL.md 合法字段，Skill 工具调用走同一替换管线）。

| 信号特征 | 模式 |
|---|---|
| 多方向、问"还有没有别的可能"、无单一焦点 | 扩散（diverge） |
| 单一对象 + "再深入/本质是什么/往下钻" | 深钻（deepdive） |
| **有参考物**（作品/风格/领域/案例）+ 要设计某物，或要"意想不到/创意/灵感" | 创意（creative） |
| 判据冲突（如"帮我想几个有创意的名字"且无参考物） | 有参考→创意；无参考→扩散，宣告时提示可切 |

**会话中切换**：用户说"这个分支深挖一下"→ 重新判别、宣告、加载新手册。跨模式携带上下文：发散的可能性地图分支可直接作为深钻输入；深钻/创意的产出可回填地图。

**共享规则**（从两份现有文档上移）：检索规则（搜索类 MCP，禁内置 WebSearch/WebFetch）、移交 `/grilling` 闸门、兼听机制总说明（预算真源 `.listen/state.json`，规格见 [2026-10-29-dual-model-listening.md](2026-10-29-dual-model-listening.md)）。

**新 description**：吸收 pacemaker 触发词（深挖/本质/下钻/深度打磨）并新增创意触发词（创意/灵感/参考……设计/意想不到）。

## 2. 创意灵感模式规格（含 codex 评审修订）

### 2.1 定位

**远距关联引擎**：把参考物的**深层机制**翻译到用户需求上，产出**意料之外、情理之中**的设计。

三模式几何隐喻：扩散是平面上铺点（广度），深钻是一个点上钻（深度），创意是**两个远点之间架桥**（距离）。价值度量：发散数分支，深钻数论证，创意数**意外程度 × 契合度**。

创意模式是三模式中**唯一自带筛选的**：发散只发散不收敛，深钻只论证不发散，创意必须"远距发散 + 双轴筛选"两手都有——用户要的是能用的设计，不是可能性清单。

### 2.2 工作流五步

**1. 盘点**
- 需求 N：用户要设计什么（名字/方案/活动/产品形态）、交付形式
- 参考 R：用户给的参考物（任何领域：作品、品牌、游戏机制、自然现象）
- 约束：不可更改的边界
- 无参考时：请用户提供 1-3 个；用户说"你来挑"则技能自选，自选必须跨领域并声明"为何选它做参考"（自选参考本身是创意行为，也过反平庸检查）

**2. 解构参考（本模式的命门）**
对每个参考做机制层分解，区分两层：
- 表层特征：视觉、词汇、风格词（国潮的水墨、盲盒的盒子）
- 生效机制：它为什么有效（盲盒 → 不确定性奖励 + 收集完整性执念；交响乐四乐章 → 张力-释放的周期结构）

每个参考提炼 2-4 条机制，每条写清"为什么有效"，并**必附生效条件清单**——它依赖什么前提才有效（盲盒的不确定性奖励依赖"低风险单次决策"这一前提）。【修订 #2】

**3. 远距关联（四透镜）**

| 透镜 | 核心动作 | 例 |
|---|---|---|
| 机制移植 | 参考的机制原样搬到新语境 | 盲盒机制 → 功能发布的节奏设计 |
| 结构映射 | 找参考物与需求问题的结构同构 | 四乐章张力结构 → 技术分享的叙事结构 |
| 混血 | 两个参考的机制杂交 | 即兴戏剧"是的，而且" × 代码评审流程 |
| 变维 | 把机制的一个参数推到极端 | 年度仪式 → 每日微仪式（时间维度压缩） |

每条关联必须写出**关联路径**：需求的哪个结构点 ← 参考的哪条机制。移植时**逐条核对生效条件**：目标语境满足则通过；不满足时给补偿设计或该关联出局。【修订 #2】

**4. 双轴筛选**
- **意外轴**：意外点必须**锚定到指名的领域惯例**——写出"该领域常规做法是 X，本设计偏离在 Y"。惯例是否属实可核对，不靠自评"这个很意外"。【修订 #1】
- **契合轴（同构检验）**：参考机制与需求问题的结构是否真的同构，生效条件逐条满足（见第 3 步），机制搬过去后原有效应仍成立。
- 两轴都过才入选；只意外不同构 → 胡闹，弃；只同构不意外 → 平庸，回第 3 步再拧。

**5. 产出**
3-5 个设计，**按意外程度从近到远排序，并明示该排序不代表可行性、成本或收益预测**——可行性评估归深钻模式或 `/grilling`。【修订 #3】

每个设计五要素：

```markdown
## 💡 [设计名]
- **关联路径**：需求[结构点] ← 参考[机制]（创意的证据）
- **设计描述**：落在用户语境里的具体形态
- **意外点**：打破的领域惯例（指名"常规做法是 X，本设计偏离在 Y"）
- **合理点**：生效条件逐条核对的结果
- **试金石**：一个低成本验证设计是否真有效的方式（必填，规则见下）
```

**试金石规则**【修订 #6】：必填，删除"凭直觉判断"豁免。确实写不出低成本验证的，该设计**单独归类为"未验证创意"**，并给用户一个可自查的具体问题（如"拿给一个目标用户看，TA 第一反应说的是不是你想要的那个点"），不给空出口。

### 2.3 反平庸宪法（硬约束）

1. **禁止第一层联想**：表层特征直接贴皮（"参考是赛博朋克所以加霓虹"）一律不出现在产出里
2. **意外锚定惯例**：意外点必须指名领域惯例，可核对（见双轴筛选）
3. **关联必有路径**：说不出"哪个机制 ← 需求哪个结构"的关联是随机，不是创意
4. **意外与合理缺一不可**

### 2.4 检索策略【修订 #4，取代原"不自动检索"】

不做"检索生成关联素材"（创意的新颖性要求跳出搜得到的关联），但**检索用于两处**：
- **机制核实**（第 2 步）：解构参考时核实机制的生效条件是否如所记，防模型记忆里的 folk theory
- **产出后查新**（第 4 步之后）：对入选设计查是否已是业界常见做法——查得到现成实现则"意外"不成立，出局或降级

### 2.5 退出规则【修订 #5】

四透镜遍历一轮仍无合格关联 → **如实报告"本参考组合产出不足"**，建议换参考或切换模式。允许交付少于 3 个甚至 0 个并说明原因，**禁止降门槛凑数**。

用户说"还有吗"：先用同批参考再拧一轮（换透镜）；拧不出新东西时如实说明并建议换参考。

### 2.6 对话节奏

任务型，**不建日志**（与深钻一致，区别于发散）。支持迭代指令："再野一点"（放宽契合优先级、加大关联距离）、"再稳一点"（反向）、"换个参考"（回到第 2 步）、"深挖这个设计"（切换深钻模式）。

### 2.7 刻意不做的

- **不给 creative 模式加兼听**：dual-listen.py 目前只有 diverge/attack/blindspot 三种 mode，加 creative 是脚本 + 预算管理的新增面。先观察使用频率，真有需求再立项。
