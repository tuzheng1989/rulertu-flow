### A3 SKILL.md 路由层（≤100 行）

frontmatter（description 文案**逐字使用**）：

```yaml
---
name: brainstorm
description: 思维探索引擎，三模式按用户上下文自动判别，也可用参数显式指定：深钻——对单一想法、方向或问题做领域专家级深挖（原始材料、对抗性检验、经论证的深度洞察），当用户说"深挖一下""再深入""本质是什么""往下钻""这个方向还能怎么深入""找不到本质差异""深度打磨标题/功能/研究方向"时触发；扩散——纯发散式头脑风暴，透镜轮换（SCAMPER、类比跨界、逆向假设、随机刺激、绿帽思考）最大化可能性空间，产出以"可能性地图"形式持续生长，只发散不收敛，适用于技术产品、商业策略、职业发展、创意项目等全领域话题的想法发散；创意——远距关联引擎，把参考物的深层机制翻译到用户需求上，产出意料之外、情理之中的设计，适用于用户给出参考物（作品/风格/领域/案例）并要求设计某物、或要"意想不到""创意""灵感"的场景。多方向铺开用扩散，单点钻透用深钻，收敛决策用 /grilling。
argument-hint: "[模式：深钻|扩散|创意] 主题"
arguments: mode
---
```

正文骨架（标题自定，内容依方案 §1.2）：

1. **身份**：思维探索引擎，同一技能三种模式，一次会话只运行一个模式
2. **开场硬规则**：每次触发先公开宣告"本轮判定为 X 模式，判据是……；如需切换，说'切换深钻/扩散/创意'"→ 读对应 `references/mode-*.md` 手册 → 开始执行
3. **模式判别三层（顺序固定）**：
   - 第 1 层 **$mode 显式参数**：正文固定包含两行——`用户指定模式参数：$mode`、`完整调用参数：$ARGUMENTS`。对 $mode 做**前缀匹配**别名表：深钻/下钻/deepdive→深钻；扩散/发散/diverge/头脑风暴→扩散；创意/灵感/creative→创意。命中即进入该模式，宣告标注"用户指定"。**守卫**：$mode 为空串或保留字面"$mode"时视为未指定，落到第 2 层
   - 第 2 层 **自由文本点名**：$ARGUMENTS 或会话消息中出现"深钻模式""切换创意"等点名短语时进入对应模式（覆盖会话中途切换）
   - 第 3 层 **自动判别表**（含判据冲突规则：有参考物→创意；无参考物→扩散，宣告时提示可切）
4. **会话中切换**：重新判别 + 宣告 + 换手册；上下文携带（可能性地图分支可直接作为深钻输入；深钻/创意产出可回填地图）
5. **共享规则**：检索（搜索类 MCP 工具如 web-search-prime，禁内置 WebSearch/WebFetch；不为验证可行性而检索）；收敛决策一律移交 `/grilling`（建议，不自动调用）；兼听机制各模式手册内自带，预算真源 `<workdir>/.listen/state.json`，规格见 `plans/work-skills/2026-10-29-dual-model-listening.md` §2.8
6. **边界**：不制定实施计划、不生成实现代码、不做架构决策或技术选型；各模式细分边界见各自手册
