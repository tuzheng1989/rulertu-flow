## 消息 1

**用户消息**："帮我分析这个销售数据表 data.xlsx，按区域做个汇总统计"

**决策**：命中 → excel mode（`modes/excel.md`），走常规六步编排（分组统计步骤）。

**文档依据原文**：
- 路由表第 1 行："| `.xlsx` / `.xls` / `.csv` | `modes/excel.md` | 常规编排六步；总行数 ≥10k 时由 excel.md Step 2 大文件门转入引擎档 |"
- 触发词①："Excel 分析 / 表格分析 / 数据分析 / …… / 汇总统计 / 透视表 / 分组统计 / ……"
- 触发词⑤："用户上传或指定了 .xlsx / …… 文件并要求分析、提取、统计或可视化"
- capability 索引表："| excel-data-analysis | 6 | 对比、分组、KPI、透视表、时间序列、趋势分析 |"、"| excel-data-statistics | 4 | 基础/分类/分组统计、占比计算 |"

**理由**：用户指定 .xlsx 文件且要求"汇总统计"，同时命中路由表第 1 行（扩展名路由）与触发词①（汇总统计/分组统计），按路由规则 1"用户给了文件→按扩展名查表路由"进 excel mode；未提及行数规模，默认走常规六步，excel.md 内部行数门自会兜底。

## 消息 2

**用户消息**："这份发票.pdf 里面有很多发票，帮我把每张的金额提取出来做成表格"

**决策**：命中 → document mode（`modes/document.md`），加载 `doc-capability/pdf-analysis/SKILL.md` 解析提取。

**文档依据原文**：
- 路由表第 2 行："| `.docx` / `.doc` / `.pdf` / `.pptx` / `.ppt` | `modes/document.md` | 按格式加载 doc-capability 子技能解析 |"
- 触发词②："Word分析 / PDF解析 / …… / 发票提取 / 合同分析 / ……"
- 触发词⑤："用户上传或指定了 …… .pdf / …… 文件并要求分析、提取、统计或可视化"
- description："document（Word/PDF/PPT 解析与数据提取，含 3 个 doc-capability 子技能）"
- doc-capability 索引表："| `doc-capability/pdf-analysis/SKILL.md` | .pdf（文字型/扫描型判别、表格、嵌入图表） |"

**理由**：.pdf 文件 + "发票提取"触发词 + 提取金额成表格的诉求，三重命中 document mode；文档对"发票提取"和 pdf 表格提取均有显式覆盖，属"提取"而非"格式转换"，不触互斥边界。

## 消息 3

**用户消息**："我这张截图里面有个表格，帮我把数据提取出来转成 Excel"

**决策**：命中 → image mode（`modes/image.md`），会话视觉直读提取后 Excel 导出。

**文档依据原文**：
- 路由表第 3 行："| `.png` / `.jpg` / `.jpeg` / `.gif` / `.webp` / `.bmp` + 数据提取 | `modes/image.md` | 会话视觉直读（Read 工具），无外部 API |"
- 触发词③："图片分析 / 图表提取 / 表格识别 / OCR / …… / 截图分析 / …… / 提取图片中的数据 / 图片转表格 / ……"
- Modes 节："**`modes/image.md`** — 图片理解与数据提取：Read 工具视觉直读 → 结构化解析 → 可视化/Excel 导出。"

**理由**："截图 + 表格 + 提取数据转 Excel"逐字命中触发词③（截图分析/表格识别/图片转表格）与路由表第 3 行的"图片 + 数据提取"组合；image mode 说明明确覆盖"Excel 导出"终点，这是图片数据提取而非图片编辑，不触互斥边界。

## 消息 4

**用户消息**："这是个 200 万行的日志 Excel，直接读会崩，怎么处理"

**决策**：命中 → excel mode 的大文件门 → `references/large-file-engine.md` 引擎档（非独立入口）。

**文档依据原文**：
- 路由表第 4 行："| 大文件 / Parquet / 流式读取 / ≥10k 行 | excel mode → `references/large-file-engine.md` | 由 excel.md 的行数门按量级指路 |"
- 触发词④："大文件 / 大数据量 / 性能优化 / 内存不足 / OOM / 百万行 / 十万行 / 流式读取 / ……"
- 路由规则 2："用户没给文件只有触发词 → 按触发词组匹配 mode（……大文件组→excel 的引擎档）"
- Modes 节："**`references/large-file-engine.md`** — ≥10k 行引擎档：流式读取、Parquet 转换、内存优化、大文件写入。不是独立入口，由 excel.md 的大文件门进入。"

**理由**："200 万行"落在"百万行"触发词与"≥10k 行"行数门内，"直接读会崩"对应"内存不足/OOM"触发词；按路由规则 2（触发词组匹配）与路由表第 4 行进 excel mode 并由大文件门转入引擎档，引擎档定位为"不是独立入口"故决策表述为 excel mode 的引擎档而非平级 mode。

## 消息 5（边界：应拒绝）

**用户消息**："帮我把这张照片裁剪成正方形再加个滤镜"

**决策**：拒绝受理，说明不归本技能。

**文档互斥边界原文**：
- 路由规则 3："互斥边界：图片编辑/生成请求**拒绝**并说明不归本技能"
- description："仅不用于：图片编辑（裁剪、滤镜、缩放）与图片生成；……"

**理由**："裁剪""滤镜"逐字落在 description 互斥段列举的"图片编辑（裁剪、滤镜、缩放）"内，且本消息不含任何分析/提取/统计诉求，属于纯图片编辑请求。

**拒绝话术**："裁剪和加滤镜属于图片编辑，不在 data-analysis 技能的职责范围内——本技能只处理图片的理解与数据提取（表格识别、图表数据提取等），不做像素级编辑。图片编辑请使用通用图片处理能力（如图像编辑类工具）完成。"

## 消息 6（边界：应指向 anydoc-to-md）

**用户消息**："把这个 PDF 报告转成 Markdown 文件"

**决策**：分流 → 指向 **anydoc-to-md** 技能，本技能不受理。

**文档互斥边界原文**：
- 路由规则 3：""把这个 PDF 转成 Markdown"类格式转换请求指给 **anydoc-to-md**"
- description："文档格式转换（那归 anydoc-to-md——本技能管分析不管转换）"

**理由**：请求形态与路由规则 3 的示例句式"把这个 PDF 转成 Markdown"完全同构，属格式转换而非"解析与数据提取"；description 用"本技能管分析不管转换"一语划清职责线，文档表述充分无歧义。

**分流话术**："PDF 转 Markdown 属于文档格式转换，归 anydoc-to-md 技能处理（本技能管分析不管转换）。请改用 work-skills:anydoc-to-md——它对文字型 PDF 走 anydoc 引擎、扫描版 PDF 自动路由 OCR，输出干净的 Markdown。若你的目标是从 PDF 里提取数据做分析（而非转格式），再回到本技能。"
