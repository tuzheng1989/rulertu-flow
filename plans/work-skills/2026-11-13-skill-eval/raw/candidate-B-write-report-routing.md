---

已完整读取 SKILL.md（含 description 触发分流、mode 路由表、引擎模式判断流程、Subagent 架构、资产索引）。以下为 5 个 case 的路由决策与行动计划。

## 【WR-E01】"帮我把这份草稿润色一下，压缩到 1000 字以内。"

**路由决策：走 compose mode（报告成稿与改写）。不进引擎模式。**

**依据：**
- SKILL.md description「报告 mode 触发分流」第一条：「写 / 改 / 润色 / 压缩 / 扩写 报告」→ compose mode（成稿与改写）——「润色」「压缩」均为触发语逐词命中
- 「mode 路由」节表格 compose 行：典型触发语「写 / 改 / 润色 / 压缩 / 扩写 报告」
- 「mode 路由」节分流规则（第 51 行）：已有现成文稿（"这份草稿"）的改写属"面向读者交付的报告，尤其已有研究材料或文稿"场景 → compose
- 排除引擎：目标 1000 字以内，非长文档，不适用第 53 行"长文档请求不进 mode"的引擎分流

**下一步动作序列：**
1. 读取 `modes/compose.md`，严格按该文档执行（第 49 行规则："命中后读取 modes/<mode>.md"）
2. 获取草稿：用户消息未附文稿，需索取文件路径或请用户粘贴内容
3. 按 compose 契约执行润色压缩改写，验收标准明确：成品 ≤1000 字、保留草稿核心信息与论点

## 【WR-E02】"这份报告的引用靠谱吗？帮我核查一下参考文献。"

**路由决策：走 audit mode（引用与参考文献真实性审计）。**

**依据：**
- description「报告 mode 触发分流」第二条：「核查引用 / 查证出处 / 怀疑幻觉」→ audit mode——"核查"命中，"引用靠谱吗"即怀疑真实性
- 「mode 路由」节表格 audit 行：用途为"引用与参考文献审计（P0-P3 分级报告，不自动改报告）"，典型触发语「核查引用 / 查证出处 / 怀疑幻觉」逐词命中

**下一步动作序列：**
1. 读取 `modes/audit.md`，按契约执行
2. 获取报告文稿及其中引用/参考文献清单
3. 逐条核查引用真实性（查证出处），产出 P0-P3 分级审计报告
4. 注意执行边界（audit mode 定义明文）：**不自动修改报告**，审计结果交用户自行决策后续处理

## 【WR-E03】"我想知道这类行业分析报告一般应该有哪些章节，有没有规范结构可以参考？"

**路由决策：走 format mode（报告格式与结构研究），独立使用场景。**

**依据：**
- description「报告 mode 触发分流」第三条：「这类报告该长什么样 / 章节结构规范」→ format mode——"有哪些章节""规范结构"逐词命中
- 「mode 路由」节表格 format 行：用途"报告格式与结构研究（独立使用，或为 deep research 的 report_shape 提供依据）"——本条是知识咨询，不伴随写作任务，属"独立使用"分支，无需接 deep-research

**下一步动作序列：**
1. 读取 `modes/format.md`，按契约执行
2. 按 format 契约研究"行业分析报告"的规范章节结构（契约内如引用 `references/document-structures.md` 文档结构参考库则按其指引使用）
3. 产出行业分析报告的结构规范建议/参考框架，交用户参考

## 【WR-E04】"帮我写个报告。"

**路由决策：进入 mode/引擎分流判别，但信息严重不足——按 SKILL.md 明文规则执行"无法判断 → 询问用户"分支，暂不进入任何 mode 或引擎模式。**

**依据：**
- 「mode 路由」节分流规则（第 51 行）明文处理本场景："泛化的「写个报告」且无现成材料时：研究报告 → 引导先经 deep-research 取得材料再走 compose；创作型长文档 → 走引擎创建模式；**无法判断 → 询问用户**"
- 与 deep-research 分工节（description 尾部）："用户没有现成材料而要求'深度研究/调研'时，优先 deep-research"——本条无主题无材料，若是研究报告则材料获取环节不归本技能
- description 引擎模式触发注记（第 14 行）："研究报告类的'写报告'优先走上方 mode 路由"——但报告类型未知，无法套用

三路分支（研究报告 / 创作型长文档 / 询问）的判别依据全部缺失：无主题、无报告类型、无材料、无篇幅受众。主题是只有用户能做的决定，属真正阻塞，须停下询问。

**下一步动作序列：**
1. 向用户澄清三件事：报告类型（研究/分析/调研类 vs 创作型）、主题与受众、是否已有现成研究材料或文稿
2. 依回答分流：
   - 研究报告 + 无材料 → 引导先走 deep-research 取得调研产物，产物回到本技能 compose mode 成稿
   - 已有材料/文稿的研究报告 → 直接走 compose mode（读取 `modes/compose.md`）
   - 创作型长文档（手册/教程/书稿类）→ 走引擎创建模式（读取 `references/engine/create-edit-modes.md`）

## 【WR-E05】"从零开始帮我写一本 Python 入门手册，大概十个章节。"

**路由决策：走引擎创建模式。不进任何报告 mode。**

**依据：**
- description「引擎模式触发」第一条：创建模式触发语——"帮我写份长文档"、"写个手册/教程/书稿"、"从零开始写"（创作型长文档，无现成材料）——本条三重命中（"从零开始"+"手册"+十章长文档）
- 「mode 路由」节分流规则（第 51 行）："手册、教程、书稿……创作型长文档……走引擎模式"
- 「mode 路由」节（第 53 行）："长文档请求不进 mode，直接按下方引擎模式判断执行"——排除 compose 等报告 mode
- 引擎「模式判断流程」辨析：流程图中"创建"分支标注"且无'从'字"，其意图是排除第 62 行导入触发"从<某份文档>开始"；"从零开始"并非从现有文档出发，而是无现成材料创作，与 description 触发语"从零开始写（创作型长文档，无现成材料）"直接对应，判创建模式无歧义

**下一步动作序列：**
1. 读取 `references/engine/create-edit-modes.md`（创建模式完整手册，见资产索引）
2. 创建引擎工作区 `workspace/{project-name}/`：先建固定骨架 `00-structure.md`（约十章的章节大纲）与固定风格指南 `00-style-guide.md`（可参考 `references/writing-styles.md`）
3. Writer Subagent 逐章撰写（Subagent 定义随技能分发于 `.claude/agents/`）
4. Reviewer Subagent 对照结构大纲与风格指南逐章审查；不通过则 Writer 定向修改，循环最多 3 次，超限报告用户请求人工介入（「Subagent 架构」节协作关系规则）
5. 全部章节达标后运行 `scripts/merge.py` 整合，产出 `final-output.md`（「工作区概念」节文件体系）

**横向小结：** 五条请求覆盖了 SKILL.md 的全部路由面——WR-E01/E02/E03 分别命中 compose/audit/format 三个报告 mode（触发语逐词命中，各自先读 `modes/<mode>.md`）；WR-E04 是第 51 行明文规定的"泛化写报告"三路分流场景，因信息不足落入"询问用户"分支；WR-E05 是引擎创建模式（长文档不进 mode）。无一条误入引擎或 mode 的交叉区。
