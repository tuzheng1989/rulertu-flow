## 0. 背景与目标

用户延展想法：给两个思维技能引入"兼听"——宿主模型（Claude Code, Opus）与外部模型（Codex CLI，模型 `gpt-6.1-sol`、推理强度 `max`，见 2.5）分别独立思考，兼取两家之长，同时控制 token 消耗。

- 改动对象：`plugins/work-skills/skills/brainstorm/SKILL.md`、`plugins/work-skills/skills/inspiration-pacemaker/SKILL.md`，新增共用脚本 `plugins/work-skills/scripts/dual-listen.py`（两技能复用同一脚本），及其仓库级单元测试 `tests/test_dual_listen.py`
- 非目标：不做双模型多轮辩论链；不改两技能的归口/移交逻辑（/grilling、/brainstorm、/inspiration-pacemaker 三角关系不动）

## 1. 前提假设与方案取舍

**假设 1（兼听的价值来源）**：双模型的价值来自训练分布的去相关——不同家族的模型产生不同的想法分布与不同盲区。发散阶段（brainstorm）要的是"我想不到的分支"；下钻阶段（pacemaker）要的是"对结论的独立攻击"。外部模型的攻击点与盲区候选是**待验证意见**，不因来自另一个模型而自动成立——仍须走各技能既有的外部验证义务（数据反例、领域文献、可运行检验）。

**假设 2（调用机制复用已验证通道）**：宿主通过 Bash 执行 `codex exec --json`（与 plan-iterate 的 `codex_review.py` 同款通道；`--json` 向 stdout 输出 JSONL 事件流，`-o` 另存最终消息），只读沙箱（`-s read-only`），可读取工作区文件。

**取舍 A（调用时机 = 触发四路径，见 2.7）**：不每轮自动调用。显式请求即时执行；主动建议必须用户同意。
舍弃：固定每 N 轮自动调用——多数轮次不需要外部意见。

**取舍 B（上下文传递 = 唯一快照文件，非内容粘贴、非通配符）**：每次调用前，宿主生成一个**唯一命名的输入快照文件**（绝对路径 + 双引号包裹，含本次调用所需的材料），提示词只给这一个路径。对抗性检验与盲区扫描使用**不同的快照**（见 2.4）。

**取舍 C（会话策略 = 按模式划分，非一刀切）**：判据是**外部模型自身推理的连续性对下一次调用有价值还是有害**——

| 场景 | 策略 | 理由 |
|------|------|------|
| 发散 diverge | 单发 | 独立性即产品：带记忆会锚定自己往轮分支、倾向辩护 |
| 盲区扫描 blindspot | 单发 | 独立性要求最强，连宿主结论都不可见 |
| 对抗性检验 attack（同任务连续攻防） | **保持** | 宿主回应后，只有记得"自己当时为何攻此点"的模型才能判断回应是否真正闭合证据缺口、咬住未答好的点；会话前缀一致 → 前缀缓存命中，第 2 轮起只需发 delta（洞察修订 + 宿主回应），更便宜且更深 |
| 对外部输出的追问/澄清 | 保持 | 同一会话的自然续接 |
| 新任务/话题切换 | 单发 | 旧上下文是噪声 |

保持链失效（会话过期/进程失败）→ attack 降级为单发 + 增量快照（携带历史攻防，见 2.3）。发散类单发付小快照全价，购买独立性。

**取舍 D（机制交脚本执行——R5 后反转原决定）**：~~不新增脚本~~ → 新增共用脚本 `dual-listen.py`。原因：五轮迭代后机制已厚（排他目录、先扣次后启动、事件解析、五级失败分类），这些**确定性步骤**交给宿主模型按 prose 手工执行不可靠——prose 规格约束不了执行者。模型只保留判断性工作（触发、快照内容、合并与标注），机制全部下沉脚本，用单元测试保证。work-skills 内 skill 自带 scripts/ 已有先例（sn-search、route_ocr.py）。plan-iterate 评审脚本仍不复用（协议不同）。

## 2. 设计

### 2.1 记录载体与临时文件（两技能通用规则）

- **记录载体（兼听计数与证据的唯一持久化位置）**：
  - brainstorm：思考日志文件——状态行记计数（`兼听：x/3`），日志内新增"兼听记录"小节记每次调用的生效模型/用量/失败。
  - pacemaker：兼听台账 `<工作目录>/listen-ledger-<日期>-<任务关键词>.md`——头部记任务一句话（用于恢复核对），正文记计数（`已用 x/2`）与每次调用的生效模型/用量/失败。既有技能未定义任务产出文件，本节显式定义之；台账即恢复锚点，跨轮/压缩后从台账恢复预算与历史。恢复时核对头部任务一句话，不一致或同日同关键词存在多个台账 → 询问用户指定。
  - **载体写入失败（含台账创建失败）→ 本次不调用**，告知用户"无法持久化预算计数，兼听已跳过"。预算硬上限优先于任何调用。
- **扣次时序（先预留后启动）**：每次启动（含重试）前依次执行：① 查载体剩余预算 → ② 将扣次**先持久化写入载体** → ③ 写入成功后才启动进程。中断或进程未产生结果时**不返还**已预留次数（宁可低估剩余预算，不可高估）。
- **任务标识**：brainstorm = 思考日志文件名；pacemaker = `<日期>-<任务关键词>`。**台账首次创建遇同名文件 → 不覆盖**，追加序号新建（`…-2.md`、`…-3.md`），以实际创建的文件为本次任务的台账并记入日志输出。
- **临时目录**：以**记录载体所在目录**为基准的 `.listen-tmp/<尝试ID>/`——每次尝试一个独立目录，排他创建（已存在则换 ID 重建），快照 `in.md`、输出 `out.md`、事件流 `events.jsonl` 均置于目录内，唯一性由目录保证，任何重定向都不会覆盖已有文件。尝试结束后（成功合并或判定失败后）清理**仅本次**的尝试目录；清理失败记录残留目录名。宿主中断来不及清理的残留目录**不自动删除**，记入日志/台账为"待处理残留"，由用户决定删除。

### 2.2 brainstorm：兼听点 = 独立发散

- **输入快照**：尝试目录内 `in.md`，内容：话题种子 + 当前分支地图（分支名与一句话描述）+ 已饱和/僵局的说明。提示词给**该文件的确切绝对路径**（双引号包裹，禁用通配符）。
- **调用模板**（提示词 ≤200 tokens；`<repo>` = 记录载体所在目录的绝对路径，显式作为 Codex 工作目录）：

  ```
  codex exec --json --skip-git-repo-check -s read-only -C "<repo>" \
    -m gpt-6.1-sol -c model_reasoning_effort="max" \
    -o "<repo>/.listen-tmp/<尝试ID>/out.md" \
    "阅读 <repo>/.listen-tmp/<尝试ID>/in.md（可能性地图快照）。只输出地图上不存在的新分支：最多 8 条，每条 ≤40 字，各标注适用的发散透镜（SCAMPER/类比跨界/逆向假设/随机刺激/绿帽）。只发散，不评估。输出为 markdown 列表。" \
    > "<repo>/.listen-tmp/<尝试ID>/events.jsonl"
  ```

- **合并规则**（判定优先级）：仅当进程退出码 0 **且** 输出文件存在、非空、含 ≥1 条列表项时合并；超时/非零退出/中断时**一律忽略输出文件**，即使有部分内容。成功后将条目以"兼听分支（来源：codex，第 N 轮）"并入分支地图，不评判、不裁剪。
- **预算**：单会话上限 3 次，计数在思考日志状态行。

### 2.3 inspiration-pacemaker：兼听点 = 对抗性检验（默认）+ 盲区扫描（可选）

- **对抗性检验（会话保持，同任务连续攻防）**：第 1 次调用 = 全量快照（尝试目录内 `in.md`：钻探计划四问 + 洞察清单及每条论证链）+ 提示词"攻击这些结论，最多 3 个攻击点，每个 ≤80 字，指出反例或证据缺口。输出为 markdown 列表"。同任务第 2 次起由脚本自动 resume 上一线程（取舍 C），提示词只需 **delta**：修订后的洞察 + 宿主对往轮攻击点的回应（含论证），并可附"哪些点你认为未被真正回应，可继续咬住"。**resume 失效（会话过期/进程失败）→ 降级为单发 + 增量快照**（全量快照 + 此前攻击点及宿主回应 + 提示词附"已列出的攻击点不要重复"）。攻击点以"外部攻击点（来源：codex，待验证）"并入输出，每条由宿主追加**核实方式或说明不采纳理由**；洞察原有的外部验证义务不变。
- **合并规则**：同 2.2 判定优先级。攻击点以"外部攻击点（来源：codex，待验证）"并入输出，每条由宿主追加**核实方式或说明不采纳理由**；洞察原有的外部验证义务不变。
- **盲区扫描（可选，用户要求时）——独立快照防锚定**：另写尝试目录内 `in.md`，**只含**任务描述、必要背景与原始材料指针，**不含宿主的洞察与论证**。提示词："独立下钻此问题，输出最多 5 条你自己的洞察，输出为 markdown 列表。"宿主拿到外部结果后再与自己已有的洞察对比，差集标记为**候选盲区**（可能是任何一方背景缺失或质量差异，需用户判断）。
- **预算**：单任务上限 2 次，计数在兼听台账；每次启动前先查台账剩余预算。

### 2.4 快照差异一览

| 调用类型 | 快照含宿主结论？ | 内容 |
|---------|----------------|------|
| 发散（brainstorm） | 含地图（非结论，是现状） | 话题种子 + 分支地图 + 僵局说明 |
| 对抗性检验 | 含（必须，攻击对象） | 四问 + 洞察 + 论证链 + 此前攻击点及回应（第 2 次起） |
| 盲区扫描 | **不含**（防锚定） | 任务 + 背景 + 原始材料指针 |

### 2.5 模型与推理强度

- 显式传参：`-m gpt-6.1-sol -c model_reasoning_effort="max"`（不依赖宿主 config 默认值）。
- **实际生效的验证来源**：从尝试目录内 `events.jsonl`（由 `--json` 产生）的 `thread.started`/会话配置事件读取实际模型与强度；字段缺失时记为"请求值（未验证）"。
- **用量采集**：从同一事件流解析本次 token 用量（字段可分则分记输入/输出/推理，不可得标"不可验证"），写入记录载体。

### 2.6 失败分类（按优先级互斥判定，每次调用只命中一条；**所有首次启动与重试均扣次，重试前查剩余预算**）

| 优先级 | 类型 | 判定 | 处理 | 最终降级 |
|-------|------|------|------|---------|
| 1 | CLI 不可用 | 调用前 `command -v codex` 失败 | 不启动 | 本会话禁用兼听（不扣次，未启动） |
| 2 | 模型名不可用 | 错误信息明确指向模型名无效/无权限 | 不重试（不猜测替代模型名） | 本会话禁用兼听 |
| 3 | 强度不支持 | 错误信息明确指向 `model_reasoning_effort` | 回落 `"high"` 重试一次；回落仍失败 | 本会话禁用兼听 |
| 4 | 进程失败 | Bash 超时 120s 或其他非零退出 | 告知 stderr 摘要；可重试一次；**连续 2 次进程失败 → 本会话禁用** | 本会话禁用兼听 |
| 5 | 解析失败 | 退出码 0 但输出不满足合并条件 | 不重试，告知"输出格式不符" | 不禁用（下次可再试） |

- 降级时**如实告知"本轮无外部视角"**，禁止宿主自评冒充外部意见。
- 任何失败路径都执行 2.1 清理规则。

### 2.7 触发四路径（两技能通用）

| 路径 | 行为 |
|------|------|
| 用户显式说"兼听" | 立即执行。brainstorm：地图已存在即可调；pacemaker：洞察未成形时先完成💎区块再调，并向用户说明该顺序 |
| 主动建议 → 同意 | 执行一次，扣次 |
| 主动建议 → 拒绝 | 本轮不再建议，记录于日志/台账 |
| 建议后未回应 | 不调用，继续原流程 |

- brainstorm 主动建议时机：饱和提示 / 地图同质化（每次会话至多建议 2 次）；pacemaker：💎 区块首次成形时（每任务至多建议 1 次）。

### 2.8 兼听脚本 `dual-listen.py`（机制执行者，收尾修订新增）

2.1–2.7 中的**确定性机制**（预算扣次时序、排他目录、进程启动与超时、合并判定、2.6 失败分类、用量提取、清理）自本修订起全部由脚本执行；模型只做判断性工作：决定触发、撰写快照、读取脚本结果并合并/标注。SKILL.md 中的调用模板与操作 prose 相应删减为"写快照 → 跑脚本 → 按 JSON 结果合并"三步。

**接口**（单文件，仅标准库，无第三方依赖）：

```
python dual-listen.py --mode {diverge|attack|blindspot} \
  --snapshot <快照绝对路径> --workdir <记录载体所在目录> \
  --task-id <任务标识> --budget-limit {3|2} \
  [--model gpt-6.1-sol] [--effort max] [--prompt-file <提示词文件>]
```

**行为契约**：

1. **预算**：状态真源为 `<workdir>/.listen/state.json`（按 task-id 键控：`{used, disabled, model_effective, usage[]}`，原子写）。启动（含重试）前：查余额 → 预留扣次并落盘 → 才启动进程；中断不返还。日志/台账中的计数是展示副本，每次调用后从脚本输出回填。
2. **尝试目录**：排他创建 `<workdir>/.listen-tmp/<ID>/`，进程结束（任何结局）后清理本次目录，摘要写入 state。
3. **执行与策略**：`subprocess.run(..., timeout=120)` 精确超时；`--json` 事件流落盘；**会话策略按取舍 C 自动执行**——diverge/blindspot 恒为 fresh；attack 模式从 state 读取该 task 的 `thread_id`，有则 `codex exec resume`（提示词只发 delta），无则 fresh 全量快照；resume 失败自动降级单发增量快照。按 2.6 表做互斥失败分类与回落重试（强度回落 high、连续 2 次进程失败禁用会话等），禁用状态与 `thread_id` 持久化到 state。
4. **校验与解析**：退出码 0 + 输出非空 + ≥1 条列表项才算成功；从事件流提取实际模型/强度与 token 用量，字段缺失如实标"请求值（未验证）/不可验证"。
5. **输出**：stdout 打印单个结果 JSON：`{ok, output_path, failure, model_effective, model_verified, usage, budget_remaining, disabled}`。合并进日志/地图仍由模型做（判断性工作：来源标注、不评判）。

退出码沿用 plan-iterate 惯例：`0` 成功、`2` 输入错误、`3` 进程失败（重试后仍失败）、`4` 协议/解析失败。

**测试**：`tests/test_dual_listen.py`，注入假 codex（PATH 替换或 `--codex-bin` 参数）覆盖：正常路径、预算耗尽、预留后中断不返还、五级失败分类各分支、目录排他、清理、事件流字段缺失标注、**会话策略**（diverge 恒 fresh；attack 第 2 次自动 resume 且提示词为 delta；resume 失败降级增量快照）。

### 2.9 文档落点与改动范围

- 两个 SKILL.md 各新增一节"兼听机制"（≈30 行：触发四路径 / 快照内容要求 / 三步调用法——写快照→跑 `dual-listen.py`→按结果 JSON 合并并标注来源 / 降级行为）。机制细节不进 SKILL.md，出处唯一指向脚本与方案文档（2.8）。插入位置：brainstorm 在"信息检索"节之后；pacemaker 在"五大深度技法"之后。
- 不改 frontmatter description；不改既有硬规则与回合结构。兼听产出一律回流既有流程：分支入地图、攻击点入输出格式并遵守外部验证义务。

## 3. Token 经济（以实测为准）

- 结构性节省点（机制保证，非估算）：提示词仅含一个文件路径（≤200 tokens），不粘贴对话历史；**会话策略按取舍 C 分治**——发散类单发付恒定小快照全价购买独立性；attack 保持会话吃前缀缓存、第 2 轮起只发 delta，成本与深度同向受益；输出条数/字数在提示词中约束。
- 实际用量（含 Codex 自读快照的输入消耗）按 2.5 从事件流实测并写入记录载体；推理用量若事件流不可验证则如实标注。实测前不做定量断言。

## 4. 验收标准
