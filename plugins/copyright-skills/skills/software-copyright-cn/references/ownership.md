# 权属证明文件决策表

中国版权保护中心官网申请须知要求：按申请情形提交相应权属证明文件。官方要求以官网现行文本为准；本文件只整理按情形取交集的必需文件清单，不新增无法核对的文件项。

核对记录：中国版权保护中心官网"所需文件"页（https://www.ccopyright.com.cn/index.php?optionid=1080），核对于 2026-09-03。凡标注"以官网现行要求为准"的项，使用前必须由人工到官网复核，复核通过后更新本记录的核对日期。

## 情形 → 必需文件决策表

| 申请情形 | 情形标识 | 必需文件 | 说明 |
|---|---|---|---|
| 独立开发 | `independent` | 著作权人主体资格证明 | 企业为营业执照，自然人为身份证等身份证明 |
| 合作开发 | `cooperative` | 著作权人主体资格证明；合作开发合同 | 全体著作权人各自提供主体资格证明；合作开发合同证明权属约定 |
| 委托开发 | `commissioned` | 著作权人主体资格证明；委托开发合同（或任务书） | 合同或任务书用于证明委托关系与著作权归属约定 |
| 职务作品 / 法人作品 | `employment` | 著作权人主体资格证明；能证明职务创作或法人归属的材料 | 任务书、劳动合同或单位证明，按官网现行要求为准 |
| 二次开发或修改他人软件 | `derivative` | 著作权人主体资格证明；原著作权人许可证明（授权文件） | 授权文件由原著作权人出具，须覆盖本次修改与登记的范围 |
| 受让取得 | `transferred` | 著作权人主体资格证明；转让合同 | 转让合同证明权利移转；受让方为主体资格证明上的著作权人 |

补充口径（跨情形）：

- 涉外主体：外文材料需附中文翻译件。翻译件的签章与形式要求以官网现行要求为准。
- 除决策表所列文件外，不虚构额外文件；官网口径更新时以官网为准修订本表。

## 文件三态

每个必需文件按下列三态记录，不使用其他状态值：

| 状态 | 判定规则 |
|---|---|
| `provided` | 用户已交付该文件，且文件名、签章主体、著作权人与事实表口径一致 |
| `pending` | 该情形需要此文件，但用户尚未交付或内容口径未确认 |
| `na` | 该文件对本情形不适用，且有明确理由（如自然人申请人无营业执照，在 note 中写明理由） |

判定优先级：先判断适用性（`na`），再判断交付状态（`provided` / `pending`）。判 `na` 必须写理由，不允许静默省略必需文件。

## 权属文件清单 JSON schema

本节是权属文件清单格式的唯一出处，后续校验脚本（`check_submission.py`）按此消费。

```json
{
  "scenario": "<六种情形之一的标识：independent | cooperative | commissioned | employment | derivative | transferred>",
  "items": [
    {"file": "<证明文件名>", "type": "<identity|contract|license|translation|...>", "status": "provided|pending|na", "note": "<说明>"}
  ]
}
```

字段约定：

- `scenario`：决策表中的情形标识，六选一。
- `items[].file`：证明文件名，与实际交付文件名对应；`na` 项可为空字符串。
- `items[].type`：文件类型，取 `identity`（主体资格证明）、`contract`（开发/转让合同、任务书）、`license`（许可证明/授权文件）、`translation`（中文翻译件）等。
- `items[].status`：三态之一，见上文判定规则。
- `items[].note`：说明；`na` 项必须在此写明不适合理由。

消费规则：

- `status=pending` 的项必须进 `review-needed.md`，逐条列出待补文件与责任方。
- 提交前校验：存在 `pending` 项时按阻断处理，即内部暂停提交，待补齐并复核后再进入上传流程。
- `scenario` 不在六种标识之内，或 `status` 不在三态之内，视为清单无效，不进入提交校验。
