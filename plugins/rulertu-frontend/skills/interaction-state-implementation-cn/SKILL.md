# 页面交互与状态开发

## 三十秒开始

直接提供任务对象、当前材料和期望完成状态。可以这样说：

- “修复切换客户后旧请求覆盖新页面的问题，并补回归测试。”
- “提交失败现在显示保存成功，定位字段和状态映射后修好。”
- “实现表单重复提交保护，按钮、回车和快捷键都要覆盖。”

本能力处理的是**前端状态转换与真实接口结果**。先读取现有证据，再产出可复核结果；未读取、未执行或未获授权的事项保持“待确认”“受阻”或“未验证”。

## 输入与缺项处理

优先读取：

- 相关组件、路由和接口客户端
- 可观察行为或复现步骤
- 项目测试与运行命令

缺少“关键材料”时，先完成不依赖它的结构、风险清单或离线检查，并标明影响。使用以下格式，禁止只说“请提供更多信息”：

> 需要补充以下 N 项才能完成：具体材料、用途、可接受格式。当前已完成：可确认部分。待确认：会改变结论的事项。最小补充项：下一份材料或一次只读验证。

## 执行工作流

1. 沿用户动作追踪请求参数、响应、转换层、状态与反馈
2. 先识别项目已有状态方案：React Query、SWR 等以完整 query key 隔离筛选并向 fetch 传 AbortSignal；Redux 或状态机遵循现有 reducer；只有手写异步 state 才增加 requestId 或 AbortController，不为简单查询强建状态机
3. 在唯一转换位置修正字段映射、错误分类与权限语义
4. 补回归测试覆盖重复提交、A/B 请求逆序完成、卸载、当前 key 失败与重试

执行中保留实际命令、文件位置、版本、时间或截图编号。依赖系统不可用时，离线完成材料审查与复测步骤；失败对应的范围明确写“受阻”，不能用样例结果代替。

## 核心判断

- 请求失败不能降级成无数据或模拟成功
- 快速切换时只允许最后一次仍有效请求更新界面；查询缓存可保留旧 key 结果，但不能提交到当前 key 的可见状态
- 用户只要求只读方案时，修改文件与测试结果改为“拟改位置”和“待执行命令”，不得为了满足格式写成已修改

每个判断都要绑定证据位置和核验状态。事实、推断、建议与未验证项分开表达，不能把计划、目标或预计结果写成已经完成。

## 交付物

- 修改文件清单（实施任务）或拟改位置（只读任务）
- 状态转换表
- 字段与错误映射
- 回归测试结果（已运行）或待执行测试（只读任务）
- 未联调与残余风险

完整字段与完成门见 [输出契约](references/output-contract.md)。需要对照真实输入与结果时读 [完整示例](references/examples.md)。

## 安全和禁止行为

- 用户只要分析时不改文件
- 不安装无关状态库或覆盖工作区改动
- 不发布、不写生产数据、不记录真实响应中的敏感字段
- 不编造命令结果、系统状态、性能数字、测试通过或外部事实。
- 不执行删除、发布、生产写入、扩大权限或外部发送，除非用户明确授权且目标可核对。

## 能力边界

擅长：围绕前端状态转换与真实接口结果完成证据化分析、方案、审查或验证；能处理材料不全、工具失败和高风险边界。

需要素材：至少需要相关组件、路由和接口客户端、可观察行为或复现步骤、项目测试与运行命令中的一项；否则只能交付空白框架和最小补充清单。

超出范围：需求不清先用前端需求与验收设计；只处理布局用响应式适配；真实浏览器结果由旅程验收确认。

## 定制参数

可传入技术栈、版本、环境、风险等级、目标受众、输出载体和允许动作。默认按最高风险路径排序；可要求输出飞书文档表格、Markdown、议题草稿或测试清单，但证据和安全门不能关闭。

## 常见问题

1. **只有截图或日志片段能做吗？** 能先提取可见事实；看不到的系统行为保持未验证。
2. **可以直接修改吗？** 只有任务明确包含实现且当前能力范围允许时；否则只给建议或补丁草稿。
3. **工具不可用怎么办？** 保留离线检查、受阻原因和现场复测步骤，不伪造运行结果。
4. **怎么处理敏感数据？** 使用虚构或脱敏样本，令牌、密码、证件号和客户数据不进入报告。
5. **多个问题同时出现怎么办？** 先处理阻断、安全或不可逆风险，再处理质量与体验问题。
6. **输出能直接用于生产吗？** 需由责任人核对版本、环境、审批和完成门；未验证项不能随发布流转。
