# 网页性能诊断方法

优先看真实用户高分位，再用受控环境复现。前后对比至少运行多次并报告环境、缓存、样本与波动。第三方脚本、图片、字体、框架代码和接口分别归因；第三方项至少记录域名、传输耗时、是否阻塞关键渲染及其主线程任务。

## 证据顺序

1. 从用户症状确定页面、操作和指标。
2. 用性能 trace 定位时间花在哪个阶段。
3. 找到对该阶段贡献最大的资源、任务或组件。
4. 写出改动后应变化的指标和不应变化的业务行为。
5. 同环境重复测量，报告中位数、高分位和样本数。

性能预算可包含关键脚本与样式体积、图片上限、核心体验指标、长任务数和内存增长。阈值必须说明适用页面和测量环境。不得通过移除必要功能、推迟必要错误提示或降低无障碍性达成。

当两次测量环境、缓存或样本口径不同，结论只能写“不可直接比较”，不能计算一个看似精确的提升比例。
