# 网页界面交付检查

## 开工前

- 找到应用入口、路由、相邻页面、设计令牌、请求封装和测试惯例。
- 写清当前仓库中的真实实体、字段来源、权限条件和保存目标。
- 把需求拆成状态与事件；未知行为采用最小可替换假设。

## 实现中

- 组件只接收页面语义数据；服务端 DTO 在边界适配。
- 异步请求能够取消或忽略旧响应；卸载后不更新状态。
- 写操作能够阻止重复提交，失败后保留用户输入并允许重试。
- 列表键使用稳定业务标识，不能使用数组下标掩盖重排问题。
- 中文长文案、极端数字、空值与真实数据长度进入测试数据。
- 对不可信 HTML、跳转 URL、文件名和富文本做项目既有的校验或清洗；不把令牌和敏感字段写入前端日志。

## 浏览器最终验收

检查主任务、返回或取消、刷新、深链、空数据、慢请求、失败重试、无权限、重复点击、长文本、窄屏和键盘操作。生产接口不可用时展示诚实状态，不用本地假数据伪装成功。

视觉比较同时看信息层级、间距、字体、颜色、组件状态和内容密度；像素差异不能替代行为验收。

交付证据至少包含：修改文件、用户可见变化、实际运行的验证命令、浏览器路径、未覆盖环境。不要声称未运行的检查已通过。

若任务涉及快速切换筛选、路由或账户，回归测试必须控制两个请求的完成顺序，证明晚到旧响应不会覆盖新状态；不要只测加载和空状态。
