# Agent 前端方法论

为任何 harness（deepagents / LangGraph / AG-UI / 自研事件总线）之上的后端 agent 构建对话前端的方法论。提炼自真实的调度型 agent 前端（React + Zustand + SSE），每条规则背后都是一次实际翻车。

核心判断标准：**用户在任何时刻刷新页面，看到的与刷新前完全一致**。这条标准会推出下面几乎所有设计决策。

## 0. 十条不可动摇的不变量

动手前先对照这十条。违反任何一条，用户会在某个时刻看到"跑完的和刷新后不一样"、"一张卡在跑另一张发不出消息"、"旧数据覆盖新请求"。

1. **实时与历史走同一段投影代码。** 事件 → 视图状态的 reducer 写成纯函数（不碰 store、不发请求），实时 SSE、历史回放、刷新还原三条路径共用。两条路各写一份，迟早漂成"实时能渲染、回放渲染不出来"。
2. **线上帧与历史帧是同一种帧，翻译只有一处。** 后端应把流式事件与会话历史统一成同一种消息帧；前端相应只留一个 `frameToMessage`。委派节点会先后流出 SubAgent 稿与整合稿——chunk 拼出来是两稿相接，最终显示必须以收口时的一次性完整帧为准。
3. **运行期是投影，落库是权威，终态后读回。** 运行期展示滚动状态气泡（"正在理解任务…"），终态一到就从库里读回权威版本整轮替换。不做这次读回，"跑完看到的"和"刷新后看到的"就是两个东西。
4. **中断不是终止。** HITL interrupt 只结束当前 SSE 段，订阅自动从游标续接；Run 收口也不等于请求收口（链升级后 Request 仍在途）。只有明确的终态锚点能关流、停心跳、收口输入框。
5. **事件族判别靠载荷判别键，不靠事件名。** 同名事件可能属于不同族（新旧协议并存），判别键放 payload 里（如 `mode` 字段）。按名字分流会把别人的帧误吃掉。
6. **终态判定 fail-open。** 前端认不出一种新终态时，宁可让用户持续等待（还有刷新兜底），也不要把进行中的请求误判成已完成。镜像后端白名单的**补集**（如"唯一不算结算的受控中断态"），后端加终态时前端零改动。
7. **一切按会话/轮次 keyed，杜绝全局单例。** 流式标志、AbortController、计时器、心跳全部 per-session 存 Map。全局单 boolean 的后果：多张任务卡并存时，一张在跑会把所有卡的发送按钮钉在"停止"态。
8. **异步读回必须对账。** 读回是异步的，返回前用户可能已提交下一轮。每次提交递增请求序号，读回落地前比对；同轮多次读回用代次号防乱序旧快照回退新快照。
9. **一切增量操作幂等。** SSE 重连/重放会让同一帧到达两次：文本按序号游标丢弃旧帧；工具行按 `tool_call_id` 去重不叠行；计数类取已见最大值不倒退；重复的提示帧同引用返回。
10. **UI 状态由事件统一收口，本地不抢跑。** 暂停/恢复/终止的按钮点击后只置"提交中"，等后端事件回来改 phase。本地抢先置成功，而后端其实没成功时两边永远对不上。同理：提交后先显示"正在理解任务"，别抢跑"正在规划"——顺序要与后端流水线一致，否则阶段卡闪现。

## 1. 输入区状态机

输入区不是"一个框 + 一个按钮"，是一台状态机。至少这些态，每态决定 placeholder、按钮文案、可用性：

| 态 | 按钮显示 | 输入框 | 说明 |
|---|---|---|---|
| idle | 发送 | 可用 | 前置校验（模型未配好→警告条+禁用） |
| streaming（Run 级） | 停止（=暂停，可恢复） | 禁用 | 暂停而非终止，是更安全的默认 |
| streaming（请求级直答） | 回答中…（禁用） | 禁用 | 没有 Run 可暂停，只能等收口 |
| paused | 补充并继续 | 可用 | 发送 = 带补充方向恢复，不是新请求 |
| 回放中 | 回放中 | 禁用 | 回放锁输入，防事件交错 |

要点：

- **判级前后按钮语义不同**：请求还没判出是 Run 还是直答前保留"停止"；判为请求级后只能等。这是"Run 终态 ≠ 请求终态"在按钮上的投影。
- **暂停态发送 = resume(supplement)**：会整图重排、已完成节点作废——代价超过阈值时必须让用户二次确认（`window.confirm` 列出将作废的节点数）。
- **乐观投影与认领**：发送瞬间本地先落 user 消息 + assistant 状态气泡，打上 `unclaimed` 标记和本次提交的 `localId`；建档成功拿到 runId 后由 `beginTurn` 统一盖章认领；建档失败按 `localId` 精确清除标记（并发提交时不得误清较晚请求的标记），让它们退化为无归属消息。
- **命令面板**：输入 `/` 唤起技能/流程选择。选中的技能作为**结构化参数**随请求透传，绝不拼进 goal 文本——拼进去的消息刷新后与库里不一致。
- Enter 发送、Shift+Enter 换行；textarea 随内容自动增高。

## 2. 提交与转发

- **提交是异步建档，不是同步执行。** `POST /responses` 立即返回 runId（`background: true`），随后前端单独订阅事件流。两条请求之间有窗口：本地的状态气泡、占位标题都应能被随后的真实事件幂等覆盖。
- **上游元数据透传**：前置服务的身份类 metadata 随请求带上，供工具声明引用注入下游。空对象整键不发——"没带"与"带了个空的"语义应一致。
- **澄清作答 = 组新请求重判级，不是回填旧卡。** 卡是那一轮的终点：点选选项后按「原输入（题面：答案）」拼一条新用户消息走完整入口。旧卡永不变化；用户不理卡直接发新消息也正常判级，两条路互不干扰。参数题把原命令回填输入框供修改（只认会话最新一条消息、用户已有草稿不覆盖）。
- **重试 / 编辑重跑**：从目标消息向前找最近一条 user 消息重发；编辑后同样走完整提交入口。
- **取消走 HTTP 旁路**：点击终止先 `abortSession` 断本地流，再请求后端 cancel。断流后收不到终态事件，必须自己收口气泡；取消请求失败必须明确警告用户"后台任务可能仍在执行"（静默吞掉 = 谎报停机）。409（他处已终态）时安全回读核实，按 Run 行终态还原。
- **会话命名权归后端**：前端只做本地占位标题（压空白 + 按码点截断），权威名随事件回来后本地追平；已命名的会话一个字都不动。

## 3. 附件

- **先上传、后提交**：附件在发送时先传到会话资产接口拿回执（asset_id、文件名、大小、状态），回执直接作为本地消息的 `references` 投影——与后端落库的那份同形，运行期附件 chips 才和刷新后一致。上传失败则整次提交中止并警告，不裸发。
- 上传回执同时转为请求里的结构化资源引用（`{type:'asset', asset_id}`），文本 goal 不掺附件信息（或仅生成一句说明文案）。
- **前端预校验**：扩展名白名单 + 单文件大小上限，逐文件警告、合法文件照常入列。
- FormData 请求不要手动设 Content-Type（会丢 multipart boundary），让浏览器自己带。

## 4. 事件流管线

分三层，各自独立可测。

### 4.1 传输层

- **fetch 手解析 SSE，不用 EventSource**：EventSource 无法带 Authorization 头。逐帧解析 `id:`/`event:`/`data:`，多行 data 拼接。
- **游标续传**：每帧的 `id` 记为 `lastEventId`，重连/续订时 `?starting_after=<cursor>`。刷新还原后从快照携带的 event_cursor 接上，历史 token 不会伪装成实时输出。
- **重连策略**：指数退避（如 `min(500×retries, 3000)`）封顶次数（如 8 次）；4xx（408/429 除外）不重试直接上抛——重试无益。
- **关流时机由终态判定**：收到终态（且非 interrupt）才 return；interrupt 后 reader 会抛"连接关闭"，进入重连分支从游标续接——这样被动标签页也能观察到其他入口发起的恢复。
- **丢帧不炸流但要留痕**：单帧 JSON 解析失败 `console.warn` 跳过。后端事件形状变了的表现只是"某段内容不显示"，没有任何线索——静默吞掉是最难查的 bug。

### 4.2 投影层（reducer）

事件 handler 是一个大分派函数，要点：

- **chunk 与帧分工**：chunk（TEXT/REASONING/TOOL_CALL 增量）只做流式预览（打字机由状态气泡承担）；各阶段收口时的**完整消息帧**才是最终显示的依据，按 `(runId, messageType)` upsert——更新不重排（澄清改写后消息位次不后跳，与后端落库保留原 seq 同口径）。
- **文本合并**：相邻 text chunk 就地合并成一个槽位，否则一个节点攒出上千个单字项、每项一个 Markdown 实例。同时维护一份**交错流**（text/tool 按发生位置交错）用于还原执行过程时间线。
- **终态节点守卫**：快照获取与 SSE 订阅是两个请求，并发转移可能两边都有——对已终态节点，一切 start/chunk 事件直接丢弃，绝不复活、绝不追加。
- **工具四态**：running / completed / failed / **waiting_human**。"等人批准"曾经和失败合流，界面上会把用户正要去批的那次调用标成红色失败。工具开始行按 `tool_call_id` 去重；收到回执但找不到开始行时**补一条已完成行**——从非 0 游标接入时开始帧可能根本没到过本端，让这次调用凭空消失比顺序略有出入更糟。
- **阶段计时心跳**：首个增量到达前模型可能静默很久，用滚动状态（spinner + 真实 elapsed）占位，收到真实 delta / 阶段结束 / 终态立即停。
- **提示帧三类同律**：排队、链升级、资产锁等待都是"非终态、只置提示"的帧——幂等置位、真起跑帧清除、终态兜底清除。显示用双门（状态字段与文案字段同时在场才显示条）。

### 4.3 渲染层

- **思考块**：活跃时默认展开 + 脉冲图标 + 光标；历史消息默认收起。`key` 区分活跃/历史，避免流式转历史时状态残留。
- **工具调用块**：超过阈值（如 3 条）折叠只显示最近几条 + "等 N 个工具"展开钮；每工具按名字选渲染器（注册表模式：文件类、文档生成类各有专属渲染，其余走 Default）；每个工具卡 = 标题行（名称+摘要+完成/执行中 badge）+ 可展开详情（入参/回执 JSON）。
- **正文**：Markdown 渲染；消息级阶段标签（"任务理解""执行图"）用帧里的 label，前端不自建映射表——标签绝不塞进正文（正文必须与库里逐字一致）。
- **自动滚动**：距底 < 30px 视为"跟随"，用户上滚即停，发送/重试时显式恢复。流式期间每条消息变化都滚。
- **截断分级**：后端对超大帧有卸载顺序（重字段 → 正文 → 结构化结论），前端拿 `truncated` 标记置 `detailLoaded=false`，用户点开时按 run+node 回源补全。单值显示截断按 Unicode **码点**切（`Array.from`），按 code unit 会把 emoji 劈成乱码。

## 5. HITL（人工介入）

- **interrupt 语义**：AG-UI interrupt 结束当前 SSE 段，但订阅自动从该游标续接并阻塞等待审批结果——`live` 必须保持 true（置 false 会让被动标签页谎报断流）。此刻：收口聊天输入态（放开按钮方便操作卡片）、置 `waiting_human`、渲染审批卡。
- **审批卡先于 interrupt 到达**（HITL 完整消息帧），用户看到卡片的时刻早于 SSE 分段结束——这是刻意的。
- **两种卡**：
  - **审批卡（actions 型）**：标题 + 上下文 + 动作按钮（批准/拒绝/中止），可带备注。防御式解析：载荷畸形或缺失动作列表时，兜底渲染通用"批准并继续 / 拒绝并结束"卡——**绝不因载荷畸形白屏**。
  - **澄清卡（form 型）**：多题目（单选/多选/文本/参数题）。有选项的题点选即提交；text 题在卡上作答（全局输入框裸发答案没有题面上下文，判级无法关联）；参数题回填原命令。
- **提交审批后**：走 required-action 接口 → 重续事件流（从 interrupt 游标之后，不需要重放）→ 恢复执行事件把输入区切回运行态。带执行租约时提交后恢复心跳。
- **执行租约**：页面持有心跳（如 5s 一次，409 即弃）；页面关闭/刷新时 keepalive 尽力暂停，未送达由服务端租约超时兜底。多页面安全由租约 owner id 保证。
- **暂停 ≠ 审批等待**：暂停是非终态可恢复（checkpoint 保留），恢复可带补充方向（触发重规划的代价要二次确认）；审批等待中不可暂停（点了只得 409）。
- **回放中的历史审批**：不弹真卡，只在时间线上标注"历史人工确认，回放沿用当时的决定"。

## 6. 交互卡片

结构化结果不是"更好的 Markdown"，是消息 `metadata` 上的投影指令：

- **判别键**：`metadata.presentation_type`（`data_card` / `clarification`，互斥）。解析函数做完整形状校验——任何字段缺失/类型不符返回 null，**降级渲染 content 的 Markdown**。旧消息与畸形数据不报错、不白屏，content 里永远有一份兜底文案（后端保证）。
- **卡片即轮次终点**：卡出现的那一轮到此为止，不挂起、不计时；之后的新消息按新请求正常判级。
- **结构化投影只落库、不进事件**：卡的 fields 在落库消息的 metadata 里，事件流只有收口信号——前端收到信号后**窄读回**（只读最近一条、带请求序号对账），把状态气泡替换成结构化卡。
- **data_card 形态**：上方 lead（Markdown 摘要）+ 下方「键｜值」字段列表；字段数超阈值折叠（"展开全部（共 N 个字段）"）、单值超长截断可展开、后端裁剪计数显示"已截断"提示。
- 渲染优先级在消息内容层显式排列（搜索高亮临时降级纯文本 > data_card > clarification > 默认 Markdown），一处判断、可注释互斥关系。

## 7. 轮次、多会话与回放

- **轮次 = 一次 Run**：消息带 `runId`，轮次头单独一张表；切分点 = runId 变化的那条消息。无 runId 的实时消息跟随上一轮分组但**不被折叠**——它正是用户此刻在等的那条。
- **折叠轮的轮次头必须保留**：消息剔除后头仍在原位，否则"展开"按钮随消息消失、这轮永远恢复不了。同一渲染下标可挂多个轮次头；末尾折叠轮由渲染方在消息流之后补出。
- **轮次视图存档 byRun**：每轮的执行图/节点/终稿独立存档，新一轮不顶掉上一轮；实时事件落在自己那轮（用户翻看历史轮时补丁写进存档不动当前视图）。
- **回放 = 同一 reducer 的重放**：拉全量事件账本，按相位定速播放（chunk 25ms、工具 500ms、节点切换 300ms、收口 350ms，÷倍速），复用实时事件 handler（`replay: true` 时**不回读、不收口真实轮次、不弹真卡**）。开始前备份消息/轮次/视图，结束或中止时恢复；执行中的会话禁止回放（事件与 SSE 交错）。
- **会话删除要设墓碑**：已排队的回调与 SSE 尾事件仍会抵达，墓碑集合让迟到写入 no-op。

## 8. 会话列表与历史管理

侧栏列表和主区历史是两套独立的加载策略，都有自己的坑。

### 8.1 会话列表

- **分页探测**：请求 `limit + 1` 条，多出的那条只用来判断 `hasMore`，显示时截掉。触底加载用去重合并（防并发请求重复）。
- **新建前插 + 封顶**：新会话插到列表头；列表还是"仅首页"形态（≤ 页大小）时封顶页大小、挤出尾条并置 `hasMore`——与刷新后重新拉首页的结果逐项一致。已触底加载过更多（> 页大小）就不封顶。
- **命名权分层**：`title_source` 区分 `auto`/`manual`。未命名的会话本地先显示占位标题（规则见 §2），权威名随事件回来才追平并标 `manual`——之后任何新一轮都不再碰它。本地改名不发请求（见 §0.10 同律）。
- **删除要彻底**：删一个会话要 abort 它的流、停它的计时器/心跳、清它的续传游标，并在 store 里清掉 messages/turns/views 等全部 key。再加墓碑（§7）：已排队的回调和 SSE 尾事件仍会抵达，墓碑让迟到写入 no-op，不然被删除的会话 map 又被重建出来。
- **切换会话 = 存档换出**：当前轮次视图存档后换入目标会话的视图（存档有就用，没有给空视图），绝不共享一份"当前 Run"。

### 8.2 历史加载

- **已加载过的会话不重复拉**；按轮次（run）取回，跨轮消息（澄清、直答这类不建 Run 的）单独带回。
- **消息游标续页**：跨轮消息每页有上限，超出的沿 `next_message_cursor` 往更早续取。终止保证两条：游标必须变化（同一游标再出现即停）+ 页数上限（防游标异常时无限请求）。
- **合并去重重排**：续页消息的序号会与页内 Run 消息交错，不能直接拼接——按 id 去重、按 seq 全局重排。
- **展示集谓词同源**：终态轮次滤掉暂停留下的 status 行（"可继续执行"在已终止轮里是误导的第二条收口），这个谓词必须与实时读回的展示集同一段代码；暂停轮的 status 保留；`run_id` 为空的跨轮消息不属于任何一轮，一律不动。
- **占位标题回填用会话首条输入**：历史默认只取最近 N 轮，从本页找首条 user 消息会拿到近期输入而非会话首条——用后端窄读的会话级 `first_user_input`，跨分页稳定。回填规则必须与起跑时的占位规则**逐字同源**，否则刷新前后侧栏标题闪变。

## 9. 刷新还原（快照 → 视图）

刷新/切回历史轮时，产品快照（Response 对象）是第二权威入口，它与事件路径必须同口径：

- **快照转视图的函数与事件路径共用终态映射**：后端 status → 前端 phase 的映射、降级计数解析、失败分类，一处定义两处用。paused 对外的 status 也可能是"等人拿主意"，靠 phase 字段区分——还原出来的暂停轮 `running` 必须为 false，否则卡片显示"在跑"按钮又是"停止"。
- **`running` 与 `live` 是两个字段**：`running` 反映后端执行态（还原出来"仍在跑"的快照也是 true），`live` 表示本标签页当前是否挂着活 SSE——还原的快照永远 `live: false`，续订成功才置 true。
- **续订起点来自快照的 event_cursor**：先写回游标再订阅，快照之后的新事件进实时投影，历史 token 不会伪装成实时输出。
- **取消态快照要补投影**：前端断流后收不到收口事件，快照也可能仍把未执行分支存为 pending——统一投影：running→cancelled、pending→skipped（区分"条件分支未选中"与"未到达"两种 reason）。
- **懒加载重产物**：最终结果 HTML/blocks、节点详情在用户打开对应页签时才拉，inflight 去重（防 StrictMode 双触发 + 快速连点）；拉回时会话已切走就丢弃。
- **本地存档优先于重新拉取**：这一轮在本次访问里跑过或看过，存档里的实时产出比重新拉的产品快照更细——直接切存档，不要用粗快照覆盖。
- **节点详情优先读帧**：详情接口若能回源当时推的完整帧（与实时同一形状），读法与实时完全一致，不需要第二套字段分支；平铺字段只做兜底。后端只为运行中节点重放得出交错时间线，终稿落库后是空数组——别用它覆盖本端 SSE 已攒好的流。

## 10. 执行过程视图与周边能力

调度型 agent 通常除了对话流还有执行面（DAG/节点详情/结果页签），加上一组周边能力：

- **不伪造空图**：执行图只在后端真发过"计划就绪"事件（或快照里有节点）时画。直答/单步模式后端根本不建图，画图框等于伪造——分别给直答流与结果卡各自的呈现面。
- **节点三份内容分字段**：`live_output`（纯正文，Markdown 与 blocks 兜底都读它）、`stream`（text/tool 交错的时间线）、`thinking`（思考与生命周期行）。就绪集推导（哪些节点可以点亮为 running）由已完成集合 + 条件边推导，条件后继只有在收到真实 STEP_STARTED 后才可运行。
- **时间线 feed**：节点完成、等待人工等关键节点追加一条带动作跳转的记录（"查看节点/查看结果"），比把确定性交接索引贴进对话流有信息量。
- **搜索**：Ctrl+F 唤起、跨消息字符偏移定位、命中消息滚动居中。命中正文时临时退回纯文本高亮渲染（Markdown 结构里按偏移插 mark 会错位），当前命中与普通命中区分样式。
- **导出/下载**：Markdown / HTML 两种导出，下载统一走一个 helper（统一处理吊销时序），带鉴权取流后转 blob。
- **连接状态指示**：独立的连接探测（ navigator.onLine 类语义），HUD 显示"信号: 正常/断开/检测中"——流式静默期用户靠它区分"在跑"和"断网"。
- **多标签页协调**：同一账号多标签页看同一 Run 时，执行控制权由租约裁决（§5）；被动标签页靠 SSE 自动续接观察到别处的审批与恢复，不重复发控制指令。
- **鉴权与错误底座**：请求层统一注入 Bearer 头、401 清认证态回登录页、统一信封拆包只认"三键齐"（恰好带 code 字段的业务对象不被误拆）、顶层 ErrorBoundary 兜渲染崩溃。这些是所有前端的标配，但 agent 前端的事件流错误路径（§4.1）要额外走同一套 ApiError 分类。

## 11. 工程与验收

- **分层**：`api/client`（传输 + 端点）→ `stores/*`（zustand，事件 reducer 是可独立单测的纯函数）→ `hooks`（组合：附件/自动滚动/轮次布局/搜索）→ `components`（渲染）。组件订阅用 selector + shallow，只订阅真正消费的字段。
- **测试策略**（reducer 纯函数是最易测、回报最高的资产）：
  - reducer 单测：同帧重放幂等、序号倒退丢弃、终态判定含 fail-open 分支、非本族帧原样放行（引用相等）。
  - store 测试：乐观投影→认领→失败清理的完整生命周期、读回序号对账、终态读回的守卫分支（缺收口消息不替换）。
  - 组件测试：卡的畸形 metadata 降级、工具折叠阈值、思考块活跃/历史默认态。
- **验收金标准**：本地收口态 ≡ 读回落地态 ≡ 刷新态，三方一致。每修一个 bug，问一句"刷新后还一致吗"。
- **防御式读取一切事件载荷**：`typeof` 检查 + 缺省回退，畸形帧退到基线文案而不是炸渲染。后端加字段时前端零改动，这是漂移方向的考量——认不出新失败态宁可标失败，不要标成完成。
