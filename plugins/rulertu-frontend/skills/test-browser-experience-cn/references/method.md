# 浏览器体验验收方法

证据至少包含页面状态与一个行为结果；涉及数据写入时核对刷新后的持久化结果。关键错误保留控制台或请求证据。

测试矩阵按业务实际选择浏览器、视口、角色、语言和网络，不追求所有组合。未覆盖组合明确列出。高风险生产动作使用测试环境、沙箱账户或明确授权。

每个旅程至少回答：

- 用户为什么来到这个页面，成功完成的可观察结果是什么？
- 哪个角色或数据条件最容易暴露权限和空状态问题？
- 返回、刷新、重复点击、慢请求或会话过期后应恢复到哪里？
- 哪一项失败会阻断发布，哪一项可以带已知风险发布？

自动化适合稳定、重复的业务断言；视觉层级、触控舒适度和跨页面连贯性仍需浏览器观察。自动化通过不等于体验通过。

`acceptance.json` 的最小结构为 `defaults`（可选的 roles/viewports/browsers/networks/locales）和非空 `journeys`；每个 journey 至少包含 `name`、`expected`，并可覆盖默认维度和填写 `risk`。脚本输出 `count` 与去重后的 `cases`，供人工删减低价值组合。只有产品真实支持多语言或地区格式时才加入 locales。
