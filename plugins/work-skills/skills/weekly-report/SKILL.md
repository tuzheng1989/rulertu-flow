# Weekly Report · 个人工作周报生成

把一周散落在多个 AI 会话工具和 Git 仓库里的工作记录，合并成一份**说人话**的周报：以目标和成果为主线，细节只留能说明工作量的指标。

## 数据源（四源合并去重）

**前三源已脚本化**：`scripts/collect.py` 一次采集 Claude Code + Codex + Git，输出结构化 JSON：

```bash
python {baseDir}/scripts/collect.py                 # 默认周窗口（上周一12:00~本周一12:00），仓库根 D:/runspace
python {baseDir}/scripts/collect.py --days 7        # 最近 7 天自然日窗口
python {baseDir}/scripts/collect.py --repos D:/work -o data.json   # 指定仓库根、写文件
```

| 来源 | 脚本内采集 | 说明 |
|---|---|---|
| Claude Code 会话 | ✅ `~/.claude/history.jsonl` | 按项目分组，过滤琐碎输入，内容截断 300 字 |
| Codex 会话 | ✅ `~/.codex/history.jsonl` + `session_index.jsonl` | 会话聚合 + thread_name 标题；项目归属需 Agent 判断 |
| Git 提交 | ✅ 遍历 `--repos` 目录树 | 每仓库 `git log --since/--until` |
| Hermes 会话 | ❌ Agent 用 session_search 补充 | 脚本无法访问，按 `started_at` 过滤本周窗口 |

**两阶段分工**：脚本只管"采集到什么"（原始数据 JSON），Agent 负责"这些数据意味着什么"——四源合并去重是语义判断（同一工作在多工具里操作过很常见），脚本做不了。

**周期口径**：默认上周一 12:00 → 本周一 12:00；用 `date` 命令核实当前时间，不信会话元数据。

## 生成规范（核心）

### 1. 以目标和成果为主

每条工作项回答"这周做成了什么"，不回答"过程怎么走的"：

- **成果优先**：先说达成了什么（交付了 X、修复了 Y、验证了 Z 可行），再视需要补一句背景
- **合并同项**：同一目标的多次提交/会话合并为一条（如"修了 3 个解析 bug"不是列 3 条）；相关小提交归并到一个工作项
- **工作量用指标说话**：保留能体现投入/产出的数字——提交数、测试数、会话数、覆盖文件数；删掉过程细节（调试经过、方案对比、中间版本）
- **忽略噪音**：纯配置提交（.gitignore、模型切换）、无实质内容的会话（"继续"、"/model"）、cron 触发类条目

### 2. 口语化改写（硬性）

commit message 不是周报。内部代号必须翻译成人话：

- **删代号**：实验编号（E1/D5）、票号、闸门名、里程碑代号（P6-S/W11）、章节号（§8）不出现在周报里
- **指标翻成败**："alias 0.491≥0.35，TP 178 零损失" → "关键指标全部达标，没丢正确结果"；数字本身是交付物时保留（如"150 项测试全过"）
- **通用术语可留**：MCP、DIS、GPT-SoVITS 这类行业词不用翻译；项目自造缩写必须展开
- **自检**：不看项目日志的人，能看懂这条"做了什么+结果如何"吗？不能就重写

示例：
- ❌ "E1 封闭 schema+abstain 未过淘汰门（成本 1.44x/膨胀未降双 FAIL），NO-GO 如实落档"
- ✅ "试了一种自动提取方案，实测成本反而更高、效果没提升，已确认放弃这条路线"

### 3. 结构与篇幅

```markdown
# 周报 - YYYY年M月D日 - M月D日

## 📊 本周概览
- 一两句总体节奏（重点在哪个项目、是否有里程碑）

## 🎯 主要进展
### 项目名
1. **成果导向的工作项标题**：口语化描述 + 关键指标
2. ...

## 📌 下周计划
- [ ] 计划项（从本周遗留/明确计划提取，没有就写"视进度而定"）
```

- 每项目 ≤5 项，只保留有实质工作的项目
- 不显示会话条数后缀
- 命名：`YYYY-MM-DD - 周报.md`（周期结束日）

## 输出

落盘到调用方指定目录（无指定时当前目录），并按调用渠道投递（聊天场景附文件路径）。

## 常见坑

- **会话元数据日期不可信**：时间敏感判断先跑 `date`
- **evoCenter 文档工作**：工作项标注关联的文档名（通常在会话首条输入里）
- **Codex 深挖**：轻量层不够判断时读 `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`，`session_meta.cwd` 用于归项目
- **同名项目双目录**（如 harpoon-wargame / harpoon_wargame）：合并处理
