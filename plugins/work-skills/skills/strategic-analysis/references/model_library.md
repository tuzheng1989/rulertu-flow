## 核心模型详情

### 战略规划类

#### SWOT 分析

**模型名称**：SWOT 分析

**核心定义**：通过内部优势（Strengths）/劣势（Weaknesses）、外部机会（Opportunities）/威胁（Threats），完成企业战略定位与决策分析

**适用场景**：
- 企业战略规划
- 竞品对标
- 项目可行性判断
- 市场进入决策

**必填输入项**：
1. 企业核心资源 / 能力
2. 企业核心短板
3. 外部市场核心机会
4. 外部市场核心风险 / 竞争

**可选输入项**：
- 对标企业信息
- 行业政策
- 目标客群特征

**标准分析框架**：
1. 优势（S）- 劣势（W）- 机会（O）- 威胁（T）四象限拆解
2. 四大策略匹配：
   - SO 增长策略（利用优势抓住机会）
   - WO 扭转策略（弥补弱点抓住机会）
   - ST 多元化策略（利用优势应对威胁）
   - WT 防御策略（克服弱点规避威胁）
3. 策略优先级排序

**避坑提示**：
- 禁止只列点不做策略联动
- 禁止脱离企业实际泛泛而谈
- 禁止单独使用，需配合 PEST、波特五力等模型完成外部环境的信息支撑

**行业适配规则**：
- ToB 行业：侧重资源、供应链、技术能力
- ToC 行业：侧重品牌、渠道、用户运营能力

---

#### PEST 分析

**模型名称**：PEST 分析（Political, Economic, Social, Technological）

**核心定义**：从政治、经济、社会、技术四个维度分析宏观环境，判断外部环境对企业的影响

**适用场景**：
- 新市场进入分析
- 企业战略规划
- 行业发展趋势判断
- 政策风险评估

**必填输入项**：
1. 目标市场 / 行业
2. 业务所在地（国家/地区）
3. 政策法规相关信息（如有）
4. 经济周期相关信息（如有）

**可选输入项**：
- 社会文化趋势
- 技术发展动态
- 环境因素（扩展为 PESTEL）

**标准分析框架**：
1. **P - 政治（Political）**：政府政策、政治稳定性、贸易限制、税收政策、劳工法
2. **E - 经济（Economic）**：经济增长、利率、通货膨胀、汇率、失业率、消费水平
3. **S - 社会（Social）**：人口结构、生活方式、文化态度、教育水平、健康意识
4. **T - 技术（Technological）**：技术创新、研发支出、自动化程度、技术壁垒、互联网普及率

**避坑提示**：
- 禁止泛泛罗列，必须结合具体业务场景
- 需要指出哪些因素对企业影响最大

---

#### 波特五力模型

**模型名称**：波特五力模型（Porter's Five Forces）

**核心定义**：分析行业竞争格局，评估行业吸引力和竞争强度

**适用场景**：
- 行业与市场格局分析
- 新市场进入可行性判断
- 竞争战略制定
- 行业利润水平评估

**必填输入项**：
1. 目标行业
2. 主要竞争对手
3. 供应链结构
4. 替代品情况（如有）

**可选输入项**：
- 行业准入门槛
- 客户集中度
- 供应商集中度

**标准分析框架**：
1. **现有竞争者竞争强度**：竞争对手数量、市场增长率、成本结构、退出壁垒
2. **新进入者威胁**：准入门槛、规模经济、品牌优势、分销渠道、政府政策
3. **替代品威胁**：替代品性价比、用户转换成本
4. **供应商议价能力**：供应商数量、供应商集中度、替代供应源、供应商前向整合
5. **买方议价能力**：买方数量、买方集中度、产品标准化程度、买方信息获取能力、买方后向整合

**避坑提示**：
- 必须给出五力综合评分（高/中/低）
- 需要指出最关键的力量和应对策略

### 市场行业类

#### STP 模型

**模型名称**：STP 模型（Segmentation, Targeting, Positioning）

**核心定义**：市场细分、目标市场选择、市场定位，实现精准营销

**适用场景**：
- 新产品市场进入
- 品牌定位策略
- 营销策略制定
- 目标客群分析

**必填输入项**：
1. 产品 / 服务描述
2. 目标市场范围
3. 已有客户特征（如有）

**可选输入项**：
- 竞争对手定位
- 市场规模数据
- 客户需求调研

**标准分析框架**：
1. **市场细分（Segmentation）**：
   - 地理细分：地区、城市规模、气候
   - 人口细分：年龄、性别、收入、教育
   - 心理细分：生活方式、价值观、个性
   - 行为细分：使用场景、购买频率、品牌忠诚度
2. **目标市场选择（Targeting）**：
   - 细分市场评估：规模、增长率、利润潜力、竞争程度
   - 目标市场选择标准：吸引力、匹配度、可行性
3. **市场定位（Positioning）**：
   - 定位维度：产品属性、利益、使用场景、用户类别
   - 差异化优势：与竞争对手的差异化点
   - 定位陈述：清晰的定位描述

---

#### TAM/SAM/SOM 测算

**模型名称**：TAM/SAM/SOM 测算

**核心定义**：测算市场总规模、可服务市场规模、可获得市场规模，评估市场机会

**适用场景**：
- 新市场进入评估
- 创业项目融资
- 投资可行性分析
- 增长目标设定

**必填输入项**：
1. 产品 / 服务类型
2. 目标市场范围
3. 目标客群特征

**可选输入项**：
- 市场数据来源
- 历史增长率
- 行业预测数据

**标准分析框架**：
1. **TAM（Total Addressable Market）** - 总潜在市场：
   - 定义：产品理论上可以服务的最大市场
   - 测算方法：自上而下法、自下而上法、价值理论法
   - 计算公式：目标客户总数 × 平均消费金额
2. **SAM（Serviceable Available Market）** - 可服务市场：
   - 定义：在现有渠道和地域限制下可以服务的市场
   - 测算：TAM × 可服务比例
3. **SOM（Serviceable Obtainable Market）** - 可获得市场：
   - 定义：短期内可以实际获得的市场份额
   - 测算：SAM × 预期市场份额（或基于现有资源测算）

### 竞品分析类

#### 竞品对标分析

**模型名称**：竞品对标分析

**核心定义**：系统比较竞争对手，找出自身优劣势，制定竞争策略

**适用场景**：
- 竞争策略制定
- 产品差异化设计
- 定价策略制定
- 市场定位优化

**必填输入项**：
1. 自身产品 / 服务描述
2. 核心竞争对手列表
3. 竞品相关信息（功能、价格、渠道等）

**可选输入项**：
- 竞品财务数据
- 竞品用户评价
- 竞品市场份额

**标准分析框架**：
1. **竞品信息收集**：基本信息、产品功能、定价策略、渠道布局、营销策略
2. **多维度对比**：功能对比、价格对比、用户体验对比、品牌影响力对比
3. **优劣势分析**：自身优势、自身劣势、竞品优势、竞品劣势
4. **机会与威胁**：从竞品分析中提取机会和威胁
5. **应对策略**：差异化策略、防御策略、进攻策略

### 运营增长类

#### AARRR 模型

**模型名称**：AARRR 模型（Acquisition, Activation, Retention, Revenue, Referral）

**核心定义**：用户生命周期增长模型，覆盖用户获取到推荐全链路

**适用场景**：
- 用户增长策略制定
- 产品运营优化
- 漏斗分析
- 增长目标设定

**必填输入项**：
1. 产品类型
2. 当前用户数据（如有）
3. 主要获客渠道

**可选输入项**：
- 转化漏斗数据
- 留存数据
- 营收数据

**标准分析框架**：
1. **Acquisition（用户获取）**：如何让用户发现产品
   - 渠道分析：有机流量、付费广告、社交媒体、SEO、推荐等
   - 指标：流量、获客成本（CAC）
2. **Activation（用户激活）**：用户首次使用体验
   - 激活定义：首次使用核心功能
   - 指标：激活率、时间到首次行动
3. **Retention（用户留存）**：用户持续使用
   - 留存曲线：次日、7日、30日留存
   - 指标：留存率、流失率
4. **Revenue（营收）**：用户付费
   - 付费模式：订阅、单次购买、广告等
   - 指标：ARPU、LTV、付费转化率
5. **Referral（用户推荐）**：用户推荐给他人
   - 推荐机制：邀请奖励、社交分享
   - 指标：病毒系数（K因子）、推荐率

---

#### RFM 模型

**模型名称**：RFM 模型（Recency, Frequency, Monetary）

**核心定义**：基于最近消费时间、消费频率、消费金额进行用户分层和价值评估

**适用场景**：
- 客户分层管理
- 精准营销
- 客户价值评估
- 流失预警

**必填输入项**：
1. 客户交易数据
2. 业务类型（零售、SaaS、服务等）

**可选输入项**：
- 行业平均数据
- 客户生命周期数据

**标准分析框架**：
1. **R（Recency）最近一次消费时间**：
   - 评分标准：最近消费得分最高
   - 含义：客户活跃度
2. **F（Frequency）消费频率**：
   - 评分标准：消费频率高得分高
   - 含义：客户忠诚度
3. **M（Monetary）消费金额**：
   - 评分标准：消费金额大得分高
   - 含义：客户价值
4. **客户分层**：
   - R-F-M 综合评分
   - 典型分层：重要价值客户、重要发展客户、重要保持客户、重要挽留客户、一般价值客户、一般发展客户、一般保持客户、一般挽留客户
5. **分层策略**：针对不同客户群制定差异化策略

### 财务投资类

#### 盈亏平衡分析

**模型名称**：盈亏平衡分析（Break-Even Analysis）

**核心定义**：测算收入等于成本时的销售量，评估项目最低生存门槛

**适用场景**：
- 创业项目可行性评估
- 新产品定价决策
- 投资回报评估
- 成本结构优化

**必填输入项**：
1. 固定成本
2. 单位变动成本
3. 单位销售价格

**可选输入项**：
- 预期销量
- 成本结构细分
- 敏感性分析参数

**标准分析框架**：
1. **成本分类**：
   - 固定成本：不随销量变化的成本（租金、人员工资、折旧等）
   - 变动成本：随销量变化的成本（原材料、运输、佣金等）
2. **盈亏平衡点计算**：
   - 公式：盈亏平衡销量 = 固定成本 / (单位售价 - 单位变动成本)
   - 公式：盈亏平衡销售额 = 固定成本 / (1 - 变动成本率)
3. **边际贡献分析**：
   - 单位边际贡献 = 单位售价 - 单位变动成本
   - 边际贡献率 = 单位边际贡献 / 单位售价
4. **安全边际分析**：
   - 安全边际 = 预期销量 - 盈亏平衡销量
   - 安全边际率 = 安全边际 / 预期销量

#### DCF 模型

**模型名称**：DCF 模型（Discounted Cash Flow）

**核心定义**：通过折现未来现金流来评估资产或项目的当前价值

**适用场景**：
- 投资项目评估
- 公司估值
- 并购评估
- 投资决策

**必填输入项**：
1. 预期未来现金流
2. 折现率（WACC 或 CAPM）

**可选输入项**：
- 终值计算方法
- 增长率假设
- 风险调整

**标准分析框架**：
1. **现金流预测**：
   - 自由现金流 = 经营现金流 - 资本支出
   - 预测期通常 5-10 年
2. **折现率确定**：
   - WACC 方法：加权平均资本成本
   - CAPM 方法：无风险利率 + Beta × 市场风险溢价
3. **现金流折现**：
   - 公式：DCF = CF1/(1+r)^1 + CF2/(1+r)^2 + ... + CFn/(1+r)^n
4. **终值计算**：
   - 永续增长法：TV = CFn × (1+g) / (r-g)
   - 退出倍数法：TV = EBITDA × 行业倍数
5. **净现值（NPV）**：
   - NPV = DCF + 终值 - 初始投资
   - NPV > 0 则项目可行

### 风险决策类

#### 风险矩阵

**模型名称**：风险矩阵（Risk Matrix）

**核心定义**：通过可能性和影响程度的二维矩阵评估风险，确定风险优先级

**适用场景**：
- 项目风险管理
- 战略风险评估
- 企业风险识别
- 风险应对策略制定

**必填输入项**：
1. 识别的风险列表
2. 风险的可能性评估
3. 风险的影响程度评估

**可选输入项**：
- 风险缓解措施
- 风险负责人
- 风险监控计划

**标准分析框架**：
1. **风险识别**：列出所有潜在风险
2. **可能性评估**：高（频繁发生）、中（偶尔发生）、低（很少发生）
3. **影响程度评估**：
   - 高：严重影响项目/企业目标
   - 中：中度影响
   - 低：轻微影响
4. **风险矩阵划分**：
   - 极高风险：高可能性 × 高影响
   - 高风险：高可能性 × 中影响 / 中可能性 × 高影响
   - 中风险：高可能性 × 低影响 / 中可能性 × 中影响 / 低可能性 × 高影响
   - 低风险：其他组合
5. **应对策略**：
   - 极高风险：立即处理
   - 高风险：优先处理
   - 中风险：计划处理
   - 低风险：持续监控

---

#### 决策树

**模型名称**：决策树（Decision Tree）

**核心定义**：通过树状图展示决策路径和可能结果，辅助复杂决策

**适用场景**：
- 战略决策分析
- 投资决策
- 项目选择
- 风险情景分析

**必填输入项**：
1. 决策目标
2. 可选方案
3. 各方案可能结果

**可选输入项**：
- 各结果概率
- 各结果收益/成本
- 风险偏好

**标准分析框架**：
1. **构建决策树**：
   - 决策节点（□）：需要做决策的点
   - 机会节点（○）：不确定结果的点
   - 结果节点（◇）：最终结果
2. **概率赋值**：为每个机会分支分配概率
3. **收益计算**：为每个结果节点分配收益/成本
4. **期望值计算**：从结果节点反向计算各节点期望值
   - 公式：E = Σ(Pi × Xi)，其中 Pi 是概率，Xi 是收益
5. **最优选择**：选择期望值最高的方案

## 产品专项类

#### PMF 框架

**模型名称**：产品-市场匹配框架（Product-Market Fit）

**核心定义**：评估产品是否真正满足目标市场的核心需求。PMF 不是"产品做完了"的状态，而是"用户愿意主动使用和推荐"的状态。

**适用场景**：
- 产品战略方向验证
- 新产品上线前的评估
- 增长策略制定前的前置检查
- 商业模式验证

**必填输入项**：
1. 产品核心功能/价值主张
2. 目标用户群体
3. 用户使用数据或反馈（如有）

**可选输入项**：
- 竞品的 PMF 状态
- 用户留存数据
- NPS（净推荐值）

**标准分析框架**：
1. **核心需求验证**：
   - 目标用户的痛点是否真实存在？
   - 产品是否直接解决了这个痛点？
   - 用户愿意为此付出什么代价？
2. **匹配度评估**：
   - 用户自发性使用频率
   - 用户自发性推荐意愿（NPS）
   - 用户失去产品后的反应（"失望测试"）
3. **信号判断**：
   - 未达到 PMF：需要大量推动才有用户使用
   - 接近 PMF：部分用户表现出强烈的持续使用意愿
   - 达到 PMF：用户主动使用、主动推荐，产品无法满足需求量

**避坑提示**：
- PMF 不是一个二元状态，而是一个光谱
- 不要把"用户说喜欢"等同于 PMF——看行为而非言语
- 未达到 PMF 就大力推广，是资源的巨大浪费

#### 精益画布 / 商业模式画布

**模型名称**：精益画布 / 商业模式画布（Lean Canvas / Business Model Canvas）

**核心定义**：用一页纸梳理产品/商业的全貌，快速验证商业逻辑的完整性

**适用场景**：
- 商业模式设计
- 创业项目验证
- 战略方向梳理
- 商业计划沟通

**必填输入项**：
1. 产品/服务描述
2. 目标用户
3. 核心价值主张

**可选输入项**：
- 成本结构
- 收入模式
- 竞争优势

**标准分析框架（精益画布 9 宫格）**：
1. **问题**：目标用户的 Top 3 痛点
2. **客户群体**：目标用户是谁？早期采用者是谁？
3. **独特价值主张**：一句话说清为什么选择你
4. **解决方案**：对应每个痛点的最小可行方案
5. **渠道**：如何触达用户
6. **收入来源**：怎么赚钱
7. **成本结构**：主要成本有哪些
8. **关键指标**：衡量成功的核心指标
9. **不公平优势**：对手不容易复制的东西

**标准分析框架（商业模式画布 9 宫格）**：
1. **客户细分**：为谁创造价值
2. **价值主张**：解决什么问题/满足什么需求
3. **渠道通路**：如何触达客户
4. **客户关系**：与客户建立什么类型的关系
5. **收入来源**：客户为什么付钱
6. **核心资源**：需要哪些关键资源
7. **关键业务**：必须做哪些关键活动
8. **重要合作**：需要哪些关键合作伙伴
9. **成本结构**：主要成本驱动因素

**避坑提示**：
- 画布是思考和沟通工具，不是填表游戏
- 每个格子之间的逻辑要连贯——不能"价值主张"和"客户细分"对不上
- 优先验证假设最集中的格子（通常是价值主张和收入来源）

#### Kano 模型

**模型名称**：Kano 模型

**核心定义**：将产品功能按用户满意度影响分为基本型、期望型和兴奋型，指导产品优先级和差异化策略

**适用场景**：
- 产品功能优先级排序
- 产品差异化设计
- 需求分析
- 产品路线图规划

**必填输入项**：
1. 产品功能列表
2. 目标用户群体
3. 用户需求描述

**可选输入项**：
- 竞品功能对比
- 用户调研数据

**标准分析框架**：
1. **基本型需求（Must-be）**：
   - 没有会不满意，有了也不会增加满意度
   - 策略：必须满足，但不值得投入过多资源
   - 示例：APP 的登录功能
2. **期望型需求（Performance）**：
   - 做得越好，满意度越高
   - 策略：核心差异化竞争点，值得重点投入
   - 示例：搜索速度、加载时间
3. **兴奋型需求（Attractive）**：
   - 没有不会不满意，有了会大幅提升满意度
   - 策略：创新突破口，能创造用户惊喜
   - 示例：AI 自动推荐
4. **无差异需求（Indifferent）**：
   - 有无都不影响满意度
   - 策略：不做或低优先级
5. **反向需求（Reverse）**：
   - 做了反而降低满意度
   - 策略：避免

**避坑提示**：
- 需求类型会随时间变化——昨天的兴奋型可能变成今天的基本型
- 不同用户群体对同一功能的分类可能不同
- 不要只关注兴奋型需求而忽视基本型需求

#### 产品生命周期模型

**模型名称**：产品生命周期模型（Product Lifecycle）

**核心定义**：产品从引入到衰退的完整生命周期，每个阶段需要不同的战略重点和资源配置

**适用场景**：
- 产品战略规划
- 产品线优化
- 资源分配决策
- 产品组合管理

**必填输入项**：
1. 产品描述
2. 产品当前所处阶段判断
3. 市场竞争状况

**可选输入项**：
- 历史销售数据
- 市场增长率
- 竞品动态

**标准分析框架**：
1. **引入期（Introduction）**：
   - 特征：销量低、成本高、用户少
   - 战略重点：验证 PMF、获取早期用户、快速迭代
   - 关键指标：激活率、早期留存、用户反馈
2. **成长期（Growth）**：
   - 特征：销量快速增长、竞争者进入
   - 战略重点：扩大市场份额、建立品牌、优化转化
   - 关键指标：增长率、市场份额、CAC/LTV
3. **成熟期（Maturity）**：
   - 特征：增速放缓、竞争激烈、利润压力
   - 战略重点：差异化、客户忠诚度、运营效率
   - 关键指标：留存率、ARPU、NPS
4. **衰退期（Decline）**：
   - 特征：销量持续下降、用户流失
   - 战略重点：收割还是转型、资源重新分配
   - 关键指标：流失率、维护成本、替代方案评估

**避坑提示**：
- 不要假设所有产品都会走完完整周期——有些产品在引入期就失败了
- 好的战略可以延长成长期和成熟期
- 衰退期不一定要退出——可以找到第二曲线

## 技术专项类

#### Gartner 技术成熟度曲线

**模型名称**：Gartner 技术成熟度曲线（Hype Cycle）

**核心定义**：评估技术所处的发展阶段，判断技术是处于过度期望期还是真正可用期，避免追热点或错过时机

**适用场景**：
- 技术路线选型
- 技术投资时机判断
- 新技术评估
- 技术战略规划

**必填输入项**：
1. 候选技术/技术方向
2. 业务场景和需求
3. 技术采用时间计划

**可选输入项**：
- 行业采用情况
- 技术社区活跃度
- 供应商成熟度

**标准分析框架**：
1. **技术触发期（Innovation Trigger）**：
   - 技术刚出现，概念验证阶段
   - 判断：关注但不投入大量资源，做技术储备
2. **期望膨胀期（Peak of Inflated Expectations）**：
   - 媒体炒作高峰，过度承诺
   - 判断：警惕跟风，区分炒作和真实价值
3. **泡沫破裂低谷期（Trough of Disillusionment）**：
   - 期望落空，关注度下降，但技术在沉淀
   - 判断：最佳投入时机——技术开始成熟但竞争者少
4. **稳步爬升期（Slope of Enlightenment）**：
   - 技术找到真正适合的场景，实用化进展
   - 判断：适合早期采用者进入
5. **生产成熟期（Plateau of Productivity）**：
   - 技术广泛采用，最佳实践成熟
   - 判断：主流采用，但先发优势已减弱

**避坑提示**：
- 不同技术的爬升速度差异巨大——有些技术可能长期停留在低谷期
- 企业的风险偏好决定最佳进入时机——激进型企业可在低谷期进入
- 结合企业自身技术能力判断，不能只看外部成熟度

#### Build vs Buy vs Partner 框架

**模型名称**：Build vs Buy vs Partner 框架

**核心定义**：系统评估某项技术能力应该自研、采购还是合作，从战略价值、资源效率、风险三个维度做决策

**适用场景**：
- 技术路线选型
- 技术投资决策
- 平台/工具选择
- 能力建设规划

**必填输入项**：
1. 目标能力/技术需求
2. 团队现有技术能力
3. 预算和时间约束

**可选输入项**：
- 市场上可用的解决方案
- 竞品的技术选择
- 长期战略规划

**标准分析框架**：
1. **自研（Build）评估**：
   - 优势：完全可控、可定制、可积累核心竞争力
   - 劣势：周期长、成本高、维护负担
   - 适用：核心业务能力、差异化技术、长期战略资产
2. **采购（Buy）评估**：
   - 优势：快速上线、成熟稳定、供应商持续维护
   - 劣势：依赖供应商、定制受限、持续成本（订阅/许可）
   - 适用：非核心能力、标准化需求、时间紧迫
3. **合作（Partner）评估**：
   - 优势：共享风险、互补能力、更快进入市场
   - 劣势：协调成本、利益分配、合作伙伴依赖
   - 适用：互补型能力、新市场探索、资源不足时
4. **多维度对比**：
   - 战略价值：对核心竞争力的影响
   - 时间到价值：多长时间能产出业务价值
   - 总拥有成本：包括隐性的维护、迁移、学习成本
   - 风险：技术锁定、供应商可靠性、团队能力匹配

**避坑提示**：
- 不要把"技术偏好"当成战略判断——很多自研决策本质上是工程师的个人偏好
- 考虑演化路径：先 Buy 快速验证 → 再 Build 核心部分
- "非此处发明"综合症（NIH）是技术决策的常见陷阱

#### 技术债务评估框架

**模型名称**：技术债务评估框架（Technical Debt Assessment）

**核心定义**：量化技术债对业务的影响，建立偿还优先级，平衡技术债和新功能的资源分配

**适用场景**：
- 技术投资优先级决策
- 技术架构演进规划
- 研发资源分配
- 技术战略制定

**必填输入项**：
1. 已知的技术债务清单
2. 各技术债对业务的影响
3. 当前研发资源分配比例

**可选输入项**：
- 技术债的历史增长趋势
- 系统稳定性数据
- 开发效率指标

**标准分析框架**：
1. **技术债识别与分类**：
   - 架构债：系统结构层面的设计缺陷
   - 代码债：代码质量、重复、缺乏测试
   - 依赖债：过时的库、框架、第三方依赖
   - 知识债：文档缺失、知识集中在少数人
   - 流程债：缺乏自动化、CI/CD 不完善
2. **影响评估（四维）**：
   - 业务影响：是否影响用户体验、收入、可用性
   - 开发效率：是否拖慢新功能开发速度
   - 团队士气：是否影响团队信心和招聘
   - 安全风险：是否存在安全隐患
3. **优先级矩阵**：
   - 高影响 + 高成本：分阶段偿还，优先级最高
   - 高影响 + 低成本：立即偿还（Quick Win）
   - 低影响 + 高成本：延后处理
   - 低影响 + 低成本：有空时处理
4. **资源分配建议**：
   - 健康比例：20%-30% 的研发资源用于偿还技术债
   - 紧急情况：短期内可提升到 50%
   - 长期策略：将技术债管理融入日常开发流程

**避坑提示**：
- 技术债不是全是坏的——合理的"有意识的技术债"是快速迭代的手段
- 不要试图一次性偿还所有技术债——按业务优先级逐步处理
- 评估技术债时，以业务影响为准，不要以技术完美度为准

## 模型联动规则

### 常见模型组合

| 分析场景 | 推荐模型组合 | 逻辑链路 |
|----------|--------------|----------|
| 新市场进入分析 | PEST → TAM/SAM/SOM → 波特五力 → STP → SWOT | 宏观环境 → 市场规模 → 竞争格局 → 定位策略 → 落地决策 |
| 创业项目可行性 | SWOT → 盈亏平衡分析 → DCF → 风险矩阵 | 优劣势分析 → 财务可行性 → 投资价值 → 风险评估 |
| 竞争策略制定 | 竞品对标 → SWOT 对标 → 波特五力 | 竞品分析 → 自身定位 → 行业竞争分析 |
| 用户增长策略 | AARRR → RFM → 漏斗模型 | 增长框架 → 客户分层 → 转化优化 |
| 技术路线选型 | Gartner 技术成熟度曲线 → Build vs Buy vs Partner → SWOT | 技术成熟度判断 → 获取方式决策 → 方案对比 |
| 产品差异化 | Kano 模型 → STP → 竞品对标 | 需求分类 → 市场定位 → 竞品对比 |
| 产品路线图 | Kano 模型 → 产品生命周期 → AARRR | 需求优先级 → 阶段策略 → 增长目标 |

### 联动原则

1. **前序模型输出作为后序模型输入**
   - PEST 的政策、社会文化结论 → SWOT 的机会/威胁
   - TAM/SAM/SOM 的市场空间数据 → DCF 的现金流预测
   - Gartner 技术成熟度判断 → Build vs Buy vs Partner 的时机考量

2. **避免模型重复**
   - PEST 和 PESTEL 取其一
   - SWOT 不需要和 TOWS 重复使用

3. **按逻辑顺序调用**
   - 先宏观后微观
   - 先分析后决策
   - 先定性后定量
