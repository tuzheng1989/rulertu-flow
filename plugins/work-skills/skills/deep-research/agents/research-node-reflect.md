# Research Node: Reflection and Decision

## 任务描述

分析当前研究摘要的完整性，识别知识缺口，并决定是否需要继续深入研究。

## 输入参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `research_topic` | string | 研究主题 |
| `research_brief` | string | 研究简报（**评分维度与权重从此动态读取**） |
| `running_summary` | string | 当前累积摘要 |
| `loop_count` | number | 当前循环次数 |
| `max_loops` | number | 最大循环次数 |
| `sources_count` | number | 已收集来源数量 |

## 输出格式

```json
{
  "completeness_score": 7.5,
  "dimension_scores": {
    "<维度1，来自 research_brief>": 8,
    "<维度2，来自 research_brief>": 7,
    "<维度3，来自 research_brief>": 6,
    "<维度4，来自 research_brief>": 5,
    "<维度5，来自 research_brief>": 7,
    "<维度6，来自 research_brief>": 4
  },
  "knowledge_gaps": [
    "NIST 标准化的具体进展",
    "商业抗量子密码产品的可用性",
    "与传统密码算法的性能对比"
  ],
  "strengths": [
    "核心概念解释清晰",
    "威胁分析全面",
    "技术方案覆盖完整"
  ],
  "follow_up_query": "NIST post-quantum cryptography standardization timeline",
  "should_continue": true,
  "reasoning": "核心概念和技术原理已充分覆盖，但缺乏标准化进展和实际应用案例信息。建议继续研究以获取更全面的信息。"
}
```

> **v0.4.0 变更**：`dimension_scores` 的键不再固定为 `core_concepts` 等英文名，而是 `research_brief` 中声明的维度名（可为中文）。

## 评估维度（由 research_brief 动态驱动）

评分维度**不再硬编码为固定 6 项**，而是从 `research_brief` 的「必须覆盖的维度」清单动态读取，权重沿用 brief 声明。

**执行步骤：**
1. 解析 `research_brief`，提取维度清单与各自权重
2. 对每个维度独立打 1-10 分
3. 按权重加权计算 `completeness_score`

**通用评分标准（适用于任何维度）：**

| 分数 | 描述 |
|------|------|
| 9-10 | 优秀：该维度信息全面、深入、准确 |
| 7-8 | 良好：信息充分，稍有不足 |
| 5-6 | 及格：基本信息覆盖，有重要缺口 |
| 3-4 | 不及格：信息不足，有明显缺失 |
| 1-2 | 很差：几乎没有有用信息 |

## 决策准则

### 应该继续研究 (should_continue: true)

**条件（满足任一即继续）：**
- 完整性评分 < 7/10
- 存在明显的重要知识缺口（影响理解）
- 有未探索的关键维度（权重高的维度评分 < 6）
- 未达到最大循环次数且仍有改进空间

**优先探索的缺口：**
1. 权重高的维度（核心概念、技术原理）
2. 当前评分 < 6 的维度
3. 用户可能特别关心的方面
4. **来源覆盖缺口**：高风险事实仅单源、或某维度过度依赖单一 `source_type`——写入 `knowledge_gaps` 以驱动下一轮 query 分派到未覆盖通道（v0.5.0）

### 可以结束研究 (should_continue: false)

**条件（同时满足）：**
- 完整性评分 >= 8/10
- 主要维度（权重 > 15%）都已充分覆盖（评分 >= 7）
- 缺口内容非核心或较边缘
- 已达到或接近最大循环次数

## 知识缺口识别指南

### 常见缺口类型

| 缺口类型 | 描述 | 示例 |
|---------|------|------|
| **定义缺失** | 核心术语未定义或定义不清晰 | "未解释什么是 Shor 算法" |
| **原理不清** | 工作机制未深入解释 | "未说明量子计算如何破解 RSA" |
| **案例缺失** | 缺乏具体应用案例 | "未提及实际部署的抗量子系统" |
| **数据缺失** | 缺乏量化数据或统计 | "未提供性能对比数据" |
| **进展缺失** | 缺乏最新发展信息 | "未提及 2024 年的最新研究" |
| **对比缺失** | 缺乏与其他方案的对比 | "未比较不同抗量子算法的优劣势" |
| **来源覆盖缺失** | 某关键维度过度依赖单一 source_type，或高风险事实仅单源未交叉验证 | "性能数据仅社区来源，缺官方/学术交叉" |

## 决策逻辑流程

```
开始
  │
  ▼
计算各维度评分
  │
  ▼
计算加权完整性得分
  │
  ▼
完整性评分 >= 8?
  │
  ├─ 是 ─→ 主要维度评分 >= 7?
  │         │
  │         ├─ 是 ─→ should_continue = false
  │         │
  │         └─ 否 ─→ should_continue = true
  │
  └─ 否 ─→ should_continue = true
  │
  ▼
生成知识缺口列表
  │
  ▼
生成后续搜索查询
  │
  ▼
结束
```

## 注意事项

1. **评分一致性**: 使用相同的标准评估不同维度
2. **缺口具体性**: 缺口描述应该具体明确，便于后续搜索
3. **查询质量**: 后续查询应该针对缺口，能够有效填补信息空白
4. **决策依据**: reasoning 字段应该清楚说明决策理由
