# Research Node: Summary Compressor

## 任务描述

将膨胀的累积摘要（running_summary）**重写为更紧凑的结构化版本**，治理多轮研究后的摘要膨胀问题。借鉴 `open_deep_research` 的 `compress_research`，但采用**阈值触发**（非每轮压缩）以降低常规开销。

**触发方**：主控流程。当 `len(running_summary) > compress_threshold_chars`（默认 3000）时调用本节点。本节点自身不做触发判定。

## 输入参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `research_topic` | string | 研究主题 |
| `research_brief` | string | 研究简报（压缩后的分段须遵循其维度清单） |
| `running_summary` | string | 待压缩的累积摘要 |
| `compress_threshold_chars` | number | 触发阈值（默认 3000，仅供参考） |

## 输出格式

输出压缩后的 Markdown 摘要（与 summary 节点同构），直接覆盖 `running_summary`。不要输出任何解释或元信息。

## 执行逻辑

### 第 1 步：解析现有摘要

按 `research_brief` 的维度清单，将现有 `running_summary` 的内容归入各维度。

### 第 2 步：压缩重写（硬性要求）

1. **保留所有事实性信息与量化数据**（数字、名称、日期、结论）——不得丢失
2. **保留 `[n]` 引用编号**——压缩后编号与原摘要一致，不重新编号
3. **删除**：重复表述、冗余过渡句、口语化片段、同类信息的重复例证
4. **每个维度压成 3-5 句要点**，聚焦核心结论
5. **分段遵循 brief 维度**，不引入新维度，不丢弃维度

### 第 3 步：长度控制

目标长度 ≤ 原长的 **50%**。若原摘要 4000 字，压缩后应 ≤ 2000 字。

## 注意事项

1. **不丢失信息是第一优先级**：宁可压缩率低，也不丢事实。若不确定某信息是否重要，保留。
2. **不动 sources 列表**：`sources` 是独立的结构化字段（URL 去重），本节点只压缩 `running_summary` 文本，不影响来源完整性。
3. **引用编号保留**：压缩文本中的 `[n]` 必须能对应到 `sources` 列表中的来源。
4. **首轮不压缩**：主控流程保证 loop=1 不触发本节点（保基础理解）。
5. **失败兜底**：若 LLM 压缩结果反而更长或丢失明显信息，主控流程应回退使用原摘要（不强制覆盖）。
