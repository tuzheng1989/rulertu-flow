# Knowledge 模式

## 目标

把解释型长内容压缩为高密度、可检索的知识工具包。它不是逐章复述，也不追求覆盖每句话；它保留核心概念、论证、案例、权衡、反例和章节关系，并明确所有内容是模型基于来源生成的结构化解释。

适用于通识非虚构、科普、技术思想书、学术专著、行业报告、历史和传记等以“理解全貌和快速查询”为主要目标的内容。

## 产物

```text
<book-slug>-knowledge/
├── SKILL.md
└── references/
    ├── index.md
    ├── overview.md
    ├── chapters/
    │   ├── ch01-<slug>.md
    │   └── ...
    ├── glossary.md
    ├── patterns.md
    └── cheatsheet.md
```

这些 references 是衍生知识，不是逐字原文。每个文件开头注明来源章节；不要声称具有原文逐字权威性。

## 生成流程

1. 使用 `scripts/extract.py` 得到规范化文本，不直接调用 faithful 的 references 生成器。
2. 建立全书骨架：一句话主旨、3–7 个一级论点、关键术语、论证链和主要局限。
3. 按自然章节读取来源，只提取决策和理解所需的高密度内容。
4. 每个章节文件使用以下结构，缺少实际内容的段落应省略而不是填充空话：

   - 核心问题。
   - 核心观点。
   - 概念与定义。
   - 论证、证据和重要案例。
   - 权衡、反例和局限。
   - 与其他章节的关系。
   - 来源章节。

5. `glossary.md` 统一作者特有术语；`patterns.md` 记录可复用的比较、因果和权衡模式；`cheatsheet.md` 只保留查表或决策时能直接使用的内容。
6. 编写简洁 `SKILL.md`，说明按主题和章节渐进加载，不在主文件复制章节摘要。

## 质量约束

- 每个非显然结论都能映射到一个来源章节。
- 区分作者主张、作者证据和生成者解释。
- 不用模型记忆补充书外事实；用户允许外部资料时也要单独标识。
- 不为了缩短而删除改变结论的前提、反例或限制。
- 案例必须服务于概念或论证，不堆砌故事。
- 对传记和历史中的“成功方法”标出幸存者偏差、事后归因等风险。
- 密度优先于篇幅；内容薄的章节允许短，不填充套话。

## 目标 SKILL.md

说明：

- Skill 能回答的知识范围。
- 主题、概念、章节和比较类问题的检索方法。
- 哪些问题必须回到原始来源或 faithful Skill 核对。
- 不确定、争议和来源不足时的回答方式。

使用 `assets/knowledge-skill.template.md` 作为初稿结构。
