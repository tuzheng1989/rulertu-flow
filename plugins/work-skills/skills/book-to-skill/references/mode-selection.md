# 模式选择

在生成任何目标 Skill 前，先判断用户目的和内容性质。用户明确指定模式时优先服从；未指定时，对整书和各主要章节分别评估 `F`、`K`、`M` 三项分数。

## 评分

每项取 0–5 分，并记录来自目录、前中后样本和用户目标的证据。

- `F`（原文依赖度）：规则、参数、公式、定义、例外、覆盖关系或精确引用越重要，分数越高。
- `K`（知识压缩价值）：解释和故事较多、存在重复论证、用户需要快速理解和主题检索时，分数越高。
- `M`（方法迁移价值）：存在反复出现的框架、清单、输入—判断—动作流程、可迁移场景和失败边界时，分数越高。

不要只根据书名或类别打分。至少检查目录、开头、中部、结尾和一个内容密集章节；超长内容按自然章节抽样。

## 决策规则

- 某项至少为 4，且比其他项至少高 2 分：选择对应单模式。
- 两项至少为 4，或主要章节明显属于不同模式：选择有规划的 hybrid。
- 三项都高：仍先做章节分配，不默认生成三种完整产物。
- 最高分低于 3：说明内容可能不适合直接 Skill 化，提出更合适的检索、分析或专题方案。
- 评分接近且用户目标无法消歧：询问一个最能改变输出的问题。

模式名称固定为：

- `faithful`：原文保真。
- `knowledge`：知识压缩。
- `methods`：方法蒸馏。
- `hybrid`：选择性组合。

## 模式计划

在工作目录中记录模式计划；单模式可在高置信度时直接执行，hybrid 必须先向用户展示计划并取得确认。计划至少包含：

```json
{
  "schema_version": 1,
  "book_slug": "example-book",
  "selected_mode": "hybrid",
  "confidence": "high",
  "scores": {"faithful": 5, "knowledge": 2, "methods": 4},
  "components": ["faithful", "methods"],
  "excluded_components": {"knowledge": "压缩会削弱规则条件，收益不足"},
  "scopes": {
    "faithful": {"chapters": "all", "purpose": "保存完整规则"},
    "methods": {"chapters": ["1", "3"], "purpose": "提炼两个明确流程"}
  }
}
```

约束：

- `selected_mode` 不是 `hybrid` 时，`components` 只能含同名组件。
- `hybrid` 必须含 2–3 个不同组件，并为每个组件限定范围和目的。
- `excluded_components` 说明为什么没有机械生成其他模式。
- 用户确认后的计划是生成和验证的唯一依据；变更范围时重新确认。

## 常见路由

- 规则书、标准、手册、API 文档：通常为 faithful。
- 通识非虚构、技术思想书、长报告：通常为 knowledge。
- 决策、管理、投资、写作、销售、课程：存在稳定方法时通常为 methods。
- 技术教材：常见 faithful + knowledge。
- 含权威规则和明确操作流程的专业手册：常见 faithful + methods。
- 传记和历史：通常 knowledge；提炼方法前警惕幸存者偏差和事后归因。
- 小说、散文、诗歌：不默认 methods；先确认用户想做原文分析、主题检索还是叙事技巧研究。
