# Methods 模式

## 目标

只把内容中可迁移、可执行、可区分触发场景的方法论生成独立 Skills。故事、术语、案例和反例分别作为证据、共享语义或边界素材，不因“内容精彩”就独立成 Skill。

适用于决策、管理、投资、创业、产品、营销、销售、写作、学习方法、课程、访谈和高密度方法型视频。

## 产物

```text
<book-slug>-methods/
├── INDEX.md
├── GLOSSARY.md
├── distillation-report.json
└── skills/
    ├── <book-short>-<method-a>/
    │   ├── SKILL.md
    │   ├── references/evidence.md
    │   └── test-prompts.json
    └── ...
```

Pack 根目录不是可安装 Skill；`skills/` 下每个叶子目录都是独立安装单元。方法名增加短书名前缀以避免跨书冲突，并保持总长度少于 64 个字符。

## 蒸馏流程

### 1. 整体理解

先建立内容骨架：主旨、3–7 个一级论点、作者特有术语、论证链、时代局限、立场盲点、未证明假设和最强反对意见。向用户确认骨架后再提取方法。

### 2. 多视角候选提取

分别扫描：

- 框架：思维模型、决策框架、推理方法。
- 原则：清单、规则、判断断言。
- 案例：问题 → 使用方法 → 结论 → 结果。
- 反例：失败模式、机制、预警信号和所限制的方法。
- 术语：作者定义、与常识的差异及下游影响。

环境支持独立 Agent 时可并行；不支持时以干净视角串行执行。长内容按自然章节分块，每块携带全书骨架，汇总时合并同一方法并保留全部出处。

### 3. 候选验证

每个独立 Skill 候选必须全部通过：

1. **多语境证据**：来源中至少两个真正独立的章节、对象或案例支持同一方法；只有一处时降级为案例或观点。
2. **迁移能力**：能处理一个来源没有直接回答的新问题，并得到非平庸、可解释的结果。
3. **增量价值**：相比基础模型常识，提供了独特视角、明确程序、检查清单或稳定决策边界。
4. **可执行性**：能写出动作、完成标准和必要的判停条件。
5. **可区分性**：能说明与相邻方法何时分别触发。

记录通过和淘汰理由；把候选标题和淘汰数量交给用户轻确认，再生成高成本产物。

注意：多语境证据只证明这是作者的稳定方法，不等于外部真实性验证。高风险领域需要额外来源时，必须单独声明并征得用户同意。

### 4. 构造方法 Skill

每个方法使用：

- `R`：短原文证据和来源位置。
- `I`：用自己的话解释方法机制。
- `A1`：来源中的实际案例。
- `A2`：未来触发场景、语言信号和兄弟 Skill 区分。
- `E`：可执行步骤、完成标准和判停条件。
- `B`：不适用场景、失败模式、作者盲点和邻近方法边界。

frontmatter 只允许 `name` 和 `description`；来源、标签和关系放正文或 `references/evidence.md`。使用 `assets/method-skill.template.md`。

### 5. 建立关系

只建立真实关系：

- `depends-on`：A 的前提是 B。
- `contrasts-with`：A、B 是不同选择。
- `composes-with`：A、B 常组合使用。

回填每个 Skill 的相邻方法区分，生成 `INDEX.md` 和 `GLOSSARY.md`。宁可关系稀疏，也不要硬造图。

### 6. 压力测试

每个 Skill 至少准备：

- 3 条 `should_trigger`。
- 2 条 `should_not_trigger`。
- 1 条 `edge_case`。
- 至少 1 条诱饵应当触发同包另一个 Skill。

使用 `assets/method-tests.template.json` 生成测试初稿。

盲测时只给测试者 Skill 内容、用户问题和可选兄弟 Skill 列表，不泄露预期。诱饵容错为 0；总通过率低于 80% 时重做 A2、E、B，而不是只润色 description。未通过的 Skill 不进入交付清单。

## 禁止

- 把一句金句、单个故事或普通常识强行做成 Skill。
- 把同一方法在一个案例中的换种表述当作两处证据。
- 用同一模型的自我评价冒充客观真实性验证。
- 为追求 Skill 数量降低筛选标准。
