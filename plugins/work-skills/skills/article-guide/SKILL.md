# 文章互动导读

让用户用短轮次理解文章，并能沿兴趣深入。以原文为学习主线，根据文章类型与用户反馈调整讲法。

## 1. 取得文章并选择起点

接受链接、本地文件或粘贴的正文。优先用当前环境可用的读取工具；需要转换时，使用可用的网页或文档转换能力。本技能不依赖特定 MCP、转换技能或搜索服务。

- 缺少文章时，请用户提供链接、文件或正文；在拿到内容前不生成针对该文章的知识地图。
- 记录标题、作者（若有）、来源和实际读取范围。只有摘要、摘录、截断正文或 OCR 不确定内容时，明确范围，并以可读取部分开展导读；不把缺失内容补写成原文结论。
- 检查当前对话及用户指定的学习笔记。用户要求续学时，先读取 [笔记与续学约定](references/learning-notes.md)，查找匹配笔记并恢复位置，再决定下一步，避免重复入口问答；来源不匹配或文章有更新时先核对。

首次学习，用同一轮选项题了解背景和目标。沿用用户已经明确表达的选择，只询问未确定项；用户可只答编号，无需写背景介绍：

> **熟悉程度**：A. 刚接触，需要解释术语；B. 了解一些，重点补机制与联系；C. 比较熟悉，重点看新意、证据和边界。
>
> **学习目标**：1. 抓住主旨，能复述要点；2. 深入理解，能解释为什么；3. 实际应用，能判断何时、如何使用。
>
> 例如回复“A2”。也可以说“直接开始”，按 A2 起步，随时调整。

若有选项式提问工具，可将两项各设为一题；否则直接显示选项。用户跳过时使用默认，不反复要求填写。等待选择期间可以读取文章、梳理结构，不替用户选择。

## 2. 给知识地图和推荐路线

阅读可用正文的结构与主张，识别关键知识及其依赖关系。初次输出尽量一屏内读完：

- 一两句说明文章试图解决的问题，以及学完能解释或处理什么。
- 用简短列表或小图呈现核心知识点，通常 4–7 项；短文可更少。说明必要的前置关系，每项带简短原文定位。
- 给出适合当前目标的推荐顺序。按理解依赖组织，必要时调整原文顺序；说明未纳入主线的次要内容，可按需补读。

地图标注已检查的范围；长文分段读取时，将未读章节标为待检查。用户要求全文覆盖时，持续核对章节覆盖，不能把挑选的重点当作全文覆盖。

用户已选择或跳过入口题后，地图后可以直接开始推荐的第一个知识点；用户只要地图或指定了节点时，按其要求执行。每轮围绕一个知识点，讲完留出追问空间。

## 3. 分块讲解和讨论

每块以一个具体问题或情境切入，用适合用户背景的语言解释概念、机制或论证，再用具体例子连接抽象知识。根据内容选择所需结构，不必每块套同一模板。

- 技术文章、论文、教程：重点讲解决什么问题、如何运作、关键条件、代价；数值推演或小代码有助于理解时再使用。
- 观点、商业、历史等文章：区分主张、证据、推理与价值判断；说明替代解释和适用范围。
- 先给最低必要的背景，再解释新概念。类比说明对应关系及失效之处；虚构例子明确为假设，真实案例附可核查出处。
- 原文观点用章节、页码、段落锚点或短引文定位。采用实际存在的定位；无页码时用小节标题或短语，不编造编号。
- 明确区分“作者的观点”“为理解而补充的解释/推演”“外部资料”；作者观点中的不确定性、限制条件随解释保留。

用户可用自然语言控制路线，不要求记住命令。常见意图如下：

| 用户意图 | 下一步 |
| --- | --- |
| 继续 / 换下一个 | 进入推荐路线的下一项 |
| 没懂 / 再简单点 | 缩小到卡住的一步，换例子或补前置知识 |
| 举例 / 演示 | 给具体过程，解释例子与概念的对应关系 |
| 深入 / 为什么 | 补机制、推导、假设或证据，保持当前问题边界 |
| 跳过 / 我熟悉这个 | 标记跳过并继续，可随后返回 |
| 搜索 / 对比 / 有其他观点吗 | 进入按需延展 |
| 回主线 / 看进度 | 显示当前位置并回到保存的节点 |
| 暂停 / 总结 / 下次继续 | 更新笔记和断点，交付笔记位置 |

允许用户自由讨论和质疑；依据原文与证据回答。讨论深入时先解决当前问题，不自动推进。轮尾可给少量适合当前内容的下一步选项，避免反复展示整张菜单。

关键点可提供一个可跳过的小挑战，例如判断反例、预测变化或用自己的话解释。用户愿意回答时，指出具体正确之处与缺口；需要时直接补充解释。用户跳过或想继续就按其意愿推进。只根据可观察的回答记录理解情况，“讲过”或“我懂了”不足以证明掌握。

## 4. 按需搜索延展

以下情况触发搜索：用户要求找案例、查资料、比较其他观点；理解受前置知识阻碍而需要外部资料；关键事实、真实案例或时效信息需要核实。可用已有解释解决的问题不必每轮搜索。

1. 明确这次要解决的一个问题，并保留当前主线节点和待解疑问。
2. 使用当前可用的搜索、阅读能力，优先官方文档、原始论文、原始数据等一手来源。阅读支撑结论的相关内容；只有摘要或搜索片段时说明限制。
3. 回答该问题，附实际使用的来源链接，说明与原文的关系。资料冲突时交代条件、时间或证据差异；无法判断时保留不确定性。
4. 简短提示回到哪个主线节点，允许用户继续延展。关联话题先记录为候选，由用户选择后再展开。

搜索不可用或未找到可靠资料时，说明未能核实的部分，继续基于原文或明确标注的推理讲解。不得将未搜索的内容写成检索结果，也不编造出处。

## 5. 自动保存与续学

首次创建或恢复笔记时，读取 [references/learning-notes.md](references/learning-notes.md)。默认在当前工作区的 `learning-notes/<文章短名>/notes.md` 保存一份持续更新的 Markdown；用户指定位置优先。首次保存后告知位置。

在知识点讲解、重要讨论或延展后更新相关内容；暂停、总结或结束时立即保存当前位置。保留用户补写的内容。用户要求不落盘时以其要求为准；没有可写工作区或写入失败时，交付可复制笔记并说明尚未保存。

结束时简短整理核心知识、未解决问题、值得继续探索的方向，并链接笔记。学习进度与理解证据分开记录；路线未结束时给出精确续学位置。已覆盖推荐路线不等于全文已覆盖或用户已掌握。
