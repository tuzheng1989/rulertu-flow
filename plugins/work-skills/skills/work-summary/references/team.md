# 团队融合

1. 每次取得用户指定的成员总结目录，仅处理 Markdown（`.md`、`.markdown`）和纯文本（`.txt`）。运行 `workspace.py discover <目录>` 列出候选和读取错误；同时发现工作区同周期个人总结。优先复用经核对的工作区同周期个人总结；团队目录用于补充和核对，不以文件数量推断成员覆盖。
2. 确定预期成员和团队周期。逐文件核对身份、起止、时区、来源和主题；元数据缺失时读取正文和证据判断。身份无法识别、周期不匹配、来源冲突、不可读文件和缺失成员均列入缺口，请用户补充或澄清。若成员资料缺失且用户授权或资料可用，按个人模式采集其记录；否则注明缺口，不推测身份或归属。避免将自己的会话或所有 Git 作者的提交当成其他成员的记录。
3. 读取 [分尺度融合](multiscale.md)，依照其中的时间、信息覆盖和证据规则处理各成员资料。按项目和目标对齐共同事项，以事件、交付物和证据识别重复，团队成果计一次；对有证据的个人贡献保留归属。成员对同一事项的不同说法或指标冲突时保留来源与冲突，不做无依据的合并。各成员数字只有符合可加规则才汇总。
4. 成稿说明成员范围、周期、来源、无法处理的文件与覆盖缺口；按目标呈现团队成果、个人贡献（有依据时）、状态、验证边界和后续事项。使用团队模式元数据及独立文件名。
