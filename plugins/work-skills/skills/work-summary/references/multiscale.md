# 分尺度融合

目标是在有限上下文中覆盖整个周期，同时保留足以回查的证据，而不是反复压缩成无法验证的短摘要。

1. 确定总窗口、时区、读者、所需详略和上下文预算。为指令、最终输出和回查留出空间；按实际模型可用容量控制每批输入，不假设固定 token 数。先列出所有子窗口和来源清单，记录缺失项。
2. 将长周期切成不重叠的日或周窗口；月度可由周或日汇总，季度由月汇总，半年和年度由月或季度汇总。子窗口严格覆盖总窗口，跨月周按边界切开；资料稀少时可合并，过大时继续细分。对每个窗口单独采集到文件，分批读取，避免将整年 JSON 输出到对话。已有下级总结可作索引，但确认其时间、来源和覆盖，并对关键结论回查原始证据；缺失部分直接采集或标为缺口。
3. 每批生成可持久化的中间记录，包含：窗口和覆盖来源、项目/目标、成果及其发生时间、状态、关键指标及其口径、证据定位（来源路径或会话 ID、提交 hash、时间）、未决事项、缺失与冲突。保留反例、失败及状态变化；摘要抽样只提供候选，关键事项回查原文。记录应足够紧凑，但不得丢掉溯源信息。
4. 按项目和目标融合相邻子窗口：识别同一事项的持续推进与状态变化，保留首次/最终状态和关键里程碑；跨源证据去重。只合计可相加、时间范围不重叠且口径一致的指标；无法证明时分别列出或不合计。重大、异常、失败和低频事件不因出现次数少而丢弃。
5. 每层只加载本层中间记录，先按项目分批融合，再生成上层记录；若仍超预算，继续分批并保留索引。最终综合跨项目趋势、成果及问题，并抽查重要结论回到来源。对覆盖不完整、时间归属不明或来源矛盾的内容显式限定结论，必要时请求补充材料。

中间文件仅供本任务使用，放在用户指定位置或工作区内临时目录；涉及个人会话时避免不必要的持久化和分享。输出中注明实际覆盖范围、主要数据源与影响结论的缺口。
