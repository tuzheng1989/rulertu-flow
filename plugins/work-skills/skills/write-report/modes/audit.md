# 报告审计（Report Audit）

把一份报告里"每一条引用是否真实、是否可访问、著录是否准确、文中论断与原文是否相符"这四件事查清楚，产出一份分级审计报告。审计只下结论与给修正建议，**不自动改报告**——是否落地由用户确认后再做（避免误改、保留可审轨迹）。

## 适用模式

按顺序判断：

1. **标准全量审计**：给定 `report.md` 路径 → 盘点全部引用项 → 分组并行核验 → 出分级审计报告。默认输入为 `workspace/reports/`（deep-research 产物根目录）下最新的 `report_dir/report.md`。
2. **定向核验**：用户指定某条/某几条引用或某个可疑论断 → 深度核验 → 出单条结论。
3. **两者都缺**：回退，提示用户指定报告路径或核验目标。

## 边界

**做：**
- 核验每条引用实体是否真实存在（论文 / 标准 / 模型 / 数据集 / 网址 / 白皮书）
- 核验参考文献是否有真实可访问的信息源（DOI / arXiv / 期刊页 / 官网 / 国家标准网）
- 核验著录准确性（作者全名与首字母、标题、年份、期刊/会议、卷期页码）
- 核验文中论断与所引原文是否相符（防张冠李戴、防时间矛盾）

**不做：**
- 不修改被审计报告（只出结论与建议；修正需用户明确说"应用修正"后再做）
- 不做文风润色、章节结构重组
- 不做事实主张的取证回溯（那是 deep-research 的职责）
- 不做代码级审查（那是 verify / code-review 的职责）

## 审计方法

### 输入
- `report.md` 路径（默认 `workspace/reports/{YYYY-MM-DD}-{topic}-{hex4}/report.md`，deep-research 产物根目录）
- 可选：用户指定的单条/若干条定向核验目标

### 核验四维

| 维度 | 检查内容 | 判定等级 |
|---|---|---|
| 真实性 | 引用实体是否真实存在 | ✅真实 / ❓查不到 / ❌疑似虚构 |
| 可访问性 | 是否有可访问 DOI/arXiv/官网/标准网 | ✅可访问 / ⚠️需重定向或协议小误 / ❌无法访问 |
| 著录准确性 | 作者、标题、年份、出处、卷期页码 | ✅准确 / ⚠️有细节误 / ❌严重错误（标题或出处全错） |
| 论断对应 | 文中对它的论断是否与原文相符 | ✅相符 / ⚠️部分相符或过度引申 / ❌张冠李戴 |

### 流程

1. **盘点**：通读全文，列出**全部**引用项，分四类登记：
   - 正文内引（作者+年份）
   - 参考文献表条目
   - Web / 标准资源 URL
   - 具名实体（模型名、数据集、标准号、白皮书等，即便只在正文提及也要核验真实性）
2. **分组**：按主题/类型分批，每批 5-10 条，便于并行。典型分批：经典理论文献 / 方法论文献 / 应用实证文献 / 模型与数据集 / 国家与国际标准 / 中文文献与白皮书 / Web 资源 URL。
3. **并行核验**：每批派一个子代理（`model: sonnet`）联网核验，要求：
   - 用 web_search 与 webReader **实际联网**，禁止凭记忆作答
   - 对每条给出四维判定 + 权威证据链接（DOI / arXiv / DBLP / 期刊页 / 国家标准网 openstd.samr.gov.cn / 作者主页等）
   - 核对作者全名与首字母、标题全文、年份、出处、卷期页码；给出正确值
   - 评估文中论断是否与原文相符
4. **主审复核**：对最关键的负向结论（尤其"张冠李戴""虚构框架/术语""量化数据无源""时间矛盾"），主审**独立联网复核一遍**再定稿——这类结论影响大，子代理单判不足以采信。
5. **分级**：把所有发现按严重度归入 P0-P3，给出逐条修正建议。

### 分级标准

| 级别 | 含义 | 典型 |
|---|---|---|
| 🔴 P0 | 内容硬伤，必须改 | 虚构框架/术语名；论断与出处存在时间矛盾（如把后出的工具归于早前的论文） |
| 🟠 P1 | 严重错误，强烈建议改 | 论断张冠李戴（挂到无法支撑它的真实文献）；著录信息严重错误（标题/期刊/卷期全错） |
| 🟡 P2 | 著录小误，建议改 | 作者首字母错；标题截断；预印本/正式发表年份混淆；页码缺失 |
| 🟢 P3 | 措辞/链接，可选改 | 媒体措辞（"首个"等）；URL 协议或路径小误；标准草案/正式状态标注 |

### 输出格式

输出一份审计报告，包含：
- **总体结论**：有无虚构引用、关键证据是否可靠、整体可信度评级。
- **逐条判定表**：每条引用的四维判定 + 证据链接 + 正确值（如有误）。
- **分级修正清单**：按 P0→P3 列出修正建议，每条可对应到报告具体位置。
- **确认可靠的关键引用**：重点列明报告"承重"引用（核心数据、关键理论框架）经核实属实，给用户信心。
- **结尾问询**：是否应用修正。**不自动改动 report.md。**

## 子代理约定

- 一律加 `model: sonnet`（用户此前明确的偏好约定：既绕网关 529，也是子代理常态默认）。
- 子代理必须用 web_search + webReader 实际联网，**禁止凭记忆作答**——这是审计可信度的底线。
- 子代理返回结构化判定（中文条目清单：判定 / 证据链接 / 细节核对 / 论断是否相符 / 备注）。
- 若要求 JSON 输出：提示词里明确"字符串内引用用中文引号「」或转义，输出后用 json.loads 校验"（子代理 JSON 转义高频翻车点）。
- 分组并行：多个 Agent 调用放在同一条消息里并发；每组提示词内嵌该批次的精确引用原文，避免子代理误读。

## 质量门槛

- 每条引用必须有明确判定，不得漏判（含正文仅具名、未进参考文献表的实体）。
- 所有负向结论（⚠️/❌/❓）必须附权威证据链接，否则降级为"存疑"而非"确诊"。
- "张冠李戴""虚构""量化数据无源"三类结论必须经主审独立联网复核。
- 区分"真实但有细节误"与"疑似虚构"——真实文献的著录小误很常见，不得夸大为虚构。

## 常见失败（LLM 引用幻觉模式，重点排查）

报告审计的核心价值在于识别下列高频幻觉模式，子代理提示词与主审复核都要盯：

- **虚构框架/术语名**：把不存在的框架名（如本次实战中的"LMS Lagrangian Multi-Structure"）安到真实综述上。独立检索查无该名称即可定性。
- **作者首字母系统性错**：`et al.` 简写文献的第一作者首字母高频出错（如 Elizarov M.→A.、Wang C.→H.、Krause S.→F.）。务必查全名。
- **标题缩写漂移**：截断标题导致主题偏离（如丢掉"... for Spatio-Temporal Data"后误判主题）。
- **年份错位**：预印本年 vs 正式发表年（如 arXiv 2008 / 期刊 2010）。
- **出处张冠李戴**：期刊或会议名错误，常表现为把论文挂到一个创刊时间对不上的期刊（如把 2004 年论文挂到 2006 年才创刊的 *Applied Ontology*）。
- **论断错挂真实文献**：论断安到无法支撑它的真实文献。最硬的判据是**时间矛盾**——如把 2018 年才开源的 H3 归于 2012 年的论文。
- **量化数据无源**：报告核心数字（精度提升、耗时下降百分比等）在所引原文中找不到支撑。
- **标准草案/正式混淆**：把已正式发布的国家标准误标为"草案"，或反之。
- **URL 协议/路径小误**：HTTPS 超时但 HTTP 可用（如 LinkedGeoData）；单复数路径差异。
