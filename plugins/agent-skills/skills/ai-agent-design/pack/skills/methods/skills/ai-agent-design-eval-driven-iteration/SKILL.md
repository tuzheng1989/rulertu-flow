# 评估驱动迭代 · 没有评估就没有进步

## I · 这是什么
核心方法论：**观察 → 假设 → 实验 → 验证 → 新认识 → 新假设**，使 Agent 工程从经验驱动的「炼金术」转向数据驱动的科学工程。立场：没有评估就没有进步——评估让迭代方向不依赖直觉。

## E · 闭环
评估环境（自动化测试基础设施）→ 评估数据集（定义测试用例，经得起泄漏考验）→ 自动化评估方法（LLM-as-a-Judge 与 Rubric 打分）→ Benchmark 分析（揭示改进方向）→ 系统改进 → 更新环境与数据集 → 新一轮迭代。

## A2 · 何时用
- 判断一次改动是真变好还是运气 → 看统计显著性。
- 模型 / 提示词 / 工具选型决策。
- 建立生产级持续验证（不是偶尔考试）。
- 区分：单次完成判定用 proposer-reviewer；本方法是系统级、批量、可复现的度量。

## 关键实现要点
- **评估环境**：工具调用型 / 人机交互型两种范式 + 仿真环境。
- **数据集**：防泄漏设计。
- **LLM-as-a-Judge + Rubric**：自动化评判，定义清晰评分量规。
- **统计显著性**：判断改动可信度的地基。
- **可观测性 + 生产级评估基础设施**：从外部评估延伸到内部持续评估。

## R · 证据
- 引言：评估是科学方法论的地基；要赶在名词流行前掌握原则，必须建立评估机制。
- ch6 整章：评估闭环；评估是 Harness「验证」功能的系统化实现。
- ch7：评估环境 / 数据集是后训练的重要输入，仿真环境是练习场。

## A1 · 书中案例
- ch6 / 06.01 一个具体的评估示例 → 自动评估环境 → 数据集 → 指标 → LLM-as-a-Judge → 选型 → 显著性 → 可观测性 → Benchmark 到改进 → 生产级基础设施 → 仿真环境，形成完整链路。

## B · 不适用与边界
- 评估本身需防泄漏，否则结论不可信。
- LLM-as-a-Judge 有评判偏差，需校准。
- 兄弟 skill：单任务完成判定用 proposer-reviewer；本方法度量系统整体。
