# ReAct 循环 · Agent 的核心推进机制

## I · 这是什么
ReAct = Reasoning + Acting。Agent 通过「思考→行动→观察」迭代推进任务：每轮模型先思考下一步、调用工具行动、观察工具返回，再把结果追加到轨迹进入下一轮。本质是**通过不断追加轨迹让模型持续推进任务**。

## A2 · 何时用
- 构建 Agent 主循环。
- 模型需自主决定下一步、调用工具、基于结果继续。
- 区分：固定流程无自主决策 → 工作流；单次问答无工具 → 直接 LLM 调用。

## E · 如何实现
1. 维护消息列表（轨迹）= 系统提示词 + 工具定义 + 对话历史。
2. 循环：① 调 LLM（带工具定义）；② 返回工具调用 → 执行工具，结果作为 observation 追加轨迹，回①；③ 返回最终回答（无工具调用）→ 结束。
3. 完成标准：模型返回无工具调用的最终答案，或触发判停。
4. 判停（必须）：最大迭代次数上限——防止死循环。

## B · 不适用与边界
- 任务完全确定 → 工作流更安全。
- 需实时流式 → ReAct 按轮次，非实时（后记「两朵乌云」之一）。
- 失败模式：死循环 / 过早放弃 / 假成功 → 需验证器（见 `ai-agent-design-proposer-reviewer`）。
- 兄弟 skill：本循环解决「如何推进」；完成判定用 proposer-reviewer；工具设计用 tool-design。
