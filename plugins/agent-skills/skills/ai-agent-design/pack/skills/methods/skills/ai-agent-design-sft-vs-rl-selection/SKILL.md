# SFT vs RL 选型 · 把交互策略写入参数

## I · 这是什么
模型后训练的本质是把交互策略写入参数。**SFT 与 RL 是先后关系，不是竞争关系**：SFT 先把输出格式稳定下来（否则 RL 奖励信号无法计算），RL 再在此基础上学会泛化。「SFT 记忆、RL 泛化」是可测量的现象。

## 两条比算法更重要的判断
1. **数据和环境比算法更重要**：现成 RL 算法会用就行，差距在仿真环境保真度与训练数据质量；很多场景 SFT 数据质量到位，甚至不需要 RL。
2. **当前 RL 的主要瓶颈是样本效率**。

## E · 选型决策
- 输出格式不稳 / 要「记住」特定行为 → **SFT**。
- 要泛化 / 探索最优策略 → **RL**（且 SFT 先行稳定格式）。
- 默认：先把 SFT 数据质量做到位，再评估是否需要 RL。

## 奖励信号设计
二元奖励 → 过程奖励 PRM（逐步验证）→「奖励结果、约束过程」的验证路径惩罚 **RLVP**（奖励结果、惩罚路径，用可达进展的部分奖励救回全败组）。样本效率方向：**On-Policy Distillation**（让每步信号更密集）。共同点：把环境 / 数据里本被纯结果奖励浪费的信息，变成可学习信号。

## A2 · 何时用
- 要把 Agent 交互策略写入模型。
- 奖励信号设计 / 信用分配。
- 多轮 Agent RL。
- 区分：不改权重的进化 → ch8 外部化学习，非本方法。

## B · 不适用与边界
- 算法选择不是关键，别过度纠结算法；环境与数据才是。
- 高风险领域需额外外部来源验证（多语境证据只证明是作者稳定方法，非外部真实性）。
- 兄弟 skill：评估训练效果用 eval-driven-iteration（评估是训练前提）。
