# 工具设计 · 决定能力上限与可靠性

## I · 这是什么
**工具设计决定 Agent 能力上限，异步架构决定能否在真实世界可靠运行。** 工具是 Agent 的手脚。贯穿一切工具的底线：**参数传递保真性**——模型感知的世界与工具操作的世界之间不能有系统性偏差。

## E · 五类工具设计要点
| 类别 | 关键设计 |
|---|---|
| **感知工具** | 粒度权衡、上下文感知智能总结、分页与显式截断；只读 → 可缓存与并行 |
| **执行工具** | 层次化安全防护、提议者-审核者（事前审批 + 事后验证）、Sidecar |
| **协作工具** | 子 Agent 生命周期原语（创建 / 消息 / 取消 / 发现）、人工介入学习闭环 |
| **事件触发工具** | 触发条件过滤、事件载荷设计，让世界主动唤醒 Agent |
| **用户沟通工具** | 异步消息模式、多渠道选择与用户召回、虚拟身份与隔离执行环境 |

## 通用原则（ACI）与生态
- **ACI**：粒度权衡、通用性设计、描述规范。
- **MCP**：统一工具互操作标准。
- 层次化组织、动态工具发现、Skills 回应「工具过多」。
- 异步：OpenClaw（Hooks / Cron / Heartbeat）→ PineClaw（Channel 机制）；取消式 / 队列式 / 并行三策略。

## A2 · 何时用
- 新建 Agent 工具集或接入第三方 MCP。
- 设计执行不可逆操作的工具。
- 让 Agent 响应外部事件（邮件 / API 回调）。
- 区分：工具完成判定安全 → proposer-reviewer；本方法解决「工具本身怎么设计」。

## A1 · 书中案例
- ch4 实验 4-1~4-3 构建感知 / 执行 / 协作三大基础工具集；4-4 邮件 Agent 事件驱动；4-5 并行 / 打断恢复；4-6 主动工具发现。

## B · 不适用与边界
- 接入第三方 MCP = 引入信任边界：**工具描述投毒、工具遮蔽、凭证管理**风险，需接入前审查 + 运行时防御。
- 异步架构与同步训练范式矛盾，现仅能用异步占位符缓解。
- 兄弟 skill：执行安全的事前事后审查细节用 proposer-reviewer。
