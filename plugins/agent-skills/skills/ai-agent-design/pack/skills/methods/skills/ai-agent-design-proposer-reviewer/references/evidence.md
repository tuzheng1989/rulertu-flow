# evidence · 提议者-审核者（proposer-reviewer）
来源：bojieli/ai-agent-book

## 核心证据
- **引言**：作者团队早于 loop engineering 概念流行，就用 proposer-reviewer（书中称提议者-审核者）解决模型过早认为任务完成的问题——既有过早放弃，也有假成功；核心是让 Agent 审阅自己的交付件并由验证而非感觉决定任务结束。
- **ch4 / 04.05 执行工具**：层次化安全防护、提议者-审核者审查（事前审批 + 事后验证）、Sidecar 机制。
- **ch5**：多媒体生成（PPT / 视频）通过 proposer-reviewer 机制实现质检。
- **ch10 / 10.05 失败模式 + Loop 工程**：循环的瓶颈在验证器；多 Agent 优势在于 Reviewer 获得外部反馈（代码执行结果、视觉渲染截图、工具验证输出）；终结偷懒式假完成、过早放弃、假成功三类过早终止。

## 多语境支持
引言 + ch4 + ch5 + ch10 = 四个独立章节 / 场景支持。这是作者反复强调的稳定方法，非孤例。

## 迁移性
适用于任何需要可靠完成判定的高风险 Agent 场景；关键约束：验证器必须有独立于模型自宣称的真实观测来源。
