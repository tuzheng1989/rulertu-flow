# 代码作为元能力 · 能创造工具的工具

## I · 这是什么
**代码不只是写程序的工具，它是 Agent 形式化思考和精确表达的语言。** Coding Agent + 文件系统是所有通用 Agent 最核心的基础。关键判断：Coding Agent 成熟度高，主因不是代码模型强，而是**软件工程几十年攒下的基础设施（测试 / 类型 / 版本控制）天然构成强大的 Harness**——这个结论可推广到其他 Agent 场景。

## 六大维度（代码在编程之外的价值）
| 维度 | 价值 |
|---|---|
| **思考工具** | 符号计算 + 约束求解弥补概率思考不足 |
| **业务规则约束** | 无歧义表达业务规则，在不可逆操作场景提供确定性安全防线（价值远超实现成本） |
| **多媒体生成** | 通过 proposer-reviewer 创建 PPT / 视频 |
| **系统适配器** | 自动跟随格式演化，日志解析与问题诊断全自动化 |
| **生成式 UI** | 动态创建表单 / 可视化 / 完整应用，突破纯文本限制 |
| **Agent 自举** | 用代码修复和创造同类 Agent——能创造 Agent 的 Agent |

## A2 · 何时用
- 需要确定性推理 / 精确计算（概率模型不稳）。
- 不可逆操作需确定性安全约束。
- 现有工具不够，需现场创造新工具。
- 区分：用现有工具 → tool-design；本方法是「用代码创造工具 / 形式化思考」。

## E · 如何实现
1. 识别任务中需要确定性 / 精确性 / 可验证性的子问题。
2. 让 Agent 生成代码解决，借助软件工程 Harness（测试 / 类型 / 沙箱执行）验证。
3. 代码既可一次性执行，也可沉淀为可复用工具（→ 工具创造）。
4. 完成标准：代码通过测试 / 类型检查 / 沙箱运行得到预期输出。
5. 判停：反复失败 → 回退到其他方案并报告。

## R · 证据
- ch5 整章：代码是思考语言；软件工程基础设施 = 天然 Harness；可靠性 = 每类故障有检测 / 恢复 / 终止路径；六大维度。
- ch8：从工具使用者到创造者（Voyager 开放世界蓝图；从头编写新工具）。

## A1 · 书中案例
- OpenClaw 架构（代码生成 + 文件系统范式）。
- Voyager：开放世界中 Agent 自主编写新工具、自我进化的完整蓝图。

## B · 不适用与边界
- 简单工具调用不必升级到写代码。
- 代码执行需沙箱隔离，避免安全风险。
- 兄弟 skill：工具的通用设计用 tool-design；本方法聚焦「代码作为元能力」。
