# 第 6 章 · Agent 的评估

> 来源：原书第 6 章。衍生解释，非逐字原文。

## 核心问题
怎么判断 Agent 真的变好了？核心立场：**没有评估就没有进步**。生产级评估不是偶尔的考试，而是嵌入每个产品决策的持续验证。

## 核心方法论
**观察 → 假设 → 实验 → 验证 → 新认识 → 新假设**，使 Agent 工程从经验驱动的「炼金术」转向数据驱动的科学工程。

## 评估闭环（完整链路，每环都影响结论可信度）
评估环境（自动化测试基础设施）→ 评估数据集（定义测试用例，经得起泄漏考验）→ 自动化评估方法（LLM-as-a-Judge 与 Rubric 打分）→ Benchmark 分析（揭示改进方向）→ 系统改进 → 更新环境与数据集 → 新一轮迭代。

## 关键概念
- **评估环境**：工具调用型 / 人机交互型两种核心范式，章末讨论仿真环境。
- **LLM-as-a-Judge**：用 LLM 担任评判者；Rubric 评分量规。
- **统计显著性**：判断改动是真变好还是运气（评估驱动选型的基础）。
- **可观测性**与**生产级评估基础设施**（从外部评估到内部评估）。
- **仿真环境**：从评估到后训练的桥梁。

## Harness 视角
本章评估方法论 = Harness 中「验证」功能的系统化实现；「从 Benchmark 到系统改进」的闭环是 Harness 迭代优化的核心机制。

## 与其他章节关系
为 ch7 后训练提供关键基础——评估环境与数据集是后训练的重要输入，仿真环境是练习场。下一章把交互策略写入模型参数。
