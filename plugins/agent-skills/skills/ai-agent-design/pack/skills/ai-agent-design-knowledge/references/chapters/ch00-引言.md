# 引言 · 为什么写这本书

> 来源：原书引言。衍生解释，非逐字原文。

## 核心问题
AI Agent 设计如何从「感觉驱动」变成「原则驱动」？架构原则能否穿越模型快速迭代？

## 核心观点
- **好的设计原则穿越模型迭代周期**：它们描述智能系统与世界交互的基本模式，而非某个模型的用法。
- **实践在前，命名在后**：Skill、Harness、Loop Engineering 都是头部公司先做出来、后才被命名。要赶在名词流行前掌握原则。
- 本书由 Pine AI 生产实践背书——处理金钱 / 长程敏感任务（替用户打电话协商账单、退款、取消订阅），几十轮交涉、真金白银风险，倒逼出 Harness 原则。
- 本书用「whisper coding」（口述式协作）方式创作，语音带宽约为打字 4 倍。

## 关键概念
- **核心公式**：Agent = LLM + 上下文 + 工具（大脑+眼睛+手脚；Policy+Observation+Action）。
- **术语约定**（务必区分）：reasoning →「思考」（思维链 / 思考模型 / 思考过程）；inference →「推理」（模型运行 / 推理时 / 推理成本）。例外复合词仍用「推理」：逻辑推理、多跳推理、空间推理、时序推理。

## 赶在名词流行前掌握原则的两个方法
1. **拥有对 Agent 能力上限有极高要求的真实业务**，持续获得真实反馈——复杂场景自然倒逼你构建 Harness。
2. **建立评估机制**——没有评估就没有进步；评估让 Agent 迭代方向不依赖直觉。

## 与其他章节关系
引言定下全书基调（公式 + Harness + 评估）。ch1 展开公式，ch6 展开评估方法论，后记回应「模型会不会吃掉 Harness」。
