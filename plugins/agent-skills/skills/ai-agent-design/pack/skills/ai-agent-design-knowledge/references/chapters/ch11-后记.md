# 后记 · 回到 Agent = LLM + 上下文 + 工具

> 来源：原书后记（含「两朵乌云」「模型与 Agent 的共同演进」）。衍生解释。

## 核心问题
全书回到开篇公式。两个总结：模型会不会吃掉 Harness？Agent 天空还有哪些乌云？

## 核心观点
十章都在公式三词内：上下文（ch2/3）= Agent 看到什么；工具（ch4/5）= Agent 能做什么；模型（ch6/7）= Agent 大脑本身（评估度量智能、后训练放大智能）。ch8/9/10 是组合应用。ch10 多 Agent 并非公式外新东西：上下文共享=ch2「隔离优于压缩」，Agent 互为工具=ch4 协作工具，新信息判据=ch6 评估。

## 两朵乌云（Agent 天空未散）
1. **流式实时交互**：真实世界不停下等 Agent 想完。两条路：① 架构快慢分离（前台快模型维持节奏，后台慢模型深度思考）；② 推理本身做快（小米 MiMo 1T 模型 >1000 token/s；Taalas 固化进芯片 ~17000 token/s、响应 <100ms，代价是只能跑被固化的模型）。
2. **从经验中持续学习**：**小世界假设**（大模型装得下所有通用知识，瓶颈是数据，训练一次即可）vs **大世界假设**（具体用户 / 公司的知识不在语料里且时时在变，只能上岗后持续学习）。结论：模型最强的能力终将是**学习与适应**，而非记住。

## 模型与 Agent 共同演进（飞轮）— 回应「模型会不会吃掉 Harness」
**会，一层一层地吃，但永远吃不完。**
- harness 兜底逻辑记录模型此刻做不稳的地方；下一代模型内化后代码可删；而模型能内化，正因为 Agent 已在真实业务替它趟坑、沉淀为训练信号 → 自我强化飞轮。
- 永远吃不完的三理由：① 训练以月计，业务等不起；② 模型无法内化所有业务约束与偏好；③ 每代模型打开新前沿，前沿处最不稳。
- Harness 不消失，只是随模型向新前沿迁移。
- 《苦涩的教训》Agent 时代读法：通用方法终将胜出，但「终将」二字里每一段路，都是 Harness 铺出来的。

## 关键证据
- 不换模型只改 harness：任务准确率 **52.8% → 66.5%**（harness 杠杆大，也说明模型还没到那步）。
- 飞轮本身是最深的护城河：真实业务 + 反馈数据 + 模型迭代咬合越紧，越难被外部追上。

## 行动含义
- **造模型者**：让真实场景反馈尽快回流训练。
- **造应用者**：harness 是短期最锋利的杠杆，但长久护城河在技术之外（独占数据、稳固渠道、用户信任、网络效应、人机协作复杂场景）；用 harness 争取时间，构筑技术外的壁垒。

## 三个不过时的问题
**看到什么、能做什么、如何验证做得对不对**——描述智能系统与世界交互的基本方式，非某个模型用法。
