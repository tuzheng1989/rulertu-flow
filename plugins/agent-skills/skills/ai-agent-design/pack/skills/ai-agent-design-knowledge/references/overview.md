# 全书骨架 · 《深入理解 AI Agent：设计原理与工程实践》

> 作者李博杰（Pine AI 首席科学家）。本文是模型基于原书生成的结构化解释，非逐字原文；逐字核对请用 `ai-agent-design-source`。

## 一句话主旨

**Agent = LLM + 上下文 + 工具**。模型正在商品化，真正的竞争力在 **Harness**——围绕上下文、工具、验证构建的工程脚手架。**好的设计原则能穿越模型迭代周期**。

## 核心公式（三个层次，同一对象）

| 层次 | 表述 |
|---|---|
| 实现层 | LLM + 上下文 + 工具 |
| 直觉层 | 大脑 + 眼睛 + 手脚 |
| 学术层（RL） | Policy + Observation Space + Action Space |

三者缺一不可；其中"眼睛"（上下文）是决定性因素。

## 全书一级论点（10 章 = 三大支柱 + 进阶）

**基础**
- **ch1 Agent 基础**：核心公式 + Harness 是竞争力 + 从工作流到自主 Agent 的编排顺序

**支柱一：上下文（眼睛）**
- **ch2 上下文工程**：上下文决定能力上限（KV Cache / 提示工程 / Skills / 状态栏 / 压缩）
- **ch3 用户记忆与知识库**：跨会话持久化（用户记忆四策略 + RAG 技术栈 + 双层记忆架构）

**支柱二：工具（手脚）**
- **ch4 工具**：工具设计决定能力上限，异步架构决定可靠性（MCP / 五类工具 / 事件驱动）
- **ch5 Coding Agent**：代码是元能力（思考语言 + 创造工具的工具，软件工程即天然 Harness）

**支柱三：模型（大脑）**
- **ch6 评估**：没有评估就没有进步（观察→假设→实验→验证 闭环）
- **ch7 后训练**：SFT 记忆、RL 泛化；数据和环境比算法更重要

**进阶**
- **ch8 自我进化**：不改权重的进化（经验学习 + 工具创造）
- **ch9 多模态与实时交互**：语音 / Computer Use / 机器人；延迟与多模态两道坎
- **ch10 多 Agent 协作**：上下文共享维度 × 拓扑维度；协作是否引入新信息

## 贯穿全书的 6 条核心判断

1. **好的设计原则穿越模型迭代周期**（引言）——原则描述智能系统与世界交互的基本模式，非某个模型用法。
2. **实践在前，命名在后**（引言）——Skill / Harness / Loop Engineering 皆先实践后命名；要赶在名词流行前掌握原则。
3. **Harness 是竞争力**（ch1）——模型商品化，差异在约束 / 验证 / 纠正机制。
4. **没有评估就没有进步**（引言 / ch6）——评估让迭代方向不依赖直觉，是科学方法论的地基。
5. **数据和环境比算法更重要**（ch7）——现成算法够用，差距在仿真保真度与数据质量。
6. **循环的瓶颈在验证器**（ch4 / ch10 / 引言）——proposer-reviewer：由扎根真实观测的验证器、而非模型自宣称，来判定任务完成；终结假成功 / 过早放弃。

## Harness 论证链（如何贯穿全书）

ch1 提出 Harness 框架 → ch2/3 Harness 的「上下文」层 → ch4/5 Harness 的「工具」层 → ch6 Harness 的「验证」层系统化（评估闭环）→ ch7 把 Harness 中积累的反馈信号写入参数（后训练）→ ch8 不改参数的进化 → ch9/10 扩展到多模态与多 Agent。后记回到核心公式。

## 三种学习范式（ch1 / ch7 / ch8 对照）

| 范式 | 机制 | 周期 |
|---|---|---|
| 后训练 Post-training | 写入模型参数 | 以周计 |
| 上下文学习 In-Context | 临时适应 | 单次会话 |
| 外部化学习 Externalized | 工具库 / 知识库 / Skills | 持续，不改权重 |

## 主要局限

- 内容截至 2026 年中，模型 / 产品迭代快（GPT-5.x、Claude 4.x），具体能力数字会过时，**原则部分稳定**。
- ch7 后训练侧重直觉，实操需补 ML 与数学基础。
- ch10 多 Agent 侧重协作模式，**非分布式系统工程**（无 CAP / 一致性 / 容错）。
- 评估指标、基准分数有时效性。
