# 第 10 章 · 多 Agent 协作

> 来源：原书第 10 章。衍生解释，非逐字原文。

## 核心问题
多个 Agent 如何分工合作？这是 AI Agent 系统的终极形态。

## 两个正交的核心设计维度
**上下文是否共享 × 协作拓扑**。

### 上下文维度
- **共享上下文（继承式）**：后续 Agent 继承前序完整上下文，信息零损耗，但上下文膨胀快。
- **不共享上下文（独立）**：通过提炼后的移交包、文件系统、消息传递交换信息。

### 拓扑维度
- **对等模式**：适合少量 Agent 的迭代改进。
- **管理者模式**：适合需要动态调度的复杂任务（规划者是系统瓶颈，应配最强模型与最精提示词）。
- **去中心化模式**：职责对等、控制权需在 Agent 间自主流转。

## 基础设施（操作系统隐喻）
**Agent 之于运行时，恰如进程之于内核**：静态前缀是程序，轨迹是内存，LLM 是分时复用的 CPU。
- **数据平面——共享文件系统**：挂载 Agent 专属工作区 / 多 Agent 共享空间 / 外部资源 / 系统内置资源四类区域的虚拟目录树；传递文件路径交换产物。
- **控制平面——通信与控制**：消息传递、状态查询、执行终止、资源调度；消息总线；跨组织边界用 A2A 协议。
- **轨迹即状态**：崩溃后加载轨迹即可恢复会话。

## 核心准则（判断多 Agent 是否优于单 Agent）
**协作过程是否引入了生成时不存在的新信息**。
- 只重新审视同一段文本（如辩论模式）→ 等量计算下单 Agent 同样有效，多 Agent 无优势。
- Reviewer 能获得**外部反馈**（代码执行结果、视觉渲染截图、工具验证输出）→ 多 Agent 优势实质性。

## Loop 工程：循环的瓶颈在验证器
要终结三类过早终止——**偷懒式假完成、过早放弃、假成功**——必须由扎根真实观测的验证器、而非模型自宣称，来判定任务完成。给更多步骤预算不自动更好，需显式**预算感知**机制。

## Agent 社会与经济（涌现）
- 斯坦福 AI 小镇（25 Agent 自发传播消息、协调聚会）、Agentopia（10 年模拟 + 生活奖励筛选轨迹）、Moltbook（150 万 Agent 涌现数字宗教与协作协议）。
- 经济维度：Vending-Bench Arena（价格战、合谋定价）、Pinchwork（市场互相雇佣）、RentAHuman（加密货币雇佣人类）。
- 暗示：基于市场机制的去中心化资源分配。

## 权衡与反例
- 共享上下文信息全但膨胀；不共享省上下文但有信息损失。
- 多 Agent 不是银弹——若无新信息引入，不如单 Agent。
