# 第 4 章 · 工具

> 来源：原书第 4 章。衍生解释，非逐字原文。

## 核心问题
Agent 如何通过工具与外部世界交互？核心结论：**工具设计决定能力上限，异步架构决定能否在真实世界可靠运行**。

## 核心观点
- **ACI 原则**（工具设计通用原则）：粒度权衡、通用性设计、描述规范。
- **MCP 协议**统一工具互操作标准；层次化组织、动态工具发现、Skills 回应「工具过多」的选择挑战。
- 接入第三方 MCP = 引入新信任边界：**工具描述投毒、工具遮蔽、凭证管理**风险，需接入前审查 + 运行时防御。
- 贯穿一切工具的底线：**参数传递保真性**——模型感知的世界与工具操作的世界之间不能有系统性偏差。

## 五类工具及设计侧重
| 类别 | 关键点 |
|---|---|
| **感知工具** | 粒度权衡、上下文感知智能总结、分页与显式截断；只读 → 天然可缓存与并行 |
| **执行工具** | 层次化安全防护、**提议者-审核者审查**（事前审批 + 事后验证）、Sidecar 机制 |
| **协作工具** | 子 Agent 生命周期原语（创建/消息/取消/发现）、人工介入学习闭环 |
| **事件触发工具** | 触发条件过滤、事件载荷设计，让世界主动唤醒 Agent |
| **用户沟通工具** | 异步消息模式、多渠道选择与用户召回、虚拟身份与隔离执行环境 |

## 异步架构
- **OpenClaw** 内置自动化：Hooks、Cron、Heartbeat（定时自主行动），但缺第三方事件即时接入。
- **PineClaw** 引入 **Channel 机制**补缺口：从时间驱动到事件驱动。
- 三种处理策略：取消式 / 队列式 / 并行，应对不同优先级。
- 深刻矛盾：异步架构 vs 当前大模型的同步训练范式；现用异步占位符缓解，根本解法有待模型在异步环境中 RL 内化（呼应 ch9 VLA）。
