# ai-agent-design-practices · 书外工程实践层

本书 pack 的**第五组件**，定位为书外工程实践层。本书公式：**Agent = LLM + 上下文 + 工具**。

本组件**不讲原理**，只提供「工程社区里有哪些现成的 agent 协调模式与做法可选用」。原理与书内方法论归 knowledge / source / methods 三组件，本组件补充三组件覆盖不到的「书外工程实践」。

## 身份与边界（硬约束）

- ⚠️ 本组件内容来自**工程社区实践**（非李博杰本书内容）。第一批五种协调模式迁移自原全局 `agent-patterns` skill。
- **只回答**：「有哪些工程模式可选」「选哪种协调结构」「工程上怎么落地」。
- **不回答**：「为何这么设计」「原理是什么」——这些归 knowledge / source / methods。
- 引用本组件内容时，必须标注「书外工程实践」，**不得**包装为本书观点或设计原理。
- 与书内 method 主题重叠时（如生成器-验证器 vs `proposer-reviewer`），method 讲原理、本组件讲工程实现，互补非重复。

## 快速模式选择

| 问题特征 | 推荐模式 |
|---|---|
| 输出质量要求高，有明确评估标准 | **生成器-验证器** |
| 任务可清晰分解，子任务有边界 | **协调器-子代理** |
| 并行工作负载，独立的长运行子任务 | **代理团队** |
| 事件驱动流程，代理生态会增长 | **消息总线** |
| 协作研究，代理共享发现 | **共享状态** |
| 需要消除单点故障 | **共享状态** |

模式总表与文件链接见 [index.md](references/index.md)。

## 够格放进本组件的规则（防杂物堆）

1. 必须是 agent 工程领域、有工程社区共识的模式 / 做法（非个人随意总结、非一次性技巧）。
2. 必须有明确可溯来源（哪篇文章 / 哪个框架 / 哪家公司实践）。
3. 不与书内 methods 重复（若重复，methods 为准，本组件顶部做交叉引用）。
4. 定位是「可复用的模式 / 做法」，不是项目清单（归 examples）、不是原理推导（归 knowledge）。
5. 引用时必须标注「书外工程实践」，不得包装为书内观点。

## 推荐起点

对于大多数用例，建议从**协调器-子代理**开始。它以最少的协调开销处理最广泛的问题。观察其遇到的困难，再随需求清晰向其他模式演进。

## 实现建议

1. 从最简单的可能模式开始，复杂性引入自己的问题。
2. 明确终止条件，避免无限循环。
3. 设计故障恢复机制：最大迭代限制、回退策略。
4. 记录协调决策，便于调试与优化。
5. 监控指标：令牌使用、响应时间、通过率。
