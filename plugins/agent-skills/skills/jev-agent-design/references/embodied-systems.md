# 具身与实时决策：从观测到安全执行

## 适用场景与证据

用于无人机、机器人、遥感或其他有时间限制、传感器与执行器的 Agent 设计。主要依据 [jev-drone 原项目 README](https://github.com/RomanSlack/jev-drone)、[驾驶仿真 README](https://github.com/kavehmz/typesafe-playground)，以及用户提供的[文章](https://mp.weixin.qq.com/s/TsvhzW15qXLcFZrc1idO8A)（2026-09-30）。前两者是仿真项目自述，未在本技能中独立运行；下文遥感流程是基于其架构的设想，不是实测案例。文章中部分场景表格是图片，本次提供的 Markdown 仅包含图片链接，未提取表内内容。

文章反映早期快照：其「官方只支持文本」和「没有公开遥感项目」不宜当作当前事实。当前题型和模态应查 [TypeSafe 文档](https://docs.typesafe.ai/introduction)及具体模型；项目只说明它实际发送了哪些数据。文章中的速度、价格与本地部署判断不能直接推广到当前产品、其他模型或目标数据。

## 分层与时间契约

先根据系统的截止时间、物理能力和实际风险设计以下分层；频率以目标系统测量为准，案例频率只用于理解职责，不是推荐配置。

1. **感知**：从相机或其他传感器提取目标、距离、障碍和状态，给每项标注坐标系、单位、时间戳、来源、质量或未知值。
2. **语义判断**：在允许的决策周期内，用 Jev 对当前状态和有限动作提原子问题；需要时同一请求并行判断动作、风险和其他独立条件。
3. **独立安全与控制**：安全约束和紧急动作由宿主与底层控制系统负责，具备覆盖或拒绝模型建议的能力；执行器完成平滑控制。模型无响应时控制层仍需按已设计的安全策略运行。
4. **反馈**：记录观察版本、动作建议、校验结论、执行和环境后果，支持回放、事故分析和场景评测。

对异步请求写明 `observed_at`、状态版本、期限及允许复用的条件；收到响应后重新验证状态、动作合法性和授权，过期或不符合条件则丢弃并进入既定退路。视控制系统的实际保证，设计超时、断网、数据缺失、时钟误差、重复响应与状态突变的处理；缓存命中不能替代新鲜度检查。以上是适配建议，不是原项目对全部失效情形的保证。

## 状态设计：判断前先做可观测性检查

将每个候选动作需要的事实逐一映射到观测来源。例如「越过障碍」至少需要能评估障碍位置/高度、有效可见性以及自身能力限制；如果顶边不可见，标记未知并走相应退路，不把缺省值当安全。原无人机项目报告：只提供水平距离时模型从不选择爬升，增加顶边高度、可见性及可爬升上限后才有依据。这说明应先定位信息缺口，再讨论模型、题型或阈值；字段丰富也可能引入错误、漂移与延迟。

## 遥感 / 低空的迁移试点（设计假设）

从低风险、可离线回放的场景切入，例如：

- **遥感解译复核排序**：检测器或 GIS 流程先生成疑似变化区域及面积、质量、时间、类别和证据摘要；Jev 判断复核优先级或是否缺证据，人工复核并记录结果。空间计算、坐标转换、合规和最终判定由现有流程负责。
- **巡检任务分流**：既有系统给出观测质量、覆盖缺口、天气和任务约束摘要；Jev 给出重拍候选或升级建议，确定性规则及授权方决定是否改动任务。此例不等于自主飞行控制。

两例是可证伪的试点设计，非文章报告的现成项目，也不代表从图像到字段的感知质量已经解决。先确认原始影像、坐标、派生摘要是否允许发往所选服务；需要本地部署时，单独验证候选模型的许可、部署条件、模态、接口与本域质量，兼容接口不代表决策或阈值等价。

## 验证与晋级

固定版本并以相同场景、种子、预算、观测和动作能力比较基线；包括无模型、原规则及可行的其他判断方案。区分「基线没有这个动作」与「同样动作能力下模型判断更好」。覆盖光照/遮挡、未知观测、状态过期、传感器错误、网络超时及突发变化；测任务成功、漏检/误报、安全覆盖或否决、截止期违约、延迟分位数、成本和人工接管。结果需给出样本数与限制。

先离线回放或影子模式，再在适用的仿真、测试和授权条件下逐步推进；能否接入真实系统由领域规范、实际验证与用户授权决定，不能由仿真演示推断。
