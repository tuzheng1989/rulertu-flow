# 设计、接入与评测

以下为基于案例与官方资料的工程建议，需在目标环境验证；具体版本语法以 [TypeSafe 文档](https://docs.typesafe.ai/) 和实际 SDK 为准。

## 设计一个决策点

1. **定义后果**：列出自动执行、升级、人工处理、无动作等分支及代价；确定性规则、授权、输入校验和副作用由代码负责。
2. **构造状态与候选**：只提供该判断所需的目标、当前观察、相关历史和领域含义；标识不可信外部文本，避免把其当系统指令。执行候选由宿主生成并过滤，包含无匹配或无法决定时的退路。
3. **设计题目**：Choice 选离散项，Noul 表示命题为真的概率，Score 使用有意义的有序量规，Box 用于图像定位；原子题目各自独立，同一次调用不能依赖另一题的答案。需要级联时先消费第一轮结果再构造第二轮。
4. **制定消费规则**：校验题目与候选 ID、类型、概率和缺项；分清 Noul 的命题真值概率与 Choice/Score 的 confidence 等字段。概率不等于正确性保证；对开放集提供拒绝/升级，规则需覆盖低信心、冲突与无效答案。
5. **执行并验证**：执行前检查权限和状态是否仍新鲜；有副作用的步骤考虑幂等和重复执行，完成以独立可观察结果为准。必要时限制步骤、循环和预算。

## 在现有系统接入

- 在原路由、搜索、压缩或执行器旁建立独立判断接口：状态投影、题目/候选版本、模型配置和策略显式注入，避免污染原始会话或执行上下文。
- 首先离线重放或影子运行，在不改变用户结果时记录两条路径的决策及最终结果；确认权限、敏感数据、服务端点和数据保留方式适合实际部署。
- 调用超时、限流、结构错误、服务不可用须表示为错误而非负判断；只读建议可回原有流程，高影响或不可逆操作可暂停或升级，具体由宿主风险策略决定。
- 日志只记录获准保存的最少信息，必要时脱敏；包含输入/题目/候选及策略版本的可审计标识、结果分布、选择、退路、耗时和结果。缓存键覆盖模型、题目、状态与策略身份，并定义失效；禁止仅按用户请求文本复用与上下文不一致的判断。

## 评估与优化

冻结代表性样本和基线，覆盖常见、边界、无匹配、对抗输入、长上下文、工具失败和不同风险级别；训练/调参数据与最终保留集分开。记录样本来源、标签与限制，避免用同一数据反复挑阈值后宣称泛化。

| 决策点 | 直接质量 | 端到端后果 |
| --- | --- | --- |
| 选模型/专家 | 路由混淆矩阵、低配率、弃权率 | 任务成功、重试、成本、p50/p95 延迟 |
| 动作循环 | 合法动作率、状态过期、重复动作 | 任务完成率、危险动作、人工接管 |
| 压缩 | 关键信息保留、误删率、配对完整性 | 后续任务成功、恢复成本、节省 token |
| 搜索/重排 | recall@k、MRR/NDCG、无匹配误接收 | 回答正确率、上下文长度和费用 |
| 完成验证 | 漏报/误报、证据缺失检出 | 未验证完成率、阻塞与人工负担 |

比较同一任务集的原方案与新方案，记录分母、样本和费用，必要时用配对置信区间；分别测负例、故障注入和重复运行的概率波动。按错误代价选阈值与弃权区间，评估各组校准及分布偏移；无法获得真实标签时明确只能做离线代理指标。先优化状态投影与候选召回，再对题型、批处理、缓存、窗口逐项消融，记录质量与成本的权衡。
