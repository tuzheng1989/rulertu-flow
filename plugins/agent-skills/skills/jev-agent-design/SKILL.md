# Jev Agent 设计

把 Jev 当作对应用状态回答类型化问题的判断组件，宿主负责候选构造、权限、执行和结果验证。先用 [设计哲学](references/design-philosophy.md) 找决策边界和权衡，再按需读 [社区案例](references/community-patterns.md) 与 [设计与验证](references/design-and-evaluation.md)。

## 按需求选择入口

| 需求 | 先看 |
| --- | --- |
| 从零架构、改造评审、权衡是否接入 Jev | 设计哲学的「设计判断」和「如何套用」 |
| 构建或改造执行循环、浏览器 Agent | 社区案例的「有限动作循环」「浏览器动作」 |
| 遥感 / 低空 / 机器人等有感知或实时控制的 Agent | [具身与实时决策](references/embodied-systems.md)，再结合社区案例中的仿真项目 |
| 选择模型 / 推理档位，或筛选历史上下文 | 社区案例的「模型路由」「上下文压缩」 |
| 事件唤醒、技能选择、权限门控、检索验证 | 社区案例相应章节；设计哲学的风险与退路对比 |
| 检索、记忆重排、完成验证或暴露 MCP 工具 | 社区案例的「检索与记忆」「完成验证」「MCP」 |
| 改写问题、标定阈值、比较效果、排查失败 | 设计与验证 |

## 工作方式

1. 查清现有系统的目标、执行器、状态源、权限与成本/延迟基线。先找可枚举且高频的语义判断，说明其输入、候选、结果消费者；需要自由生成或复杂推理的部分保留原执行路径。
2. 用设计哲学选架构权衡，读取对应案例，列出其实际机制与局限，再据目标系统设计状态投影、原子题目、业务规则、弃权/失败路径与验证方式；标明哪些是项目做法，哪些是适配建议。
3. 以代表性轨迹和错误样本比较原系统，分别评估路由/判定质量与端到端任务效果，包含延迟、成本、误判、故障和人工介入。没有证据的阈值、速度或节省率标为待验证。
4. 落地时保持代码对执行权限和外部副作用的控制；模型不可用或输出异常与有效低分分开处理，并按操作风险选择安全退路。按任务授权范围实现或给出可审查的改造方案。

## 版本与来源边界

- 案例是 2026-11-10 查阅的项目文档快照；局部源码核验与 README 声明的范围分别标注，不代表已运行或独立复现。各仓库随时可能变化。
- 目录 [awesome-jev-hub](https://github.com/supermanc417-alt/awesome-jev-hub) 及其社区精选清单用于发现案例；具体设计以案例原仓库为准。清单可能重复收录，不能把重复条目当独立证据。TypeSafe 当前列出 Choice、Score、Noul、Box；题目并行独立评估，不把同请求中另一个答案当作已知状态。见[官方介绍](https://docs.typesafe.ai/introduction)。
- 实装前查[官方文档](https://docs.typesafe.ai/)和所用 SDK 类型确认当前 API、模型、限额及数据处理；不可访问时说明依据的本地版本，不猜接口。`agent-retrieval` 是本插件内的特定检索库指南，涉及该库具体行为时另读其技能。
