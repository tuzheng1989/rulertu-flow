# Adaptation：适应

【原文】执行成功不足以证明介入值得。论文 §4.6、图 12 讨论含偏差的隐式反馈、任务中的反思与修正，以及长期校准、个性化与信任。可按任务内快环和跨任务慢环设计，但这两种时间尺度是工程归纳，不应把原文的多层反馈压成恰好两个模块。

## 三类反馈的分流【原文＋导读归纳】

| 反馈语义 | 检验对象与流向 | 不能直接推出 |
|---|---|---|
| 执行成功／失败 | 环境状态、规则与工具可靠性 → Awareness／世界模型及 Action | 失败不直接证明用户目标错误；成功不证明主动介入有价值 |
| 建议被接受／修改／拒绝 | 需求预测、时机和呈现 → Anticipation、Action；也可能涉及 Arbitration | 接受不证明预测正确；拒绝不证明长期偏好改变 |
| 协助是否符合用户目标 | 目标筛选与介入标准 → Agenda、Arbitration 参数 | 单次选择不授权改写顶层目标或扩大委托 |

跨类型误读会让系统学错；保留原始反馈与情境，再更新具体假设。

## 悬置与多假设

【原文】一次改变可由当天情境或长期倾向解释。即时证据可修正本次任务，长期意义需更多支持。

【导读】交接格言「证据缺失不等于缺失证据」在此指：未观察到响应，不能证明不需要、不喜欢或已同意。保持悬置，让之后的证据仍能改变判断。

【实现约定】归因记录可采用：

```yaml
observation: user_did_not_respond
context_ref: intervention-event-id
hypotheses:
  - explanation: user_busy
    status: suspended
  - explanation: bad_timing
    status: suspended
  - explanation: content_not_useful
    status: suspended
current_task_adjustment: defer_under_existing_policy
long_term_update: pending_evidence
next_discriminating_evidence: null
```

示例的空值需换成场景可得的区分性证据或明确不可得；不为采集反馈不断追问用户，额外询问也要经过注意力成本判断。候选解释可被支持或反驳，悬置不是永久拒绝得出结论。

## 学什么、何时学

- 快环修正当前预测、计划或执行错误，保留可恢复状态。
- 慢环根据跨任务证据更新偏好、提醒时机、介入形态和阈值；记录支持证据、有效范围、失效条件与纠正方式。
- 【原文＋导读】主动程度本身可被学习；反馈有时延与噪声，不能把短期点击、默认接受当成长期收益。
- 【导读＋共创】权限是人的委托。学到用户较信任系统，可提出调整建议；实际扩大授权仍由人决定。

**失败与验证**：做完就忘、一次拒绝便固化长期偏好、沉默被当许可、执行成败被当目标适配。用相同表面反馈配不同情境，检查系统是否保留竞争解释；跨任务加入反证与过期偏好，检查修正和遗忘。

**环间接口**：反馈修订全部五环，并区分模型错误、筛选错误、介入错误和交付错误；保留每次参数修订的证据，供长期评测回查。
