# Anticipation：预判

【原文】由当前情境估计预测潜在需求，并比较行动与不行动的后果。论文 §4.2、图 8 区分用户建模、世界建模、反事实比较和情境模拟。两类模型的权重随部署情境变化，不要求每个系统建设同样复杂的用户画像。

需要做出的决策：

- 用户模型：哪些目标、偏好、预算已经证实，哪些只是当前任务假设。
- 世界模型：哪些规则、资源、时间与其他参与者会影响未来；变化速度和不确定性如何表示。
- 后果链：把「观察 → 条件假设 → 后果 → 受影响目标」逐跳展开，只推到会改变取舍的深度。每个关键假设附补证方法。
- 比较行动、等待、先获取信息的未来；等待可能保留选项，也可能错过窗口。模拟给出预测，不能替代事实核实。

【导读】双路输出：潜在需求交给 Agenda 筛为待办；行动价值估计供 Arbitration 判断。事实和假设分离，使预判能反向派生 Awareness 的查询工作，而非把整条后果链当作已发生。

【导读】反射性检查：物理环境、规则市场、会适应的对手具有不同反应结构；对用户的推荐也可能改变用户偏好。询问「行动会不会改变预测对象」，避免用固定世界模型推演自适应对象。

【实现约定】输出可用 `evidence → assumptions → predicted_need → act/wait consequences → information_needed → expires_at`；预测过期需重估。

**诊断与验证**：看见变化但不懂后果，查模型缺失与因果链；把假设当事实，查证据边界；只估行动收益，补不行动对照。给一条同样的变化，分别改变期限或一个关键规则，检查预测和等待成本是否随之变化。

**环间接口**：事实不足回 Awareness；需求由 Agenda 决定是否承诺；价值估计与不确定性进入 Arbitration；反馈检验模型，不把用户接受直接当成预测正确。
