# 边界、利益与授权

以下以交接中的【导读】【共创】保留，区分论文论点、推演与本技能设计约束；不当成已验证公式。

## 长程委托与目标修订

【导读】委托范围会随信任和任务变化漂移。每次变更应能追溯由谁、何时、基于什么修改了哪些权限及约束；学习到用户信任不能自行转成授权。

【原文】论文 §4.3.3 将自生成目标置于用户权威之下，议程优先级并非执行许可；§6.14.1 的样本中没有领域达到自生成高层议程档。

【导读＋共创】本技能的设计约束：最高层目标修订权留人，Agent 获得其下层待办的生成和调整权。高层修改作为提案呈现，待人更新委托后生效。「任何部署都该如此」是规范主张，不冒充样本实证。

## 为谁主动

【导读】六环框架不能独自保证部署方与用户的激励一致。平台收入指标可能劫持「值得处理」的判据，长期反馈又强化偏差。商业部署需明确受益者、目标冲突、问责和可退出的控制点；不能以 GMV、点击或汇报次数直接代表用户收益。

【共创】授权函数：可开放的主动性上限 ≈ 激励耦合度 × 能力可靠性。这是定性授权顺序：先问为谁工作，再问做得好不好；无量纲、无标定、不可据此计算分数或概率。

【共创】放大器模型：主动性会放大被委托目标中的对齐误差。交接中的强表述是「对齐未解决前任何执行侧权限都不该给」；实际设计需明确把它作为高后果执行的保守原则，允许在委托内先发现、调查、准备并呈现可审核方案。对齐不足时降低介入形态，不必关闭发现能力；具体权限随情境与人类授权确定。

【共创】激励耦合是光谱。付费结构、声誉市场、监管问责与控制权共同作用；自控可降低部署方的利益错位，但理解误差与能力不足仍在。订阅制也可能产生「证明价值型过度介入」：为了显得有用持续打扰。

【共创】「发现工作」与「决定值得」应可区分和检查；这不要求每个候选都由人审批，人的目标与约束指导 Agenda 筛选，后续 Arbitration 决定具体介入。

## 边界审查的交付

写明冲突指标、对用户目标的影响、约束执行点、审查证据和未决项。遇到商业激励与用户利益冲突，不用一句“用户至上”填表过关；指出应改哪环的目标函数、哪些行为需保留用户控制、用什么真实收益验证。
