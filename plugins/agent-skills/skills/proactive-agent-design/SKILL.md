# 主动型 Agent 设计

把「什么值得处理」与「是否、何时、怎样介入」变成可检查的设计决策。用中文讨论机制、取舍和边界；已有上下文足够回答的问题直接沿用，追问会改变设计的缺口。

## 工作方式与来源

- 本技能是设计与评审工具。用九问组织推理，用模板保存决策；完成度看决策是否有依据、缺口是否可见。
- 设计对话每轮聚焦一个关键决策，必要时合并紧密相关的 2–3 问。先指出已有证据和具体缺口，再提问；用户答不上时记录「待定：影响／补证方式」，继续可独立推进的部分。用户要求评审报告、评测计划或一次性交付时，围绕其核心问题直接交付有缺口标记的草案，不把逐问对话作为前置条件。
- 区分「用户已确认／材料可证／设计假设／待定」。设计假设不代表事实或授权。技术实现建议需说明它解决哪一环的缺口。
- 知识标记：【原文】为论文观点的中文转述；【导读】为交接材料的分析、命名和工程推演；【共创】为用户讨论产出。保留后两类标记；本技能补充的字段与度量口径标为【实现约定】。核对范围与转述修正在 [sources.md](references/sources.md)，需要核引文或处理来源冲突时读取。

## 入口分流

| 场景 | 推进方式 | 交付范围 |
|---|---|---|
| A 全新设计 | 确认委托与对齐 → 四维定位 → 九问逐环决策 → 用一条变化事件走通闭环 | 默认产出四份设计产物 |
| B 评审诊断 | 取现有架构、运行记录或一例失败 → 快检 → 区分材料缺证与最早可确认的机制故障及下游放大 → 提出修补与验证 | 六环 gap 分析、按影响排序的缺口；更新受影响产物 |
| C 评测设计 | 先查输入是否替系统发现了问题 → 定义机会与合理不行动 → 三层指标 → 长程与反例 | 评测计划；仅在职责或权限不清时补相关表 |

B 场景的“未提供证据”记为待核实，不能等同于“机制不存在”。架构评审涉及主动性之外的部分时，明确本框架的覆盖范围。

## 设计九问

按以下依赖顺序推进；评审与评测可从问题所在环切入，再回查上游约束。

| 顺序 | 决策问题 | 足以推进的结果／按需读取 |
|---|---|---|
| 1 委托范围 | 系统代表谁、持续负责什么？哪些目标、预算、日期是硬约束，哪些取舍属于剩余决策空间？谁可更新委托？ | 明确受托职责与边界；按 [四维坐标](references/coordinates.md) 分别定位能力、对齐、发起和执行权限 |
| 2 对齐检查 | 「值得处理」用谁的目标判断？部署方收益与用户利益冲突时怎么裁决？ | 可验证的用户收益与冲突处理；商业部署、授权漂移、目标修订读取 [边界卡](references/boundaries.md) |
| 3 Awareness | 哪些信源、触发方式和频率？成本预算多少？无查询时，什么变化与哪条职责相关？ | 监控拓扑、信息有效期与补证入口；读 [察觉卡](references/awareness.md)，与 Agenda 联合设计相关性 |
| 4 Anticipation | 用户与世界模型分别有哪些变量？后果链推到哪里？事实与假设如何分开？现在行动与等待会怎样？ | 带证据的后果链、待核实假设、等待损失；读 [预判卡](references/anticipation.md) |
| 5 Agenda | 预测如何筛成承诺？每项是否有依据、进度、依赖？抢占保存什么，重启后怎样恢复与清理过期项？ | 持久议程与恢复策略，显式标人补位；读 [议程卡](references/agenda.md) |
| 6 Arbitration | 每个任务段可选哪些介入形态？证据、价值、期限与风险如何改变选择？打扰怎样计价？ | 每段「档位＋升级／降级触发器＋停止条件」；读 [仲裁卡](references/arbitration.md) |
| 7 Action | 草稿、编辑、撤销、接管实际支持到哪一步？如何呈现改动、成本、未生效状态？部分失败如何恢复？ | 能力支持的介入清单、状态与恢复路径；读 [行动卡](references/action.md)，回修仲裁可选空间 |
| 8 Adaptation | 执行、接受／修改、目标适配三类反馈流向哪里？怎样保留归因多假设与悬置？何时更新长期偏好和介入参数？ | 快慢反馈与归因条件；读 [适应卡](references/adaptation.md) |
| 9 评测 | 输入是否停在原始素材层？发现、漏报、多余介入怎样计数？合理不行动如何得分？人工审核成本是否纳入？ | 可运行的三层评测与长程情境；读 [评测卡](references/evaluation.md) |

【导读】六环按「构造待办 → 仲裁枢纽 → 执行与学习」理解，但数据流是闭环：预判会要求补采信息，议程反向界定监控，行动能力限制仲裁，反馈修订所有环节。六环是机制职责，不要求拆成六个服务或六个 Agent。

## 介入与学习的决策纪律

- 【原文＋导读】把权限分配到任务段落。无副作用的准备可在委托内推进；边界段交人决策；授权执行段按已有权限执行。批准过的范围直接沿用，范围外才补授权。
- 【导读】介入建议始终包含档位与触发器。缺期限、证据成熟度、可撤回性或权限等会翻转选择的变量时，先问相关变量；未答前只推进独立的分析、草稿或补证设计，具体档位记待定。
- 【导读】严重性影响值得投入多少，证据成熟度影响现在可做什么。期限逼近可以提高补证与提醒的优先级，不能制造证据或权限。
- 【原文＋导读】有限反馈维持候选解释和悬置状态，标明下一次如何区分；有足够证据才更新结论。沉默不能自动转成拒绝、长期偏好或执行许可。
- 【导读＋共创】顶层目标修订权留人；Agent 在现有委托下生成下层待办。主动程度的学习受当前授权上限约束，扩大委托需由人确认。
- 涉及教育、医疗、推荐，或以领域成熟度推断权限时，读取 [领域与可撤回性卡](references/domain-matrix.md)，按任务段检查塑造效应。

## 评审快检

1. 待办重启后还在，且知为何在、做到哪、在等什么吗？
2. 介入按任务段分配了吗，是否同时有升档、降档与停止条件？
3. 可撤回性包括对人、时间窗口和其他系统的影响吗？
4. 打扰、核对与纠错是否计入成本？
5. 执行失败、建议拒绝与目标错配是否被分流解释？
6. 评测输入是否替 Agent 说出了问题或行动？
7. 部署方与用户的目标冲突如何处理？
8. 高层目标与委托修订权归谁？

【实现约定】缺口按「证据 → 所属环 → 影响／相邻环 → 最小修补 → 验证 → 尚缺信息」记录。一次失败可以跨多环，分别标记最早缺证的位置和最早可确认的机制故障；前者说明要补什么材料，后者说明先修哪里，避免把材料缺失或一切失败归为模型不够聪明。

## 交付与完成判定

A 场景默认交付下列四份产物，作为整段设计协作的收尾成果，首轮无需全部输出；可合并到一份架构文档。B、C 按入口表裁剪，裁剪理由写明。模板用于保留决策依据，用户数据不足时保留缺口。

1. [四维定位表](references/templates/positioning.md)：现状、目标、证据与验证方式。
2. [六环设计表](references/templates/six-capacities.md)：职责、机制、人补位、失败恢复及环间接口。
3. [介入等级分配表](references/templates/intervention.md)：分段档位、条件、权限与可撤回性。
4. [评测计划](references/templates/evaluation-plan.md)：原始素材输入、三层指标、发现与多余介入、长程与人工成本。

收尾用一条具体变化走过六环，再走一次合理不行动或需求消失、一例中断／部分失败。每条链能追溯证据、决策、权限、状态与反馈；否则列为待验证，交付为草案。报告最关键的取舍、未决问题和下一步补证，不以填满表格宣布可上线。
