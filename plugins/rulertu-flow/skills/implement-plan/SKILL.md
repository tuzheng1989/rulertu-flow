# 分批计划实施

本技能是 T 级、派单、验证和波次收口政策的唯一出处。角色局部行为从 `../../references/roles/` 注入，不在此复制。

## 开工检查点

每批开工前读取详案并向用户复述批次、T 级、依据、流程和验收条数；核对前置批次证据。读取 [TDD](references/tdd.md)，把本批接缝、红绿循环和测试替身边界写入委派单。接缝不明时按需读取 [代码库设计](references/codebase-design.md)、[深化模块](references/deepening.md)、[设计两次](references/design-it-twice.md)、[测试](references/tests.md) 或 [替身](references/mocking.md)，补齐后再派单。

## 宿主与角色

- Codex：为每个角色创建通用的新上下文代理，把对应 `references/roles/<role>.md` 全文与任务包一起注入；同一任务的后续修订使用同一代理。创建参数固定如下，模型或档位不可用时阻断并报告，不继承主控或替换为其他模型：

  | 角色 | `model` | `reasoning_effort` | `fork_turns` |
  |---|---|---|---|
  | Executor | `gpt-5.6-terra` | `medium` | `"3"` |
  | Auditor | `gpt-5.6-sol` | `high` | `"none"` |
  | Advisor | `gpt-5.6-sol` | `xhigh` | `"none"` |

  `fork_turns="all"` 会强制继承主控模型，不用于这三个角色。Auditor/Advisor 的独立上下文所需事实全部由证据包注入。
- Claude Code：调用 `rulertu-flow:executor`、`rulertu-flow:auditor`、`rulertu-flow:advisor` 薄封装。模型路由由 wrapper frontmatter 固定：Executor 使用 `sonnet`，Auditor 与 Advisor 使用 `opus`。
- Advisor 由主控或 Executor 派发：技术歧义类 Executor 可直连，条件与输入要件见角色文档，意见原文落盘证据目录；边界与范围类必须上报主控。主控验收回报时复核落盘意见是否越界、输入是否为具体选择题。
- Codex 侧 Executor 无嵌套代理能力时，上报触发条件与完整试错清单，由主控按同规格派发；输入要件不降。

委派能力不可用时，T1 由主控实施，并加强定向测试与完整差异核验，同时在证据中声明降级；T2/T3 立即阻断并报告缺失能力。

## 风险流程

| 级 | 实施 | 验证 |
|---|---|---|
| T0 | 主控 | 锚点测试与差异核验 |
| T1 | Executor | 主控机械验证 |
| T2 | Executor | Auditor 证据包审计 |
| T3 | Executor | Auditor 审计与独立第二意见 |

实际改动超过定级假设时升级。任何必查项失败都退回修复并重新走该级完整流程。T2/T3 不静默降级。

## 委派单

委派单必须自包含：目标；验收标准原文；改动锚点与边界；实现接缝；以及每个“改动锚点 → 定向测试命令”映射。无法建立可信映射时在开工检查点补齐，不能只凭文件名推断。

Executor 在 TDD 循环运行单个锚点测试，收尾运行受影响模块测试、必要集成测试、类型和静态检查。仅有以下情况运行全量测试：

1. 当前任务明确是波次收口；
2. 修改测试运行器、构建系统、依赖锁文件或全局配置；
3. 修改跨模块公共契约或共享测试设施，无法建立可信定向范围。

例外触发依据必须进入回报。共享数据库、端口、快照或生成目录的定向测试也与同工作区写入隔离。

## 验证证据

Executor 对每条命令回报命令、退出码、通过/失败数量和关键错误，完整日志落盘。主控在派 Auditor 前抽查一至两条关键测试；通过后标注可采信，Auditor 默认采信并只对高风险或可疑项复跑。证据包包含验收清单、差异范围、Executor 回报、测试证据及建议抽查命令。

疑似 flaky 测试最多定向复跑一次；再次不一致时标记不稳定并阻断。失败能定位到具体批次时退回对应 Executor；归属不明时阻断波次并独立诊断。只有绿色基线或独立复现证据可证明既有失败。

## 波次收口

所有写入型 Executor 停止后，主控或专用验证代理只执行一次全量测试、构建和项目红线，再审查本波次累积差异。全量测试不得与任何写入型代理并行。P0/P1 返工并复验；P2 记档但不阻断。

审计报告、命令日志和结论写入计划指定证据目录；续会话从证据目录和计划状态恢复，不依赖会话记忆。
