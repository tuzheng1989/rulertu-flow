# 分批优化方案 · 撰写标准与分级验证

## 定位

产出一份分批实施计划（路线图 + 详案），其中**每个批次自带风险定级**。方案的质量目标不是“层层审计”，而是**验证强度与风险对齐**——低风险批次轻验证节省上下文，高风险批次重验证保护契约。

本技能只管撰写与定级；定稿后如何执行（派单流程、审计代理证据包、Codex 第二意见、波次收口）见同插件 **implement-plan**，不在本文件重复。

## 触发边界

- **触发**：需求毕业为 ≥2 个有依赖关系的实施批次。
- **不触发**：单票小改（走「读代码锚点 → TDD 红绿 → 红线回归」即可）。
- 项目特有的红线声明、范例文件名和领域规范留在项目 `AGENTS.md` 或 `CLAUDE.md`，本技能只管通用结构。

## 文档分层

- **路线图**：优先级矩阵（价值×成本）+ 波次依赖图 + 推荐执行顺序。
- **详案**：每个批次按下方"五要素"展开。

## 详案写作标准

详案是执行代理和审计代理消费的代理文档。开始撰写或修订前，读取 [为代理编写文档](references/writing-for-agents.md)；只有方案本身涉及新增或修改技能时，才继续读取 [技能机制](references/skill-mechanics.md)。完成判据和证据打包已经由本技能的验收标准内化，不重复展开。

- **正向表述**：给执行代理的指令写目标行为；禁令只保留工具陷阱类硬护栏，例如“勿持久化 `ANTHROPIC_MODEL`”；
- **单一出处**：契约和红线约束在方案中只保留一处权威陈述，其他位置引用而不复制；
- **统一术语**：全篇用同一个引导词指代同一概念，例如锚点、证据包、收口；一个概念只用一个词。

## 每批次五要素

1. **如何改**：精确到 `文件:行号` 锚点 + 改动要点。优先用代码图谱核实；不可用时，使用当前环境的文件读取与文本搜索能力核实源码，不得脑补。
2. **如何验证**：分层——L1 单元测试（锚点函数）/ L2 替身编排 / L3 端到端。附红线回归；项目红线在 `AGENTS.md` 或 `CLAUDE.md` 中声明。
3. **验收标准**：可断言清单（给/不给某输入 → 必现/必不现某输出），逐条 PASS/FAIL + 证据。
4. **代码评审节点**：该批次的重点审查项，包括边界条件、复用与简化、已知陷阱。独立质量评审默认发生在**波次末**，本节只列审查要点，不代表每批都要派独立评审。
5. **分级与验证流程**：T 级定级 + 定级依据（该级对应流程引用 implement-plan 的查表，不在 plan 内重述）。

## 风险分级（T0-T3）

定级由方案撰写者在详案中确定并**写明依据**；边界模糊时**就高不就低**。执行中若发现实际改动超出定级假设（如 T1 批改到了契约文件），立即升级重走该级流程。

| 级 | 判据 | 验证流程 |
|---|---|---|
| **T0** | 单文件小改、无契约邻近 | 锚点 → TDD 红绿 → 红线回归（无子代理） |
| **T1 低** | 加法式改动、界面调整、不邻近任何红线契约、无外部状态变更 | 执行代理实施 → **主控亲自机械验证**收口，无审计代理 |
| **T2 标准** | 多文件、邻近契约边界但不改契约本身、有既有测试覆盖 | 执行代理实施 → **审计代理（证据包模式）** |
| **T3 高危** | 改红线契约本体、外部状态或迁移、无既有测试覆盖的新路径 | 执行代理实施 → 审计代理（证据包）→ **Codex 第二意见** |

执行侧规则（分级查表、执行代理派单、主控机械验证、审计证据包、Codex 第二意见、波次组织与收口）的**唯一出处是 implement-plan**。本文件不重复，上表“验证流程”只作为定级含义索引。

## 定稿前自审（派单前的质量门）

方案初稿完成后、进入对抗式评审前，先派一个**新上下文**的只读代理做一轮硬伤自审。Codex 宿主创建通用新上下文并注入 `references/roles/auditor.md`；Claude Code 宿主调用 `rulertu-flow:auditor`。先在低成本阶段消除机械硬伤，避免放大后续评审轮次。

自审只查**机械可查的硬伤清单**，不做质量评判；论证优劣和评分留给 Codex：

1. **锚点真实性**：逐一核实全部 `文件:行号` 锚点，确认位置存在且内容与描述相符；
2. **依赖可行性**：批次依赖图无环、执行顺序可行、并行批次的文件集确不重叠；
3. **五要素完整**：每批五要素齐全，验收标准是可断言清单（给/不给某输入 → 必现/必不现某输出），不是描述性口号；
4. **定级依据**：T 级有定级依据；触碰红线契约/外部状态却未定 T3 的，标出；
5. **单一出处与术语**：契约约束只有一处权威陈述，全篇术语一致，同一概念只使用一个引导词。

流程**一轮定音，不做自审循环**：审计代理报告问题 → 主控或执行代理修复 → 只复查被修条目。修完后如需继续打磨，调用 `rulertu-flow:plan-iterate`，进入 Codex 对抗评审、修复和复审循环。含 T2/T3 批次的方案建议至少运行一轮；纯 T0/T1 轻量方案可以直接派单。

## 调研先行

动手前优先用代码图谱调研真实锚点；不可用时使用当前环境的文件读取与文本搜索能力。方案必须钉在代码现状上；调研完成前不写方案、不动手。
